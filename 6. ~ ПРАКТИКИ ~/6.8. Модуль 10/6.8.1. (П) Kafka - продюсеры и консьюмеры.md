# Цель

Добавить в <u>GoShop</u> **Kafka**, чтобы `OrderService` мог публиковать события о новых заказах, а отдельный сервис — **подписчик (subscriber)** — слушал их и реагировал.

---
## Что будет в конце

```
📦 ProductService  →   Redis Cache (TTL)
🧾 OrderService    →   Kafka (topic: "orders")
👂 Subscriber      →   читает события из Kafka
🐘 PostgreSQL      →   хранит данные
```

Kafka теперь отвечает за **асинхронную обработку событий**, а не за кэш — этим по-прежнему занимается Redis.

---
# Контекст проекта

Сейчас у нас уже есть:

|Компонент|Назначение|Где работает|
|---|---|---|
|🐘 **PostgreSQL**|хранит товары и заказы|локально|
|⚡ **Redis**|кэширует карточки товаров|локально|
|💬 **GoShop API**|основной сервис|локально|

Теперь добавим **Kafka** — систему для передачи событий между сервисами.
Она поможет обрабатывать заказы **асинхронно**, без прямой связи между частями системы.

---
## Почему Kafka запускаем через Docker Compose

Kafka сложнее, чем Redis или PostgreSQL — она состоит из двух компонентов:
- **Kafka Broker** — сама очередь сообщений
- **Zookeeper** — служба, которая управляет брокером

Поэтому её проще запустить через **Docker Compose** — одной командой, без ручной установки.

> Все остальные зависимости *(PostgreSQL, Redis)* у нас по-прежнему работают **локально**. Docker Compose мы используем **только для Kafka**.
> Подробно про Docker и Compose мы будем говорить в **последнем модуле курса** — здесь это просто удобный способ запустить Kafka.

## 1. Добавляем Kafka через Docker Compose

Создай в корне проекта файл *(на уровне с `go.mod`)*:

**`docker-compose.yml`**
```yaml
version: '3.8'

services:
  zookeeper:
    image: confluentinc/cp-zookeeper:7.3.2
    container_name: zookeeper
    ports:
      - "2181:2181"
    environment:
      ZOOKEEPER_CLIENT_PORT: 2181
      ZOOKEEPER_TICK_TIME: 2000

  kafka:
    image: confluentinc/cp-kafka:7.3.2
    container_name: kafka
    ports:
      - "9092:9092"
    environment:
      KAFKA_BROKER_ID: 1
      KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181
      KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://localhost:9092
      KAFKA_LISTENER_SECURITY_PROTOCOL_MAP: PLAINTEXT:PLAINTEXT
      KAFKA_OFFSETS_TOPIC_REPLICATION_FACTOR: 1
    depends_on:
      - zookeeper
```

### Запуск Kafka

1️⃣ В терминале (из корня проекта):
```bash
docker compose up -d
```

2️⃣ Проверяем, что всё работает:
```bash
docker ps
```

Результат:
```
CONTAINER ID   NAME        STATUS
abc123         kafka       Up
def456         zookeeper   Up
```

Kafka доступна по адресу:
```
localhost:9092
```
- Этот адрес мы будем использовать в коде GoShop.

## 2. Создаём publisher (отправитель сообщений)

Создай новый файл: `internal/events/publisher.go`

Добавь код:
```go
package events

import (
	"context"
	"fmt"
	"github.com/segmentio/kafka-go"
)

// Publisher — отправляет сообщения в Kafka
type Publisher struct {
	writer *kafka.Writer
}

// Создаём новый Publisher с брокером и топиком
func NewPublisher(broker, topic string) *Publisher {
	return &Publisher{
		writer: &kafka.Writer{
			Addr:     kafka.TCP(broker),
			Topic:    topic,
			Balancer: &kafka.LeastBytes{},
		},
	}
}

// PublishOrderCreated — публикует сообщение о новом заказе
func (p *Publisher) PublishOrderCreated(ctx context.Context, orderID int) error {
	msg := fmt.Sprintf("Создан новый заказ #%d", orderID)
	return p.writer.WriteMessages(ctx, kafka.Message{
		Value: []byte(msg),
	})
}
```

### Функции

|Метод|Описание|
|---|---|
|`NewPublisher`|подключается к брокеру Kafka и выбирает topic|
|`PublishOrderCreated`|отправляет сообщение о новом заказе|

---
### Что делает код

#### Где мы находимся

Мы создаём **Publisher** — объект, который умеет отправлять сообщения в Kafka.
Он используется, например, в `OrderService`, когда мы создаём новый заказ:
```go
publisher := events.NewPublisher("localhost:9092", "orders")
```

---
#### Конструктор Publisher

```go
func NewPublisher(broker, topic string) *Publisher {
	return &Publisher{
		writer: &kafka.Writer{
			Addr:     kafka.TCP(broker),
			Topic:    topic,
			Balancer: &kafka.LeastBytes{},
		},
	}
}
```
##### Что делает `kafka.Writer`

`kafka.Writer` — это **объект из библиотеки `segmentio/kafka-go`**, который умеет **отправлять сообщения** в Kafka *(producer)*.

Можно представить, что это *“соединение с очередью”*, через которое мы пишем новые сообщения.

##### Параметры конструктора

###### `Addr: kafka.TCP(broker)`
- Указывает **адрес брокера Kafka**, к которому подключаемся.
- `kafka.TCP("localhost:9092")` создаёт TCP-соединение по этому адресу.
- Если Kafka работает на другом сервере — укажи IP/порт, например:
```go
kafka.TCP("kafka:9092")
```

###### `Topic: topic`
- Это **название очереди (топика)**, в которую мы будем писать сообщения.
- В нашем случае — `"orders"`.
> Можно представить как «папку событий о заказах».

###### `Balancer: &kafka.LeastBytes{}`
- Kafka делит топики на **разделы (partitions)**, чтобы можно было масштабироваться.
- `LeastBytes` — это **балансировщик**, который выбирает партицию с наименьшей загрузкой.
> “Отправляй сообщение туда, где сейчас меньше всего данных”.

---
#### Отправка сообщения
```go
func (p *Publisher) PublishOrderCreated(ctx context.Context, orderID int) error {
	msg := fmt.Sprintf("Создан новый заказ #%d", orderID)
	return p.writer.WriteMessages(ctx, kafka.Message{
		Value: []byte(msg),
	})
}
```

---
#### Что делает `WriteMessages`

1. Создаёт TCP-соединение с брокером (`localhost:9092`);
2. Сериализует сообщение в байты;
3. Kafka принимает и сохраняет сообщение в журнал топика `"orders"`;
4. Подписчики (consumers) получают его в своём темпе.

## 3. Обновляем OrderService

Открой: `internal/services/order_service.go`:
```go
package services

import (
	"GoShop/internal/db"
	"GoShop/internal/events"
	"GoShop/internal/models"
	"context"
)

// OrderService — управляет заказами и отправляет события
type OrderService struct {
	repo      *db.OrderRepo
	publisher *events.Publisher
}

// Конструктор принимает publisher
func NewOrderService(repo *db.OrderRepo, publisher *events.Publisher) *OrderService {
	return &OrderService{repo: repo, publisher: publisher}
}

func (r *OrderRepo) Create(ctx context.Context, o *models.Order) (models.Order, error) {
 var ord models.Order

 query := `
 INSERT INTO orders (product_id, quantity, total)
 VALUES ($1, $2, $3)
 RETURNING id, product_id, quantity, total;
 `

 if err := r.db.GetContext(ctx, &ord, query,
  o.ProductID, o.Quantity, o.Total); err != nil {
  return models.Order{}, err
 }
 return ord, nil
}
```

## 4. Обновляем main.go

Открой `cmd/main.go` и измени код:
```go
package main

import (
	"GoShop/internal/cache"
	"GoShop/internal/db"
	"GoShop/internal/events"
	"GoShop/internal/handlers"
	"GoShop/internal/services"
	"log"
	"net/http"
)

func main() {
	dsn := "postgres://postgres:postgres@localhost:5432/goshop?sslmode=disable"

	// Подключаем PostgreSQL
	dbConn, err := db.NewPostgres(dsn)
	if err != nil {
		log.Fatal(err)
	}

	// Подключаем Redis для кэша товаров
	redisCache := cache.NewProductCache("localhost:6379")

	// Подключаем Kafka Publisher
	publisher := events.NewPublisher("localhost:9092", "orders")

	// Репозитории и сервисы
	productRepo := db.NewProductRepo(dbConn)
	orderRepo := db.NewOrderRepo(dbConn)

	productService := services.NewProductService(productRepo, redisCache)
	orderService := services.NewOrderService(orderRepo, publisher)

	productHandler := handlers.NewProductHandler(productService)
	orderHandler := handlers.NewOrderHandler(orderService)

	http.HandleFunc("/products/", productHandler.GetProduct)
	http.HandleFunc("/orders", orderHandler.CreateOrder)

	log.Println("🚀 Server started on :8080")
	http.ListenAndServe(":8080", nil)
}
```

## 5. Создаём подписчика Kafka

Создай новый файл: `cmd/subscriber.go`

```go
package main

import (
	"context"
	"fmt"
	"github.com/segmentio/kafka-go"
)

func main() {
	ctx := context.Background()

	reader := kafka.NewReader(kafka.ReaderConfig{
		Brokers: []string{"localhost:9092"},
		Topic:   "orders",
		GroupID: "notifications-group",
	})

	fmt.Println("👂 Подписчик слушает Kafka topic 'orders'...")

	for {
		msg, err := reader.ReadMessage(ctx)
		if err != nil {
			fmt.Println("Ошибка чтения:", err)
			continue
		}
		fmt.Println("📦 Новое событие:", string(msg.Value))
	}
}
```

### Разбор кода

#### `GroupID`

`GroupID: "notifications-group"` — объединяет всех подписчиков в **consumer group**.

Если их несколько, Kafka разделит между ними сообщения.
