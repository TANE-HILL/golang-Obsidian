## Что меняем из модуля 9

В модуле 9:
- Все заказы обрабатывались через PostgreSQL;
- При каждом запросе происходил прямой доступ к базе;
- Логика работы с заказами была синхронной.

Теперь:
- Мы подключаем Redis — при `GetByID` сначала проверяется кэш;
- Если заказа нет в кэше — берём из БД и кладём в Redis;
- При `Update` или `Add` — очищаем/обновляем кэш;
- Мы добавляем Kafka-продюсера — при создании заказа он отправляет событие в очередь;
- Добавляем Kafka-консьюмера — он слушает заказы и выводит сообщения в консоль.

---

## Что ты сделаешь в этом задании:

### 1. Redis: кэширование заказов

### 📁 `internal/cache/redis.go`

- Подключи Redis через `go-redis/v8`;
- Реализуй структуру `RedisCache` с методами:
```go
type RedisCache struct {
	client *redis.Client
	ttl    time.Duration
}

func (c *RedisCache) Get(id int) (order.Order, error)
func (c *RedisCache) Set(order order.Order) error
func (c *RedisCache) Delete(id int) error
```

- Логика:
    - При `GetByID` сначала проверяешь Redis;
    - Если ничего нет — идёшь в БД и сохраняешь в Redis;
    - При `Add` и `Update` очищаешь кэш.

---
### 2. Kafka: очередь заказов

### 📁 `internal/queue/kafka_producer.go`

- Используй библиотеку `segmentio/kafka-go`;
- Создай продюсера с функцией:
```go
func SendOrderCreated(order order.Order) error
```
- Она будет сериализовать заказ в JSON и отправлять в топик `orders`.

### 📁 `internal/queue/kafka_consumer.go`

- Запускай консьюмера в отдельной горутине;
- Он будет читать из топика `orders` и логировать содержимое:

## Проверка результата

```bash
go run ./cmd/api
```

Тест:
1. Отправь `POST /orders` — заказ сохраняется, сообщение отправляется в Kafka;
2. Сделай `GET /orders/1` — первый раз из БД, потом из Redis (проверь лог);
3. Обнови заказ — кэш сбрасывается, новый `GET` снова берёт из базы;
4. В логах видно сообщения от Kafka-консьюмера.

```jsx
[Kafka] Новый заказ: {"id":1,"customer":"Петя","address":"ул. Ленина","isDelivered":false}
```
