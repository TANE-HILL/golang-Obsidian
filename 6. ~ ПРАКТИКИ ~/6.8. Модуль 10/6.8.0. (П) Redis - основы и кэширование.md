# <center><u>Проект: GoShop — мини интернет-магазин</u></center>
## О чём проект

**GoShop** — это учебный мини-проект, имитирующий работу настоящего интернет-магазина.

В нём есть **товары** и **заказы**, а **API** позволяет пользователям:
- получать карточку товара;
- создавать заказ;
- получать список заказов (опционально, для отладки).

Проект построен на **Go + PostgreSQL**, и в этом модуле мы будем **расширять его**, добавляя инструменты, которые используют в реальных продакшн-системах:
- **Redis** для кэширования;
- **Kafka** для асинхронных задач и очередей событий.

## Что реализовано сейчас

На старте у нас — минимально необходимый **API** с подключённой **базой данных**.

|Метод|Путь|Что делает|
|---|---|---|
|`GET`|`/products/{id}`|Возвращает карточку товара|
|`POST`|`/orders`|Создаёт заказ|

**Данные хранятся в PostgreSQL**, доступ к БД осуществляется через `sqlx`.

```go
import (
	"GoShop/internal/models"
	"context"
	"database/sql"

	"github.com/jmoiron/sqlx"

type ProductRepo struct {
	db DBTX
}

type DBTX interface {
	GetContext(ctx context.Context, dest any, query string, args ...any) error
	ExecContext(ctx context.Context, query string, args ...any) (sql.Result, error)
}

func NewProductRepo(db *sqlx.DB) *ProductRepo {
	return &ProductRepo{db: db}
}

func (r *ProductRepo) GetByID(ctx context.Context, id int) (*models.Product, error) {
	var p models.Product
	err := r.db.GetContext(ctx, &p, "SELECT * FROM products WHERE id=$1", id)
	return &p, err
}
```

```go
package handlers

import (
	"encoding/json"
	"net/http"
	"strconv"
	"strings"

	"GoShop/internal/services"
)

type ProductHandler struct {
	service *services.ProductService
}

func NewProductHandler(s *services.ProductService) *ProductHandler {
	return &ProductHandler{service: s}
}

// Обрабатывает GET /products/{id}
func (h *ProductHandler) GetProduct(w http.ResponseWriter, r *http.Request) {
	// Пример: /products/1
	parts := strings.Split(r.URL.Path, "/")
	if len(parts) < 3 {
		http.Error(w, "missing product id", http.StatusBadRequest)
		return
	}

	id, err := strconv.Atoi(parts[2])
	if err != nil {
		http.Error(w, "invalid id", http.StatusBadRequest)
		return
	}

	product, err := h.service.GetProduct(r.Context(), id)
	if err != nil {
		http.Error(w, "product not found", http.StatusNotFound)
		return
	}

	w.Header().Set("Content-Type", "application/json")
	json.NewEncoder(w).Encode(product)
}
```

# Что будем добавлять в проект GoShop

## Зачем нам нужен Redis

Сейчас приложение **каждый раз обращается к PostgreSQL**, чтобы получить карточку товара. Если пользователь 100 раз открывает один и тот же товар, сервис 100 раз делает одинаковый SQL-запрос.

Это:
- нагружает базу данных;
- замедляет API;
- создаёт риск, что при росте нагрузки всё “задушится”.

Чтобы этого не было — мы добавим **Redis** как слой кэширования.

**Идея простая:**
```
[Запрос] → [Проверить кэш Redis] → если есть → отдать из памяти
                          ↓
                     если нет
                          ↓
                     взять из БД → сохранить в Redis
```
Такой подход ускоряет отдачу данных **в десятки раз**, потому что Redis хранит всё в **оперативной памяти**, а не на диске.

## Как это впишется в GoShop
Вот как изменится архитектура:
```
До:
API → ProductService → ProductRepo → PostgreSQL

После:
API → ProductService
          ↓
       Redis Cache  ←→ PostgreSQL
```

## Что добавим в коде

1. Пакет `internal/cache` — отвечает за подключение к Redis и работу с кэшем.
2. Изменим `ProductService`, чтобы он:
    - сначала проверял кэш;
    - если товара нет — брал из БД и сохранял в Redis.
3. В `main.go` добавим создание Redis-клиента и передадим его в сервис.

## Новый файл `internal/cache/redis_cache.go`:
```go
package cache

import (
    "context"
    "encoding/json"
    "strconv"
    "time"

    "github.com/redis/go-redis/v9"
    "GoShop/internal/models"
)

type ProductCache struct {
    rdb *redis.Client
}

// Подключение к Redis
func NewProductCache(addr string) *ProductCache {
    rdb := redis.NewClient(&redis.Options{
        Addr: addr, // например, localhost:6379
    })
    return &ProductCache{rdb: rdb}
}

// Получить товар из кэша
func (c *ProductCache) Get(ctx context.Context, id int) (*models.Product, error) {
    val, err := c.rdb.Get(ctx, key(id)).Result()
    if err == redis.Nil {
        return nil, nil // нет в кэше
    }
    if err != nil {
        return nil, err
    }

    var p models.Product
    if err := json.Unmarshal([]byte(val), &p); err != nil {
        return nil, err
    }
    return &p, nil
}

// Сохранить товар в кэш
func (c *ProductCache) Set(ctx context.Context, p *models.Product) error {
    data, _ := json.Marshal(p)
    return c.rdb.Set(ctx, key(p.ID), data, 5*time.Minute).Err()
}

// Формирование ключа
func key(id int) string {
    return "product:" + strconv.Itoa(id)
}
```
Этот пакет отвечает за **работу с Redis** — здесь мы:
- подключаемся к серверу Redis;
- сохраняем товары в кэш;
- достаём их обратно, если они уже есть;
- автоматически удаляем данные по TTL (через 5 минут).

### Подключение и зависимости
```go

```
Создаём пакет `cache`.
Все функции, связанные с Redis, будут храниться здесь — так код остаётся чистым и модульным.

## Структура для работы с Redis
```go
type ProductCache struct {
    rdb *redis.Client
}
```
Создаём структуру, которая **хранит подключение** к Redis.
Через `rdb` мы будем выполнять команды `GET`, `SET`, `EXPIRE` и другие.

---
## Подключение к Redis
```go
func NewProductCache(addr string) *ProductCache {
    rdb := redis.NewClient(&redis.Options{
        Addr: addr, // например, localhost:6379
    })
    return &ProductCache{rdb: rdb}
}
```

Эта функция создаёт новое подключение к Redis.
- `redis.NewClient` — инициализирует клиента;
- `Addr` — адрес, по которому запущен Redis (по умолчанию `localhost:6379`);
- возвращаем объект `ProductCache`, чтобы им можно было пользоваться дальше.

Пример:
```go
cache := cache.NewProductCache("localhost:6379")
```

Теперь `cache.rdb` готов для работы.

## Чтение данных из Redis
```go
func (c *ProductCache) Get(ctx context.Context, id int) (*models.Product, error) {
    val, err := c.rdb.Get(ctx, key(id)).Result()
```

Метод `Get` получает данные по ключу `product:<id>`.
- `ctx` — контекст запроса (чтобы можно было отменить по таймауту);
- `key(id)` — формируем имя ключа, например `"product:1"`;
- `rdb.Get` — отправляет команду `GET` в Redis.


```go
if err == redis.Nil {
    return nil, nil // ключ не найден
}
if err != nil {
    return nil, err // ошибка соединения или сети
}
```
- `redis.Nil` — это не ошибка, просто Redis говорит “ключа нет”;
- другие ошибки (например, Redis не запущен) — возвращаем наверх.

```go
var p models.Product
if err := json.Unmarshal([]byte(val), &p); err != nil {
    return nil, err
}
return &p, nil
```
Здесь мы превращаем сохранённый JSON обратно в структуру `Product`.

Например, Redis хранит:
```
{"id":1,"name":"Наушники","price":2500}
```
→ после `json.Unmarshal` мы снова получаем объект `Product`.

## Сохранение данных в Redis
```go
func (c *ProductCache) Set(ctx context.Context, p *models.Product) error {
    data, _ := json.Marshal(p)
    return c.rdb.Set(ctx, key(p.ID), data, 5*time.Minute).Err()
}
```
Метод `Set` сохраняет товар в Redis.
1. `json.Marshal(p)` — переводит структуру Go в JSON-строку;
2. `rdb.Set(...)` — отправляет команду в Redis:
```
SET product:1 {"id":1,"name":"Наушники","price":2500} EX 300
```
где `EX 300` — срок жизни ключа (TTL = 5 минут);
3. `.Err()` — возвращает ошибку, если Redis не ответил.

## Формирование ключей
```go
func key(id int) string {
    return "product:" + strconv.Itoa(id)
}
```
Формируем удобный и уникальный ключ для каждого товара.
Так в Redis данные будут храниться в виде:

| ID  | Ключ        | Пример значения                             |
| --- | ----------- | ------------------------------------------- |
| 1   | `product:1` | `{"id":1,"name":"Наушники","price":2500}`   |
| 2   | `product:2` | `{"id":2,"name":"Клавиатура","price":3500}` |

## Как работает на практике

|Действие|Что происходит|
|---|---|
|Первый запрос|Сервис ищет товар в Redis → не находит → идёт в PostgreSQL → сохраняет результат в Redis|
|Повторный запрос|Сервис сразу берёт данные из Redis (мгновенно)|
|Через 5 минут|Redis сам удаляет ключ (TTL истёк)|

## Изменим `ProductService`

Теперь добавим кэширование в бизнес-логику.

Открой файл `internal/services/product_service.go` и замени его содержимое:
```go
package services

import (
    "context"
    "fmt"
    "GoShop/internal/cache"
    "GoShop/internal/db"
    "GoShop/internal/models"
)

type ProductService struct {
    repo  *db.ProductRepo
    cache *cache.ProductCache
}

func NewProductService(repo *db.ProductRepo, cache *cache.ProductCache) *ProductService {
    return &ProductService{repo: repo, cache: cache}
}

func (s *ProductService) GetProduct(ctx context.Context, id int) (*models.Product, error) {
    // 1️⃣ Проверяем Redis
    if p, _ := s.cache.Get(ctx, id); p != nil {
        fmt.Println("Из Redis")
        return p, nil
    }

    // 2️⃣ Если нет в кэше — берём из БД
    fmt.Println("Из PostgreSQL")
    p, err := s.repo.GetByID(ctx, id)
    if err != nil {
        return nil, err
    }

    // 3️⃣ Сохраняем в Redis
    _ = s.cache.Set(ctx, p)
    return p, nil
}
```

### Что изменилось по сравнению с прежней версией

Раньше `ProductService` выглядел так:
```go
type ProductService struct {
    repo *db.ProductRepo
}

func NewProductService(repo *db.ProductRepo) *ProductService {
    return &ProductService{repo: repo}
}

func (s *ProductService) GetProduct(ctx context.Context, id int) (*models.Product, error) {
    return s.repo.GetByID(ctx, id)
}
```

Он **всегда ходил в базу данных**.

Каждый вызов `/products/{id}` → новый SQL-запрос к PostgreSQL.

Теперь мы добавили **второй источник данных — Redis**.

Благодаря этому GoShop теперь читает из памяти, если данные уже закэшированы.

### Новая структура сервиса
```go
type ProductService struct {
    repo  *db.ProductRepo
    cache *cache.ProductCache
}
```

Теперь сервис хранит **два источника данных**:

|Поле|Что хранит|Откуда данные|
|---|---|---|
|`repo`|подключение к базе данных|PostgreSQL|
|`cache`|подключение к Redis|оперативная память|

### Конструктор с двумя зависимостями
```go
func NewProductService(repo *db.ProductRepo, cache *cache.ProductCache) *ProductService {
    return &ProductService{repo: repo, cache: cache}
}
```
Теперь при создании сервиса мы передаём **и репозиторий, и кэш**.
Это позволяет сервису работать по принципу:
> “Сначала спроси Redis.
> Если там нет — иди в PostgreSQL, потом вернись и сохрани результат.”


### Метод `GetProduct` — пошаговая логика

### 1. Проверяем, есть ли товар в кэше Redis
```go
if p, _ := s.cache.Get(ctx, id); p != nil {
    fmt.Println("Из Redis")
    return p, nil
}
```
- `s.cache.Get(ctx, id)` — ищем товар в Redis по ключу `product:<id>`.
- Если он найден (`p != nil`), возвращаем его сразу.
- В консоли появится сообщение:
```
Из Redis
```
Это самый быстрый путь — Redis хранит данные в памяти, поэтому ответ приходит за миллисекунды.

### 2. Если товара нет в Redis — берём из PostgreSQL
```go
fmt.Println("Из PostgreSQL")
p, err := s.repo.GetByID(ctx, id)
if err != nil {
    return nil, err
}
```
- Если Redis пуст (например, первый запрос или TTL истёк), идём в БД.
- Вызывается SQL-запрос:
```sql
SELECT * FROM products WHERE id=$1;
```
- В консоли видим:
```
Из PostgreSQL
```

### 3. Сохраняем результат в Redis
```go
_ = s.cache.Set(ctx, p)
return p, nil
```
- После того как получили товар из БД — сохраняем его в Redis, чтобы ускорить будущие запросы.
- TTL (время жизни) = 5 минут.
- Теперь Redis хранит этот товар под ключом `product:<id>`.

## Пример работы на практике

1️⃣ Первый запрос:
```
GET /products/1
```
→ В консоли:
```
Из PostgreSQL
```
→ Redis получает новый ключ `product:1`.

2️⃣ Повторный запрос:
```
GET /products/1
```
→ В консоли:
```
Из Redis
```
→ Данные берутся мгновенно, без обращения к базе.

3️⃣ Через 5 минут TTL истекает
→ Redis сам удаляет ключ
→ При следующем запросе снова идём в БД.

# Новый `main.go`:
```go
package main

import (
    "GoShop/internal/cache"
    "GoShop/internal/db"
    "GoShop/internal/handlers"
    "GoShop/internal/services"
    "log"
    "net/http"
)

func main() {
    dsn := "postgres://postgres:postgres@localhost:5432/goshop?sslmode=disable"

    // Подключаем PostgreSQL
    dbConn, err := db.NewPostgres(dsn)
    if err != nil {
        log.Fatal(err)
    }

    // Подключаем Redis
    redisCache := cache.NewProductCache("localhost:6379")

    // Инициализация зависимостей
    productRepo := db.NewProductRepo(dbConn)
    orderRepo := db.NewOrderRepo(dbConn)
    productService := services.NewProductService(productRepo, redisCache)
    orderService := services.NewOrderService(orderRepo)
    productHandler := handlers.NewProductHandler(productService)
    orderHandler := handlers.NewOrderHandler(orderService)

    // Роуты
    http.HandleFunc("/products/", productHandler.GetProduct)
    http.HandleFunc("/orders", orderHandler.CreateOrder)

    log.Println("🚀 Server started on :8080")
    http.ListenAndServe(":8080", nil)
}

```

## Как проверить работу Redis

1. Запусти Redis локально
	(на macOS: `brew services start redis`,
	на Windows — `redis-server.exe` из папки Redis).
2. Запусти сервер GoShop:
```bash
go run ./cmd/main.go
```
3. В браузере или терминале:
```bash
curl <http://localhost:8080/products/1>
```

Первый запрос → выведет в консоль:
```
Из PostgreSQL
```

Второй запрос → выведет в консоль:
```
Из Redis
```
- Это значит, что данные закэшированы.
