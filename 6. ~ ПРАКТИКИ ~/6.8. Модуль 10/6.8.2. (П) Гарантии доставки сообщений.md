# Цель

Добавить в проект **несколько подписчиков Kafka** и разобраться, **как Kafka гарантирует доставку сообщений**:
- каждое сообщение не теряется;
- разные группы получают свои копии;
- в пределах одной группы сообщения делятся между подписчиками.

---
## Что будет в итоге

```
🧾 OrderService   → Kafka topic "orders"
🔔 NotificationService (группа: notifications)
📊 AnalyticsService (группа: analytics)
```

- Оба подписчика получают события о заказах;
- Каждый работает независимо — как отдельный микросервис;
- Kafka хранит offset *(позицию)*, чтобы при сбое ничего не потерять.

# 1. Добавляем второго подписчика

Создай новый файл:

**`cmd/subscriber_stats.go`**:
```go
package main

import (
	"context"
	"fmt"
	"github.com/segmentio/kafka-go"
)

func main() {
	ctx := context.Background()

	reader := kafka.NewReader(kafka.ReaderConfig{
		Brokers: []string{"localhost:9092"},
		Topic:   "orders",
		GroupID: "analytics-group", // новая группа
	})

	fmt.Println("📊 AnalyticsService слушает Kafka topic 'orders'...")

	for {
		msg, err := reader.ReadMessage(ctx)
		if err != nil {
			fmt.Println("Ошибка чтения:", err)
			continue
		}
		fmt.Printf("📈 Аналитика получила: %s\n", string(msg.Value))
	}
}
```
## Что изменилось по сравнению с `subscriber.go`
Теперь у нас два разных **consumer group** — каждая группа получает **все сообщения** из топика `orders`, независимо друг от друга.

---
## Гарантия доставки — где она обеспечивается

Kafka по умолчанию работает в режиме **at-least-once delivery**, то есть **сообщения не теряются**, даже если подписчик упадёт.

### Где это задаётся

В коде — это поведение **по умолчанию** для `kafka.Reader`. Ничего вручную включать не нужно. Ключевая идея — Kafka хранит **offset** *(позицию последнего прочитанного сообщения)* для каждой **consumer group**.

---
# 6. Проверка отказоустойчивости Kafka

Эта проверка показывает, **что Kafka не теряет сообщения**, даже если подписчик *(consumer)* был временно выключен.

Так работает гарантия доставки **“at least once”**.

## Что будем проверять

Мы убедимся, что:
- сообщения **сохраняются** в Kafka, даже если consumer не запущен;
- после перезапуска consumer **догоняет** все события, которые были отправлены, пока он был выключен.


## Шаги

### 1. Запусти сервис аналитики (подписчика)

```bash
go run cmd/subscriber_stats.go
```

Ты увидишь в консоли:
```
📊 AnalyticsService слушает topic 'orders'...
```

---
### 2. Останови подписчика (Ctrl + C)

Теперь consumer **не работает** и **ничего не получает**.

---
### 3. Пока подписчик выключен — создай несколько заказов

```bash
curl -X POST <http://localhost:8080/orders> \
  -H "Content-Type: application/json" \
  -d '{"product_id":1,"quantity":1,"total":2500}'
```

```bash
curl -X POST <http://localhost:8080/orders> \
  -H "Content-Type: application/json" \
  -d '{"product_id":2,"quantity":2,"total":6000}'
```

Эти события (`Создан заказ #1`, `Создан заказ #2`) **отправились в Kafka**, но **никто их не читал** — подписчик был выключен.

---
### 4. Теперь запусти подписчика снова

```bash
go run cmd/subscriber_stats.go
```

---
### 5. Что произойдёт

Kafka “вспомнит”, что подписчик с `GroupID="analytics-group"` **останавливался на offset 0**, и **отдаст ему все пропущенные сообщения** — начиная с того места, где он остановился.

Ты увидишь:
```
📈 Заказ получен аналитикой: Создан новый заказ #1
📈 Заказ получен аналитикой: Создан новый заказ #2
```

---
## Почему это работает

- Kafka хранит **offset** (позицию, до которой дочитал consumer) для каждой **consumer group**.
- Если consumer выключен — Kafka **ждёт**, пока он вернётся.
- После перезапуска consumer **читает с последнего offset’а**, получая все накопившиеся события.
