*"[[4.1. Работа с GitLab - репозиторий, merge requests, code review|Работа с GitLab - репозиторий, merge requests, code review]]"*

## Цель

Пройти полный путь командной работы с GitLab:
- создать новую ветку → внести изменения → отправить Merge Request → внести правки после ревью → завершить слияние.

---
## Исходные данные

Ты уже создал проект `git-practice`, загрузил его в GitLab и сделал первые коммиты.
Теперь продолжим именно с ним — не нужно ничего пересоздавать.

---
## Шаг 1. Создай новую ветку для фичи

В терминале GoLand введи:
```bash
git checkout -b feature/add-greeting-message
```
- 💬 Эта команда создаёт ветку для новой задачи и сразу переключает тебя в неё.

---
## Шаг 2. Добавь небольшое изменение

Например, дополни вывод в функции `Hello`, чтобы он показывал не только имя, но и время приветствия.

📄 **internal/greeting/greeting.go**
```go
package greeting

import (
	"fmt"
	"time"
)

func Hello(name string) {
	current := time.Now().Format("15:04")
	fmt.Printf("[%s] Привет, %s!\n", current, name)
}

```

Теперь при запуске программы ты увидишь:
```
[14:23] Привет, мир!
```

---
## 3. Сделай коммит с описанием

```bash
git add internal/greeting/greeting.go
git commit -m "feat: добавлено время в приветствие"
```

---
## Шаг 4. Отправь ветку в GitLab

```bash
git push origin feature/add-greeting-message
```
После этого в GitLab появится уведомление:
> “Создать Merge Request для новой ветки?”

---
## Шаг 5. Создай Merge Request

1. Перейди в свой проект на GitLab.
2. Зайди во вкладку **Merge Requests** → **New merge request**.
3. В поле:
    - **source branch** выбери `feature/add-greeting-message`,
    - **target branch** — `main`.
4. Добавь описание:
```
Добавлено время в приветствие
- обновлён greeting.Hello()
- теперь в выводе отображается текущее время
```
5. Назначь себя как автора (`Assignee: yourself`).
6. Нажми **Create merge request**.

---
## Шаг 6. Проведи “мини-ревью”

В роли ревьюера можешь сам себе оставить комментарий для тренировки.
Например, открой вкладку **Changes** и щёлкни по строке с кодом:
> «Может, стоит добавить тест для проверки формата времени?»

Теперь закрой комментарий, чтобы понять, как работает “обсуждение” в MR.

---
## Шаг 7. Исправь код и добавь новый коммит

После того как ты создал Merge Request, представь, что коллега оставил комментарий:
> “Будет здорово, если в приветствии появится восклицательный знак — чтобы выглядело живее!”
- Ты решил это исправить.

Открой `internal/greeting/greeting.go` и немного поменяй вывод:

📄 **internal/greeting/greeting.go**
```go
package greeting

import (
	"fmt"
	"time"
)

func Hello(name string) {
	current := time.Now().Format("15:04")
	fmt.Printf("[%s] Привет, %s!\n", current, name)
}
```

добавим восклицательный знак:
```go
fmt.Printf("[%s] Привет, %s!!!\n", current, name)
```
💬 Это небольшое изменение — но оно показывает, **как обновлять код по комментариям** ревьюера.

Теперь зафиксируй правку и отправь её в GitLab:
```bash
git add internal/greeting/greeting.go
git commit -m "fix: добавлен восклицательный знак в приветствие"
git push
```

---
После этого открой Merge Request — GitLab автоматически обновит его содержимое.

Ты увидишь, что в MR появился **новый коммит**, и твой ревьюер может снова просмотреть изменения.

---
## Шаг 8. Заверши Merge Request

Когда все замечания закрыты и ревьюер написал “Approved”:
1. Перейди в Merge Request.
2. Нажми кнопку **Merge** (в правом верхнем углу).
3. Дождись подтверждения, что ветка влита в `main`.
4. Удали ветку, чтобы не захламлять репозиторий:
```bash
git branch -d feature/add-greeting-message
```
💬 GitLab может также предложить удалить ветку автоматически — просто согласись.

---
## **Теперь ты прошёл весь цикл командной работы:**

|Этап|Что сделал|
|---|---|
|Создал ветку|работал над задачей отдельно|
|Отправил ветку в GitLab|поделился кодом с командой|
|Создал Merge Request|оформил запрос на ревью|
|Исправил комментарии|внёс правки по фидбеку|
|Слил ветку в main|завершил задачу|

---
## **Главная идея:**

Merge Request — это не “техническая формальность”, а **диалог между разработчиками**.

Ты показываешь свой код, получаешь советы, вносишь улучшения и только потом вливаешь изменения в общую ветку.

Это и есть живая командная работа.
