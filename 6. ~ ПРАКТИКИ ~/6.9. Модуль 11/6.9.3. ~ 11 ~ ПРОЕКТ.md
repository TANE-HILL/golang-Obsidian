
**В терминале *(в корне проекта*):**
```bash
make run      # запускает сервер
make build    # собирает бинарник
make test     # проверяет и тестирует код
make lint     # запускает линтер
make migrate  # применяет SQL-миграции
```

## Как использовать

```makefile
.PHONY: build run test lint migrate

build:
	go build -o bin/gotracker cmd/api/main.go

run:
	go run ./cmd/api

test:
	go vet ./...
	go test ./...

lint:
	golangci-lint run

migrate:
	psql -U $$DB_USER -d $$DB_NAME -f migrations/001_create_orders.sql
```

## Пример Makefile для GoTracker

- Команды внутри цели должны начинаться с **табуляции** *(важно: не пробелы)*.
- `build:` — название цели, запускается командой `make build`.
- `.PHONY:` — объявляет *«виртуальные»* цели, которые не связаны с файлами. Это best practice.

## Что значат эти блоки

Это обычный текстовый файл с расширением `Makefile`, в котором ты описываешь **цели** *(targets)* и команды, которые должны выполниться.

```makefile
.PHONY: build run test

build:
	go build -o bin/gotracker cmd/api/main.go

run:
	go run ./cmd/api

test:
	go test ./...
```

## Как работает Makefile

Makefile — это **файл автоматизации**, который позволяет запускать команды по коротким именам, вроде `make run`, `make build`, `make test`.

<u>Он нужен для</u>:
- **интеграции с CI/CD** *(pipeline может просто вызывать `make test` и `make build`)*;
- **стандартизации** *(каждый разработчик в команде использует одни и те же команды)*;
- **удобства запуска рутинных команд** *(сборка, тест, запуск сервера, миграции)*;
