# Цель

Пройти весь путь фичи от разработки до релиза:
1. создать ветки `dev`, `stage`, `prod`;
2. добавить простую фичу в ветке `feature`;
3. пройти все этапы слияния — `feature → dev → stage → prod`.

---
## Шаг 1. Подготовь проект

Возьми прошлый проект из практики — `git-practice`, или создай новый (в GoLand → **File → New Project → Go**).

📄 **internal/greeting/greeting.go**
```go
package greeting

import "fmt"

func Hello(name string) {
	fmt.Printf("Привет, %s!\n", name)
}

```

📄 **main.go**
```go
package main

import "git-practice/internal/greeting"

func main() {
	greeting.Hello("мир")
}

```

---
## Шаг 2. Инициализируй Git

Если репозиторий ещё не создан — включи Git:
```bash
git init
git add .
git commit -m "init: первый коммит проекта"
```

Создай репозиторий в GitLab и привяжи:
```bash
git remote add origin <https://gitlab.com/username/git-practice.git>
git push -u origin main
```

---
## Шаг 3. Создай основные ветки

Теперь создадим постоянные ветки `dev`, `stage`, `prod`.
```bash
git checkout -b dev
git push -u origin dev

git checkout -b stage
git push -u origin stage

git checkout -b prod
git push -u origin prod
```
- `dev` — рабочая ветка для разработки;
- `stage` — тестовая;
- `prod` — стабильная, релизная.

---
## Шаг 4. Создай фичу

Из ветки `dev` создадим новую ветку для задачи:
```bash
git checkout dev
git checkout -b feature/add-greeting dev
```

Добавь новую функцию:
📄 **internal/greeting/greeting.go**
```go
func Bye(name string) {
	fmt.Printf("Пока, %s!\n", name)
}
```

📄 **main.go**
```go
func main() {
	greeting.Hello("мир")
	greeting.Bye("мир")
}
```

Сохрани и сделай коммит:
```bash
git add .
git commit -m "feat: добавлено прощание"
git push -u origin feature/add-greeting
```

---
## Шаг 5. Создай Merge Request в GitLab

1. Перейди в свой проект на GitLab.
2. GitLab предложит создать **Merge Request** — нажми “Create MR”.
3. Укажи:
    - **Source branch:** `feature/add-greeting`
    - **Target branch:** `dev`
4. Добавь описание:
```
feat: добавлено прощание
- новая функция Bye()
- обновлён main.go
```
5. Нажми **Create merge request**.

После ревью *(можно самому себя “одобрить” )* — нажми **Merge**.

---
## Шаг 6. Проверим результат

После слияния открой локально ветку `dev` и подтяни изменения:
```bash
git checkout dev
git pull
```
- Теперь функция `Bye()` доступна в `dev`.

---
## Шаг 7. Готовим к релизу *(слияние в stage)*.

Когда в `dev` собралось несколько фич (или хотя бы одна) — переносим их на тестовую ветку:
```bash
git checkout stage
git merge dev
git push
```
- Теперь на `stage` тестировщики могут проверить код: запустить приложение, убедиться, что всё работает корректно.

---
## Шаг 8. Релиз в продакшен

Когда проверка прошла успешно, переносим код в `prod`:
```bash
git checkout prod
git merge stage
git push
```
- Теперь продакшен содержит новую версию приложения.

---
## Шаг 9. Отмечаем релиз

Добавь тег версии, чтобы зафиксировать момент релиза:
```bash
git tag -a v1.1 -m "Релиз: добавлено прощание"
git push origin v1.1
```
- Теперь в GitLab появится тег **v1.1**, и можно точно знать, какой код ушёл в продакшен.

---
# Что получилось

Ты прошёл полный цикл разработки:
```
(feature/add-greeting)
        ↓
     [merge]
        ↓
       dev
        ↓
     [merge]
        ↓
      stage
        ↓
     [merge]
        ↓
       prod
```

|---|---|---|
|1|Созданы ветки `dev`, `stage`, `prod`|`git branch -a`|
|2|Создана ветка `feature/add-greeting`|`git branch`|
|3|Добавлен код и коммит|`git log --oneline`|
|4|Создан и выполнен MR в `dev`|GitLab → Merge Requests|
|5|Слияние в `stage`|`git merge dev`|
|6|Слияние в `prod` и тег|`git tag`|
