# Что будет в практике

Завершим работу над проектом **GoFinance**, добавив в него **оптимизацию и безопасность SQL-запросов**.

На практике ты:
- проанализируешь производительность с `EXPLAIN ANALYZE`;
- создашь индекс для ускорения поиска транзакций;
- перепишешь потенциально опасный SQL-запрос на безопасный с `sqlx`;
- реализуешь фильтрацию и лимит через GET-запрос.

---
# Цель

Сделать работу сервиса **GoFinance** быстрее и безопаснее:
- запросы должны использовать **индексы**;
- параметры должны передаваться через **плейсхолдеры `$1`, `$2`**, а не через строковую подстановку (`fmt.Sprintf`).

# 1. Анализ производительности

Открой консоль PostgreSQL (через IDE или Docker)
и выполни команду:
```sql
EXPLAIN ANALYZE SELECT * FROM transactions WHERE category_id = 1;
```

Если видишь **Seq Scan**, это значит, что PostgreSQL **просматривает всю таблицу** построчно.

При большом количестве транзакций это будет медленно.

---
# 2. Добавь индекс

Создай новый файл миграции:

📄 `migrations/003_add_indexes.sql`:
```sql
-- +goose Up
CREATE INDEX IF NOT EXISTS idx_transactions_category ON transactions (category_id);

-- +goose Down
DROP INDEX IF EXISTS idx_transactions_category;
```
Применяй миграцию:
```bash
go run ./cmd/migrate up
```
- Теперь повтори `EXPLAIN ANALYZE` — вместо `Seq Scan` должен появиться **Index Scan**

---
# 3. Исправь небезопасный SQL-запрос

В файле:
📄 `internal/db/transaction_repo.go`:
```go
query := fmt.Sprintf("SELECT * FROM transactions WHERE category_id = %d", id)
r.db.SelectContext(ctx, &txs, query)
```
❌ Этот код небезопасен, потому что пользователь может подставить в `id` SQL-инъекцию вроде:
```
1 OR 1=1
```
и получить **все транзакции** из базы.

---
## Твоя задача

Перепиши метод **безопасно**:
- используй плейсхолдер `$1` вместо прямой подстановки;
- добавь `ORDER BY` и `LIMIT`;
- верни результаты в виде `[]Transaction`;
- комментариями опиши, что изменилось и почему это безопасно.

## Проверка работы

1. Запусти сервер:
```bash
go run ./cmd/api
```
2. Отправь GET-запрос:
```bash
curl "<http://localhost:8080/transactions?category_id=1&limit=5>"
```
✅ Ответ должен быть в JSON и содержать только нужные транзакции.

3. Проверь безопасность — попробуй ввести:
```
curl "<http://localhost:8080/transactions?category_id=1> OR 1=1"
```
Запрос **не должен** вернуть все данные, а должен ответить ошибкой `400` или пустым результатом.

## Решение (для сверки)

📄 `internal/db/transaction_repo.go`
```go
func (r *TransactionRepo) List(ctx context.Context, categoryID, limit int) ([]models.Transaction, error) {
    var txs []models.Transaction

    // ✅ Безопасный SQL-запрос с параметрами
    query := `
        SELECT id, category_id, amount, note, created_at
        FROM transactions
        WHERE ($1 = 0 OR category_id = $1)
        ORDER BY created_at DESC
        LIMIT $2;
    `

    // sqlx передаёт значения categoryID и limit как параметры,
    // а не вставляет их напрямую — защита от SQL-инъекций.
    err := r.db.SelectContext(ctx, &txs, query, categoryID, limit)
    return txs, err
}

```

📄 `internal/handlers/transactions.go`
```go
func (h *TransactionHandlers) ListTransactions(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodGet {
        http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
        return
    }

    categoryID, err := strconv.Atoi(r.URL.Query().Get("category_id"))
		if err != nil {
		 http.Error(w, "Invalid category_id", http.StatusBadRequest)
		 return
		}
		limit, err := strconv.Atoi(r.URL.Query().Get("limit"))
		if err != nil {
		 http.Error(w, "Invalid limit", http.StatusBadRequest)
		 return
		}
		if limit == 0 {
		 limit = 10
		}

    txs, err := h.repo.List(r.Context(), categoryID, limit)
    if err != nil {
        http.Error(w, "Database error: "+err.Error(), http.StatusInternalServerError)
        return
    }

    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(txs)
}

```
