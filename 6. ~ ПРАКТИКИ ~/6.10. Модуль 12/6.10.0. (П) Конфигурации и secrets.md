# Практика: добавляем конфигурации в проект **GoShop**

Открывай проект с GoShop, которые мы писали в 10 модуле.

В этом задании мы вынесем все настройки *(PostgreSQL, Redis, Kafka и окружение)* из кода в отдельный файл `.env`, чтобы приложение стало гибким и удобным для деплоя.

### 🔧 1. Создай `.env` в корне проекта

📄 `.env`
```
APP_ENV=dev

# PostgreSQL
DB_URL=postgres://postgres:postgres@localhost:5432/goshop?sslmode=disable

# Redis
REDIS_ADDR=localhost:6379

# Kafka
KAFKA_BROKER=localhost:9092
KAFKA_TOPIC=orders

```
> ⚙️ Файл .env содержит настройки для локальной разработки.
> В продакшене эти переменные будут задаваться в CI/CD.

---
### 📦 2. Создай пакет `config`

📄 `internal/config/config.go`
```go
package config

import (
    "log"
    "os"
    "github.com/joho/godotenv"
)

// Структура конфигурации приложения
type Config struct {
    AppEnv      string
    DBURL       string
    RedisAddr   string
    KafkaBroker string
    KafkaTopic  string
}

// Загрузка конфигурации из .env
func Load() *Config {
    _ = godotenv.Load() // Подгружаем .env в окружение

    cfg := &Config{
        AppEnv:      os.Getenv("APP_ENV"),
        DBURL:       os.Getenv("DB_URL"),
        RedisAddr:   os.Getenv("REDIS_ADDR"),
        KafkaBroker: os.Getenv("KAFKA_BROKER"),
        KafkaTopic:  os.Getenv("KAFKA_TOPIC"),
    }

    if cfg.DBURL == "" {
        log.Fatal("DB_URL не задан")
    }

    return cfg
}
```

---
### 🧠 3. Подключи конфиг в `main.go`

📄 `cmd/main.go`
```go
package main

import (
    "log"
    "net/http"

    "GoShop/internal/cache"
    "GoShop/internal/config"
    "GoShop/internal/db"
    "GoShop/internal/events"
    "GoShop/internal/handlers"
    "GoShop/internal/services"
)

func main() {
    // Загружаем конфигурацию
    cfg := config.Load()

    // Подключаем PostgreSQL
    dbConn, err := db.NewPostgres(cfg.DBURL)
    if err != nil {
        log.Fatal(err)
    }

    // Redis (кэш)
    redisCache := cache.NewProductCache(cfg.RedisAddr)

    // Kafka Publisher
    publisher := events.NewPublisher(cfg.KafkaBroker, cfg.KafkaTopic)

    // Репозитории и сервисы
    productRepo := db.NewProductRepo(dbConn)
    orderRepo := db.NewOrderRepo(dbConn)

    productService := services.NewProductService(productRepo, redisCache)
    orderService := services.NewOrderService(orderRepo, publisher)

    // HTTP handlers
    productHandler := handlers.NewProductHandler(productService)
    orderHandler := handlers.NewOrderHandler(orderService)

    http.HandleFunc("/products/", productHandler.GetProduct)
    http.HandleFunc("/orders", orderHandler.CreateOrder)

    log.Println("🚀 Server started on :8080, environment:", cfg.AppEnv)
    if err := http.ListenAndServe(":8080", nil); err != nil {
        log.Fatal(err)
    }
}

```

---
### 🧩 4. Добавь `.env` в `.gitignore`

Чтобы `.env` не попал в репозиторий, нужно создать или обновить файл `.gitignore`.

Это специальный файл, в котором ты указываешь, **какие файлы не должны попадать в Git** *(то есть не будут коммититься в репозиторий)*.
Мы добавляем туда `.env`, потому что он может содержать пароли и токены.

Создай его в корне проекта: Есть 2 способа создания.
#### 1. 🖥 Через IDE
1. Щёлкни правой кнопкой по корневой папке проекта (`GoShop/`).
2. Выбери **New File** → введи имя файла:
```
.gitignore
```
3. Вставь в него строки:
```
.env
```
Это скажет Git: “файл `.env` нужно игнорировать”.
#### 2. 💻 Через терминал
Если тебе удобнее работать через консоль, можно сделать то же самое командой:
```bash
touch .gitignore
```
> touch — это команда для создания нового пустого файла. 
> Она создаст `.gitignore` в текущей папке (если ты стоишь в корне проекта).    

После этого открой файл и добавь туда строку:    
```
.env
```

Если у тебя пока **нет git-репозитория**, выполни команды, чтобы его инициализировать:
```bash
git init
git add .
git commit -m "init GoShop project"
```
- Теперь `.env` будет игнорироваться при коммитах.

## Разбор кода

- `godotenv.Load()` — читает `.env` и добавляет все ключи в окружение.
- `os.Getenv()` — достаёт значения переменных окружения.
- Все параметры *(PostgreSQL, Redis, Kafka)* теперь хранятся вне кода.
- Код остался тем же, но стал универсальным — его можно запустить в любой среде.

---
## Вывод

- Конфигурации теперь изолированы от кода — это первый шаг к деплою.
- `.env` используется только локально, в CI/CD будут переменные окружения.
- `.gitignore` защищает проект от случайной утечки секретов.
- GoShop готов к следующему этапу — контейнеризации и запуску через **Docker Compose**.
