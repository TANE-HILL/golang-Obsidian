# Зачем нужен Redis

Представь, что у тебя интернет-магазин.
Ты открываешь карточку товара — а сервер каждый раз делает SQL-запрос:
```sql
SELECT * FROM products WHERE id = 42;
```

Если сайт посещает **10 000 пользователей**, этот запрос будет отправлен **10 000 раз** — даже если товар не менялся.

Зачем гонять одно и то же в базу, если можно **временно сохранить** результат в памяти?

---
# Что такое Redis

**Redis** — это **in-memory [[2.0.0. Базы данных и их виды|база данных]]**, которая хранит данные прямо в оперативной памяти.

<u>Это делает её:</u>
- **очень быстрой** *(чтение/запись — миллисекунды)*;
- но **не постоянной** *(если не включена [[2.2.0. Redis - основы и кэширование#**Персистентность (persistence)**|персистентность]])*.

Чаще всего Redis используют как **кэш** — временное хранилище для ускорения доступа к часто используемым данным.

## **<font color="#ff0000">Персистентность</font> *(persistence)***
Это способность данных **сохраняться после завершения работы программы или перезапуска сервера**.

---
## Пример: кэширование результата

Представим, что у нас есть функция:
```go
func GetProduct(id int) Product {
    fmt.Println("Запрос в БД...")
    return dbQuery(id)
}
```
- Если мы вызовем её 3 раза — БД сработает 3 раза.

**Добавим кэш через Redis:**
```go
func GetProductCached(id int) Product {
    // Проверяем, есть ли данные в кэше
    if val, ok := cache[id]; ok {
        fmt.Println("Из кэша")
        return val
    }

    // Иначе — идём в БД
    fmt.Println("Из БД")
    p := dbQuery(id)

    // Сохраняем результат
    cache[id] = p

    return p
}
```

Это и есть идея Redis — он делает то же самое, но в оперативной памяти и на миллионы записей.

# Как <font color="#ff0000">Redis</font> хранит данные

Redis — это **[[2.0.0. Базы данных и их виды#5. <font color=" f79646">Key-Value</font> базы данных|key-value]] хранилище**.
Все данные представляют собой пары:
```
ключ → значение
```

_Ключ (key)_ — это строка (уникальное имя, под которым сохраняются данные).
_Значение (value)_ — может быть разных типов: *строка*, *список*, *множество* и т.д.

Например:
```
"user:42" → {"name":"Alice","age":30}
"cart:123" → [42, 17, 8]
"session:token" → "abc123"
```

Redis не знает о наших структурах данных в [[1.1.0. Go Basics|Go]] — всё хранится в бинарном виде, который мы сами сериализуем *([[1.6.0.1. ~ JSON ~|JSON]], gob и т.п.)*.

---
## Поддерживаемые <font color="#f79646">типы данных</font> <font color="#ff0000">Redis</font>

| Тип                    | Описание                                                      | Пример использования                                       |
| ---------------------- | ------------------------------------------------------------- | ---------------------------------------------------------- |
| **<u>String</u>**      | Базовый тип. Может хранить строку, число или двоичные данные. | Кэш JSON товара, HTML-фрагмент, токен авторизации          |
| **<u>Bitmap</u>**      | Позволяет работать с отдельными битами внутри строки.         | Сохранение активности пользователей (1 — активен, 0 — нет) |
| **<u>Bitfield</u>**    | Оперирует битовыми полями внутри значения.                    | Уплотнённое хранение флагов состояний                      |
| **<u>Hash</u>**        | Набор пар “поле–значение”, похож на объект или struct.        | Данные пользователя (`user:1 → {name, email, age}`)        |
| **<u>List</u>**        | Последовательность элементов (вставка с головы/хвоста).       | Очередь сообщений, история событий                         |
| **<u>Set</u>**         | Множество уникальных значений.                                | Список уникальных тегов, подписчиков                       |
| **<u>Sorted Set</u>**  | Множество, где каждому элементу присвоен балл (score).        | Рейтинг игроков, популярные товары                         |
| **<u>Geospatial</u>**  | Хранение координат точек и поиск по радиусу.                  | Поиск ближайших магазинов, курьеров или машин такси        |
| **<u>HyperLogLog</u>** | Приблизительный подсчёт количества уникальных элементов.      | Подсчёт уникальных посетителей сайта                       |
| **<u>Stream</u>**      | Поток записей со временем добавления (лог событий).           | Очереди, микросервисы, события Kafka-подобного типа        |

## Пример ключ-значение в действии

```bash
SET product:42 '{"id":42,"name":"Keyboard"}'
GET product:42
```
→ Redis вернёт JSON-строку:
```
{"id":42,"name":"Keyboard"}
```

## Подключение <font color="#ff0000">Redis</font> в <font color="#ff0000">Go</font>

Мы будем использовать библиотеку `go-redis/v9`.

### <u>Пример:</u>
```go
import (
    "context"
    "fmt"
    "github.com/redis/go-redis/v9"
)

var ctx = context.Background()

func main() {
    rdb := redis.NewClient(&redis.Options{
        Addr: "localhost:6379",
    })

    err := rdb.Set(ctx, "foo", "bar", 0).Err()
    if err != nil {
        panic(err)
    }

    val, _ := rdb.Get(ctx, "foo").Result()
    fmt.Println("foo:", val)
}
```
- `Set` — записывает значение *(`key`, `value`, `ttl`)*;
- `Get` — читает по ключу;
- `ttl = 0` означает «бессрочно».

### <u>Построчный разбор</u>

```go
import (
    "context"
    "fmt"
    "github.com/redis/go-redis/v9"
)
```
- `context` — для управления временем выполнения операций;
- `fmt` — для вывода результата в консоль;
- `go-redis/v9` — клиент для подключения и работы с Redis.

```go
var ctx = context.Background()
```
Создаём **контекст** — специальный объект, который передаётся в сетевые операции. С его помощью можно:
- отменять операции *(например, при таймауте*);
- передавать метаданные;
- контролировать завершение при закрытии программы.

```go
rdb := redis.NewClient(&redis.Options{
    Addr: "localhost:6379",
})
```
Создаём клиент Redis.
- `Addr` — адрес, по которому запущен сервер Redis. Обычно это `localhost:6379`, если он работает локально.
- После этой строки у нас появляется объект `rdb`, через который выполняются все команды Redis.

```go
err := rdb.Set(ctx, "foo", "bar", 0).Err()
```
Отправляем команду `SET`:
- `"foo"` — ключ;
- `"bar"` — значение;
- `0` — время жизни *([[2.2.1. TTL, eviction|TTL]])*, означает “навсегда”.
- Метод `.Err()` возвращает ошибку, если что-то пошло не так *(например, сервер недоступен)*.

```go
if err != nil {
    panic(err)
}
```
Проверяем, всё ли успешно. Если Redis не запущен — программа аварийно завершится с ошибкой.

```go
val, _ := rdb.Get(ctx, "foo").Result()
```
Отправляем команду `GET`, чтобы прочитать значение по ключу `foo`.
Возвращает:
- `val` — само значение (строка);
- `err` — ошибку (например, `redis.Nil`, если ключа нет).

```go
fmt.Println("foo:", val)
```
Выводим результат в консоль.

### <u>Вывод:</u>
```
foo: bar
```

# **<font color="#ff0000">TTL</font>** — время жизни данных

**TTL *(Time To Live)*** позволяет задавать срок, после которого Redis **удаляет ключ**.
```go
rdb.Set(ctx, "session:123", "data", 5*time.Minute)
```
Через 5 минут значение исчезнет.
Это полезно, чтобы кэш не «застаивался».
