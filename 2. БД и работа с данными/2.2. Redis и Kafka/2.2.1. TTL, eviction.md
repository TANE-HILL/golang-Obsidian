# Зачем это нужно

Ты уже знаешь, что [[2.2.0. Redis - основы и кэширование|Redis]] хранит данные **в оперативной памяти**.
Это быстро, но память — **ограниченный ресурс**.

Если хранить всё подряд, Redis просто **переполнится**.
Чтобы этого не произошло, Redis использует три ключевых механизма:
1. **TTL (Time To Live)** — время жизни данных;
2. **Eviction Policy** — стратегия удаления, когда память заканчивается;
3. **Pub/Sub** — обмен сообщениями между сервисами без базы данных.
---
# <font color="#ff0000">TTL</font> — время жизни ключа

**TTL (Time To Live)** — это таймер, который указывает, как долго ключ будет храниться в Redis. Когда время истекает — ключ удаляется автоматически.
## Установка TTL при записи
```go
rdb.Set(ctx, "session:123", "data", 10*time.Second)
```
- Через 10 секунд ключ `session:123` исчезнет.
---
### Пример установки TTL при записи:
```go
package main

import (
	"context"
	"fmt"
	"github.com/redis/go-redis/v9"
	"time"
)

var ctx = context.Background()

func main() {
	rdb := redis.NewClient(&redis.Options{Addr: "localhost:6379"})

	// Сохраняем ключ с TTL = 10 секунд
	err := rdb.Set(ctx, "session:123", "user_data", 10*time.Second).Err()
	if err != nil {
		panic(err)
	}

	fmt.Println("✅ Ключ сохранён с TTL = 10 секунд")

	// Проверим, что значение доступно
	val, _ := rdb.Get(ctx, "session:123").Result()
	fmt.Println("📦 Значение:", val)

	// Ждём 11 секунд
	time.Sleep(11 * time.Second)

	// Проверяем снова
	val, err = rdb.Get(ctx, "session:123").Result()
	if err == redis.Nil {
		fmt.Println("⏰ Ключ истёк и удалён")
	} else if err != nil {
		panic(err)
	} else {
		fmt.Println("📦 Значение всё ещё существует:", val)
	}
}
```
### Что произойдёт при запуске
```
✅ Ключ сохранён с TTL = 10 секунд
📦 Значение: user_data
⏰ Ключ истёк и удалён
```
Так Redis сам очищает устаревшие данные — тебе не нужно удалять их вручную.

### Установка TTL отдельно

Иногда ключ уже существует, и TTL нужно задать потом:
```go
rdb.Set(ctx, "token:abc", "xyz", 0)         // без TTL
rdb.Expire(ctx, "token:abc", 5*time.Minute) // TTL = 5 минут
```
- Теперь `token:abc` автоматически исчезнет через 5 минут.

### Проверка TTL вручную (в консоли)

TTL можно проверить через встроенный клиент **redis-cli**.
Открой терминал и введи:
```bash
redis-cli
```
Затем:
```bash
TTL session:123
```
Пример вывода:
```
(integer) 231
```
— значит, через **231 секунду** ключ будет удалён.

Если Redis вернёт:
```
(integer) -1
```
— у ключа **нет TTL** (он бессрочный).

Если:
```
(integer) -2
```
— такого ключа уже **не существует**.

### Ещё пример — продление жизни ключа
Если пользователь активен, можно продлить срок жизни сессии:
```go
rdb.Expire(ctx, "session:123", 15*time.Minute)
```
Теперь Redis обновит таймер и оставит ключ активным ещё на 15 минут.

# <font color="#ff0000">Eviction</font> — автоматическое удаление при нехватке памяти

Когда ты работаешь с [[2.2.0. Redis - основы и кэширование|Redis]], нужно помнить важную вещь: Redis хранит все данные **в оперативной памяти (RAM)**. Это делает его очень быстрым, но если память закончится — Redis не сможет сохранить новые данные. Чтобы не *“упасть”*, Redis использует механизм **Eviction Policy** — он решает, **что удалить, когда память переполнена**.

## Как работает Eviction Policy

Redis всегда знает, сколько памяти он использует.
Если установлен лимит *(**`maxmemory`**)*, то при достижении этого лимита **Redis**:
1. **ищет кандидата на удаление** *(в зависимости от политики)*;
2. **удаляет старые или редко используемые ключи**;
3. **освобождает место для новых данных**.

## **Основные политики Eviction**

| Политика           | Что делает                                                    | Когда применять                                                           |
| ------------------ | ------------------------------------------------------------- | ------------------------------------------------------------------------- |
| **noeviction**     | Не удаляет ничего. При переполнении выдаёт ошибку при записи. | Для критичных данных (например, сессий).                                  |
| **allkeys-lru**    | Удаляет _наименее недавно использованные_ ключи.              | <font color="#de7802">Самая популярная</font>. Отлично подходит для кэша. |
| **allkeys-lfu**    | Удаляет ключи, которые _реже всего использовались_.           | Лучше при больших объёмах данных.                                         |
| **allkeys-random** | Удаляет случайные ключи.                                      | Для тестов или редких кейсов.                                             |
| **volatile-lru**   | Удаляет старые ключи только среди тех, у кого есть TTL.       | Если хочешь сохранить «вечные» ключи.                                     |
| **volatile-ttl**   | Удаляет те, у кого TTL скоро истечёт.                         | Удобно, если у всех ключей есть срок жизни.                               |

---
## Пример через консоль Redis

Ты можешь настроить всё прямо во время работы Redis:
```bash
redis-cli CONFIG SET maxmemory 10mb
redis-cli CONFIG SET maxmemory-policy allkeys-lru
```
Проверить настройки:
```bash
redis-cli CONFIG GET maxmemory
redis-cli CONFIG GET maxmemory-policy
```

## Как это работает на практике

Представь, что **Redis** хранит кэш товаров:
```
product:1 → "Наушники"
product:2 → "Клавиатура"
product:3 → "Мышь"
...
```

Теперь установим маленький лимит памяти (например, 1 МБ) и выберем стратегию LRU:
```bash
CONFIG SET maxmemory 1mb
CONFIG SET maxmemory-policy allkeys-lru
```
Добавим много ключей:
```bash
SET product:1 "item"
SET product:2 "item"
SET product:3 "item"
SET product:4 "item"
SET product:5 "item"
```
Когда Redis достигнет лимита, он **удалит старые, редко используемые** ключи.
Они будут исчезать автоматически, чтобы освободить место.

# Пример проверки в [[1.1.0. Go Basics|Go]]

Ты можешь наблюдать это поведение прямо из кода:
```go
import (
 "context"
 "fmt"

 "github.com/redis/go-redis/v9"
)

var ctx = context.Background()

func main() {
 rdb := redis.NewClient(&redis.Options{
  Addr: "localhost:6379",
 })

 // Устанавливаем лимит и политику через Go
 rdb.ConfigSet(ctx, "maxmemory", "2mb")
 rdb.ConfigSet(ctx, "maxmemory-policy", "allkeys-lru")

 // Добавляем данные
 for i := 1; i <= 20001; i++ {
  key := fmt.Sprintf("key:%d", i)
  if err := rdb.Set(ctx, key, fmt.Sprintf("value%d", i), 0).Err(); err != nil {
   fmt.Println(err)
  }
 }

 // Проверяем, что старые ключи уже исчезли
 keys, err := rdb.Keys(ctx, "key:*").Result()
 if err != nil {
  fmt.Println(err)
 }
 fmt.Println("🔑 Количество оставшихся ключей:", len(keys))
}
```

### Что произойдёт
1. Redis сохранит данные, пока не заполнит лимит 1 МБ.
2. Затем начнёт **автоматически удалять старые ключи**.
3. В выводе ты увидишь, что реально сохранено меньше 1000 ключей.
---
## Пример из реальной жизни

Представь маркетплейс, где Redis хранит карточки товаров. Пользователи открывают популярные товары — эти ключи “горячие”. Редкие товары никто не запрашивает.

С **`allkeys-lru`** **Redis** сам:
- удаляет редко запрашиваемые товары;
- сохраняет часто используемые;
- поддерживает стабильную скорость при любом объёме данных.
