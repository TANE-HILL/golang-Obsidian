# Зачем нужна ~ <font color="#ff0000">Observability</font> ~ *(наблюдаемость)*

Когда приложение растёт и разворачивается в контейнерах, важно не просто *“запустить его”*, а **понимать, что с ним происходит**:
- работает ли сервер?
- отвечает ли база данных?
- сколько запросов в секунду приходит?
- не упал ли Redis или Kafka?

Если не настроить наблюдаемость, при любой ошибке ты просто увидишь в логах *“500 Internal Server Error”* и не узнаешь, **почему** это случилось.

---
## Что включает Observability

**Observability *(наблюдаемость)*** — это способность системы *“рассказывать”*, что с ней происходит изнутри, с помощью метрик, логов и трассировок.

|Компонент|Что делает|Пример|
|---|---|---|
|**Metrics**|Числовые данные о работе приложения|время отклика, загрузка CPU|
|**Logs**|Текстовые записи событий|“Создан заказ #10”, “Ошибка соединения”|
|**Tracing**|Полный путь запроса через сервисы|“/orders → service → Kafka → consumer”|
|**Healthchecks**|Проверка “жив ли сервис”|`/healthz`, `/readyz`|

---
## Основные инструменты

| <u>Инструмент</u>                     | <u>Роль</u>                                 | <u>Где используется</u>        |
| ------------------------------------- | ------------------------------------------- | ------------------------------ |
| **Prometheus**                        | *собирает метрики из сервисов*              | **мониторинг**                 |
| **Grafana**                           | *визуализирует метрики (графики, дашборды)* | **дашборды**                   |
| **Healthcheck endpoints**             | *сообщает, работает ли сервис*              | **API / CI**                   |
| **Tracing *(Jaeger, OpenTelemetry)*** | *показывает путь запроса по микросервисам*  | **отладка производительности** |

---
# ~ <font color="#ff0000">Prometheus</font> ~ сбор метрик

Prometheus — это сервис, который **периодически опрашивает** твои приложения по HTTP и забирает у них метрики в текстовом формате.

> Формат метрик — обычный текст, вроде:
```
> http_requests_total 103
> go_goroutines 17
```
---
## Как это работает

1. Приложение публикует метрики по адресу, например `/metrics`.
2. Prometheus ходит туда раз в **`N`** секунд.
3. Сохраняет все данные во внутреннюю базу.
	По ним можно строить графики или уведомления.

---
## Пример экспорта метрик в [[1.1.0. Go Basics|Go]]

```go
import (
    "net/http"
    "github.com/prometheus/client_golang/prometheus"
    "github.com/prometheus/client_golang/prometheus/promhttp"
)

var totalRequests = prometheus.NewCounter(
    prometheus.CounterOpts{
        Name: "http_requests_total",
        Help: "Количество всех HTTP-запросов",
    },
)

func init() {
    prometheus.MustRegister(totalRequests)
}

func handler(w http.ResponseWriter, r *http.Request) {
    totalRequests.Inc()
    w.Write([]byte("OK"))
}

func main() {
    http.Handle("/metrics", promhttp.Handler())
    http.HandleFunc("/", handler)
    http.ListenAndServe(":8080", nil)
}
```
### Объяснение кода построчно
#### 1. <u>Импорты</u>
```go
import (
    "net/http"
    "github.com/prometheus/client_golang/prometheus"
    "github.com/prometheus/client_golang/prometheus/promhttp"
)
```
- **`net/http`** — стандартная библиотека Go для создания HTTP-сервера.
- **`prometheus`** — основной пакет клиента Prometheus, который позволяет **создавать и регистрировать метрики**.
- **`promhttp`** — утилита, которая умеет **отдавать метрики по HTTP** в формате, понятном Prometheus.

---
#### 2. <u>Объявляем метрику</u>
```go
var totalRequests = prometheus.NewCounter(
    prometheus.CounterOpts{
        Name: "http_requests_total",
        Help: "Количество всех HTTP-запросов",
    },
)
```
##### **Что тут происходит**:
- Мы создаём переменную `totalRequests` типа **Counter** — счётчик, который только растёт.
- `prometheus.NewCounter(...)` — создаёт новую метрику-счётчик.
##### **Аргументы**:
- **`Name`** — имя метрики, которое будет видно в Prometheus (например, `http_requests_total`).
- **`Help`** — описание, которое объясняет, что означает эта метрика.


В **Prometheus** есть несколько типов метрик:

|Тип|Что делает|
|---|---|
|Counter|считает события (только увеличивается)|
|Gauge|текущее значение (может увеличиваться и уменьшаться)|
|Histogram / Summary|измеряют распределения (например, время ответа)|

---
#### 3. <u>Регистрируем метрику</u>
```go
func init() {
    prometheus.MustRegister(totalRequests)
}
```
- `init()` — специальная функция Go, которая выполняется **автоматически при запуске программы**.
- `prometheus.MustRegister(...)` — сообщает библиотеке **Prometheus**, что эта метрика теперь должна быть **видна глобально** и попадать в `/metrics`. Если мы забудем её зарегистрировать — Prometheus просто не узнает о ней.

---
#### 4. <u>Обрабатываем HTTP-запросы</u>
```go
func handler(w http.ResponseWriter, r *http.Request) {
    totalRequests.Inc()
    w.Write([]byte("OK"))
}
```
##### Что делает этот обработчик:
- Каждый раз, когда приходит запрос на `/`, мы вызываем `totalRequests.Inc()`, то есть **увеличиваем счётчик `http_requests_total` на 1**.
- Затем отправляем ответ `"OK"`.

Если ты 5 раз откроешь `http://localhost:8080/`, в метриках появится:
```
http_requests_total 5
```

---
#### 5. <u>Настраиваем маршруты</u>
```go
func main() {
    http.Handle("/metrics", promhttp.Handler())
    http.HandleFunc("/", handler)
    http.ListenAndServe(":8080", nil)
}
```

**Разберём по шагам:**
1. **`http.Handle("/metrics", promhttp.Handler())`** — подключает *“обработчик метрик”* на путь `/metrics`.
    Этот обработчик автоматически формирует страницу со всеми зарегистрированными метриками в нужном формате.
    Когда Prometheus опрашивает `http://localhost:8080/metrics`, он получает примерно:
```
# HELP http_requests_total Количество всех HTTP-запросов
# TYPE http_requests_total counter
http_requests_total 5
```
2. **`http.HandleFunc("/", handler)`** — обычный маршрут для всех остальных запросов.
    Каждый раз, когда пользователь открывает `/`, счётчик увеличивается.
3. **`http.ListenAndServe(":8080", nil)`** — запускает сервер на порту `8080`.
    `nil` означает, что используется стандартный маршрутизатор `http.DefaultServeMux`.

---
### Как это работает в целом

1. Приложение запускает HTTP-сервер.
2. Пользователь или система делает запрос на `/`.
3. Счётчик `http_requests_total` увеличивается.
4. Prometheus каждые 5 секунд делает запрос на `/metrics` и забирает текущее значение.
5. Эти данные сохраняются, и потом можно строить графики или алерты.

# ~ <font color="#ff0000">Grafana</font> ~ визуализация

| <u>Возможность</u> | <u>Пример</u>                                |
| ------------------ | -------------------------------------------- |
| **Дашборды**       | *количество запросов, время отклика, ошибки* |
| **Алерты**         | *если запросов 0 → сломался сервер*          |
| **Live-view**      | *следишь за нагрузкой прямо во время теста*  |
Grafana — это *“панель приборов”* для метрик. Она подключается к **Prometheus** и позволяет **смотреть графики прямо в браузере**. После запуска контейнера Grafana доступна по адресу *(пример)*: `http://localhost:3000`

Это **веб-интерфейс**, где ты входишь *(логин: `admin`, пароль: `admin`)* и видишь все собранные **Prometheus**-метрики в виде **дашбордов**: графиков, таблиц и панелей в реальном времени.

> **Grafana не требует установки** — она запускается как отдельный сервис в **Docker**. Попробуем в практике

---
### Как выглядит связка

```
GoShop API ──→ /metrics ──→ Prometheus ──→ Grafana
```
- GoShop отдаёт данные о запросах.
- Prometheus их сохраняет.
- Grafana показывает графики.

# ~ <font color="#ff0000">Healthchecks</font> ~ *“жив ли сервис”*

**Healthcheck** — это простой эндпоинт *(например, `/healthz` или `/readyz`)*, который возвращает `200 OK`, если приложение работает.

> **Docker**, **CI/CD** и **Load Balancer** используют эти проверки, чтобы понять: контейнер *“жив”* или его нужно перезапустить.

---
### Пример простого healthcheck

```go
package main

import (
    "net/http"
)

func healthHandler(w http.ResponseWriter, r *http.Request) {
    w.WriteHeader(http.StatusOK)
    w.Write([]byte("OK"))
}

func main() {
    http.HandleFunc("/healthz", healthHandler)
    http.ListenAndServe(":8080", nil)
}
```

>Любой мониторинг или балансировщик может стучаться на `/healthz`, чтобы проверить, отвечает ли сервис.

# ~ <font color="#ff0000">Tracing</font> ~ трассировка запросов

**Tracing *(трассировка)*** позволяет *“проследить”* путь запроса через все сервисы.

Например:
`/orders → order_service → Kafka → notification_service`.
Используется для анализа производительности и отладки задержек.

---
### Как работает

- Приложение добавляет *“трейс-ID”* к каждому запросу.
- Этот ID передаётся по цепочке сервисов.
- Специальный инструмент *(например, **Jaeger**)* собирает эти цепочки и показывает визуально, где именно теряется время.

---
### Пример OpenTelemetry в Go

```go
import (
    "context"
    "go.opentelemetry.io/otel"
    "go.opentelemetry.io/otel/trace"
)

var tracer = otel.Tracer("my-service")

func ProcessOrder(ctx context.Context) {
    _, span := tracer.Start(ctx, "process_order")
    defer span.End()

    // ... выполняем работу
}
```
- В Grafana или Jaeger можно будет увидеть всю цепочку вызовов с таймингами.

---
## Как всё соединяется

| <u>Компонент</u> | <u>Задача</u>             | <u>Пример</u>                    |
| ---------------- | ------------------------- | -------------------------------- |
| **Prometheus**   | *собирает метрики*        | **`/metrics`**                   |
| **Grafana**      | *рисует графики*          | **“время ответа > 200мс”**       |
| **Healthcheck**  | *проверяет доступность*   | **`/healthz`**                   |
| **Tracing**      | *показывает путь запроса* | **`/orders → Kafka → consumer`** |

---
## Как это интегрируется в проект

- Контейнер с **GoShop API** публикует `/metrics` и `/healthz`.
- В `docker-compose.yml` добавляются сервисы `prometheus` и `grafana`.
- Prometheus собирает метрики с `goshop-api:8080/metrics`.
- Grafana подключается к Prometheus и визуализирует данные.
