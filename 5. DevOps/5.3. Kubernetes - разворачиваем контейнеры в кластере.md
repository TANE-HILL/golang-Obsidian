# Что такое Kubernetes - K8s

**Kubernetes *(или K8s)*** — это система, которая управляет контейнерами *(обычно Docker)* и **автоматически решает**, где и как их запустить, обновить, перезапустить и масштабировать.

> Если Docker — это коробка, в которую ты упаковываешь приложение, то Kubernetes — это склад, где десятки таких коробок работают вместе.

---
## Проблема без Kubernetes

| <u><center>Ситуация</center></u>                    | <u><center>Проблема</center></u>                 |
| --------------------------------------------------- | ------------------------------------------------ |
| **Несколько контейнеров (Postgres, Redis, GoShop)** | *приходится запускать и следить за каждым вручную* |
| **Сервис упал**                                     | *нужно перезапускать вручную*                      |
| **Рост нагрузки**                                   | *приходится запускать новые контейнеры самому*     |
| **Деплой на несколько серверов**                    | *сложно координировать версии и сети*              |
> То есть без Kubernetes весь деплой и мониторинг — ручная работа DevOps.

---
## Как решает Kubernetes

| <u><center>Возможность</center></u> | <u><center>Что делает</center></u>                          |
| ----------------------------------- | ----------------------------------------------------------- |
| **Оркестрация**                     | *сам управляет запуском контейнеров*                        |
| **Масштабирование**                 | *добавляет/удаляет копии приложения при изменении нагрузки* |
| **Восстановление**                  | *перезапускает контейнеры, если они упали*                  |
| **Сетевое взаимодействие**          | *даёт контейнерам доступ друг к другу через DNS*            |
| **Роллинг-обновления**              | *обновляет приложение без простоя*                          |
| **Мониторинг и health-checks**      | *следит за состоянием сервисов*                             |

---
## Основные понятия Kubernetes

| <u><center>Понятие</center></u> | <u><center>Что это</center></u>                             | <u><center>Аналогия</center></u> |
| ------------------------------- | ----------------------------------------------------------- | -------------------------------- |
| **Cluster *(кластер)***         | *группа серверов (нод), где запускаются контейнеры*         | *“ферма машин”*                  |
| **Node *(нода)***               | *отдельный сервер или виртуалка внутри кластера*            | *“одна машина”*                  |
| **Pod**                         | *минимальная единица запуска — 1 или несколько контейнеров* | *“маленький бокс”*               |
| **Deployment**                  | *описание, сколько Pod’ов и как их обновлять*               | *“план запуска”*                 |
| **Service**                     | *создаёт стабильный IP/доступ к Pod’ам*                     | *“точка входа”*                  |
| **Ingress**                     | *маршрутизация внешнего трафика (HTTP)*                     | *“входные ворота”*               |
| **ConfigMap / Secret**          | *хранение конфигураций и секретов*                          | *“настройки и ключи”*            |

## Как Kubernetes запускает приложение

1. Ты описываешь приложение в YAML-файле *(например, `deployment.yml`)*.
2. Kubernetes читает этот файл и создаёт **Pod’ы**.
3. Каждый Pod содержит контейнеры *(например, `goshop-api`, `redis`, `postgres`)*.
4. Kubernetes следит, чтобы нужное количество Pod’ов всегда работало.
5. Если Pod “упал” — он автоматически перезапускается.
6. Снаружи доступ обеспечивается через **Service** или **Ingress**.

## Пример: Deployment для GoShop

📄 `deployment-goshop.yml`
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: goshop-deployment
spec:
  replicas: 2
  selector:
    matchLabels:
      app: goshop
  template:
    metadata:
      labels:
        app: goshop
    spec:
      containers:
        - name: goshop
          image: goshop:latest
          ports:
            - containerPort: 8080
          env:
            - name: DB_URL
              value: "postgres://postgres:postgres@postgres:5432/goshop?sslmode=disable"
            - name: APP_ENV
              value: "prod"
          readinessProbe:
            httpGet:
              path: /healthz
              port: 8080
            initialDelaySeconds: 5
            periodSeconds: 10

```

---
### 🔍 Построчное объяснение

| <u><center>Поле</center></u> | <u><center>Что делает</center></u>                   |
| ---------------------------- | ---------------------------------------------------- |
| **`replicas: 2`**            | *Kubernetes запустит 2 экземпляра (Pod’а) GoShop*      |
| **`selector.matchLabels`**   | *выбирает, какие Pod’ы принадлежат этому Deployment*   |
| **`containers.image`**       | *указывает, какой Docker-образ использовать*           |
| **`env`**                    | *задаёт переменные окружения (как в `.env`)*           |
| **`readinessProbe`**         | *проверяет, что приложение готово обслуживать запросы* |
| **`ports.containerPort`**    | *открывает порт внутри контейнера*                     |

## Пример: Service для доступа к приложению

📄 `service-goshop.yml`
```yaml
apiVersion: v1
kind: Service
metadata:
  name: goshop-service
spec:
  type: NodePort
  selector:
    app: goshop
  ports:
    - protocol: TCP
      port: 8080
      targetPort: 8080
      nodePort: 30080

```
Теперь приложение доступно на порту **30080** на любой ноде кластера:
```
<http://localhost:30080>
```

## Как развернуть локально

1. Установи **Minikube** *(локальный Kubernetes)*:
    https://minikube.sigs.k8s.io/docs/start/
2. Запусти кластер:
```bash
minikube start
```
3. Применяй конфигурации:
```bash
kubectl apply -f deployment-goshop.yml
kubectl apply -f service-goshop.yml
```
4. Проверь состояние:
```bash
kubectl get pods
kubectl get services
```
5. Открой приложение:
```bash
minikube service goshop-service
```

## Healthchecks и масштабирование

- Если контейнер не отвечает на `/healthz`, Kubernetes его перезапускает.
- Хочешь больше копий сервиса? Просто измени `replicas`:
```bash
kubectl scale deployment goshop-deployment --replicas=5
```
    → Kubernetes сам поднимет ещё три Pod’а.
