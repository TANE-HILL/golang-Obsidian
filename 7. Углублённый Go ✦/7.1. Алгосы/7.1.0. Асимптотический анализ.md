# Асимптотический анализ

**Такой анализ оценивает, как растут затраты алгоритма при увеличении объёма входных данных**. Вместо секунд на конкретном компьютере обычно оценивают количество операций или объём дополнительной памяти.

## 1. Временная и пространственная сложность

- **Временная сложность** — как растёт количество операций с размером входа.
- **Пространственная сложность** — как растёт объём памяти, необходимой алгоритму. В задачах часто отдельно оценивают дополнительную память сверх входных данных.

Размер входа обычно обозначают `n`. Для нескольких входов используют отдельные переменные, например `n` и `m`.

## 2. Случаи выполнения и обозначения

- **Худший случай** — максимальные затраты для входа заданного размера.
- **Лучший случай** — минимальные затраты.
- **Средний случай** — ожидаемые затраты при заданных предположениях о распределении входных данных.

**Обозначения описывают рост функции сложности:**
- **`O(f(n))`** — асимптотическая верхняя граница роста.
- **`Ω(f(n))`** — асимптотическая нижняя граница.
- **`Θ(f(n))`** — точная по порядку роста граница: функция ограничена сверху и снизу величинами порядка `f(n)`.

В алгоритмах часто приводят Big O для худшего случая, но Big O само по себе не означает *«худший случай»*: оно **задаёт верхнюю границу для рассматриваемой функции**.

## 4. Как упрощать выражения

Асимптотический анализ описывает скорость роста, поэтому обычно опускают постоянные множители и слагаемые меньшего порядка.

- `3n + 5` → `O(n)`
- `2n` → `O(n)`
- `n² + n` → `O(n²)`
- `n + log n` → `O(n)`

Но нельзя опускать разные размеры входа, если каждый влияет на работу алгоритма:
`n + m` остаётся `O(n + m)`.

## 5. Как оценивать циклы

### Последовательные циклы — сложности складываются

```
for i := 0; i < n; i++ {
    // O(1)
}
for j := 0; j < m; j++ {
    // O(1)
}
```

Общая сложность — `O(n + m)`. Если оба цикла проходят по `n` элементам: `O(n + n) = O(2n) = O(n)`.

### Вложенные циклы — сложности обычно перемножаются

```
for i := 0; i < n; i++ {
    for j := 0; j < m; j++ {
        // O(1)
    }
}
```

Общая сложность — `O(n · m)`. Если оба цикла зависят от `n`, получается `O(n²)`. Оценивать нужно фактическое число итераций: не всякий вложенный цикл автоматически квадратичный.

## 6. Примеры алгоритмов

### Линейный поиск

Проверяет элементы по очереди:

- лучший случай — `O(1)`, если искомый элемент первый;
- худший случай — `O(n)`, если элемент последний или отсутствует.

### Бинарный поиск

Работает по отсортированной последовательности и на каждом шаге отбрасывает примерно половину оставшихся элементов. Число шагов растёт логарифмически: временная сложность — `O(log n)`.

### Рекурсия и дерево вызовов

Для оценки рекурсивного алгоритма полезно нарисовать дерево вызовов:

- глубина дерева показывает максимальную глубину рекурсии;
- число узлов помогает оценить общее количество вызовов и временную сложность;
- число одновременно активных вызовов влияет на память стека.

Если каждый вызов порождает два вызова и глубина пропорциональна `n`, число узлов может расти экспоненциально — порядка `O(2ⁿ)`. При этом память стека часто зависит от глубины рекурсии, например `O(n)`, а не от общего числа узлов. Точная оценка зависит от структуры рекурсии.

## 7. Амортизированная сложность

**Амортизированный анализ** оценивает стоимость операции на длинной последовательности операций, учитывая редкие дорогие операции.

Пример — добавление элемента в конец динамического массива:

- если есть свободная ёмкость, добавление обычно занимает `O(1)`;
- когда ёмкости не хватает, может потребоваться новый массив и копирование элементов — такая операция занимает `O(n)`;
- редкие расширения распределяются по множеству добавлений.

Поэтому добавление в конец динамического массива обычно имеет **амортизированную сложность `O(1)`**, хотя отдельная операция может стоить `O(n)`.

## Главное

1. Сложность описывает рост затрат при увеличении входа, а не точное время в секундах.
2. Уточняйте, что оценивается: время или память, лучший, средний или худший случай.
3. В последовательных блоках работы складывайте затраты; во вложенных циклах обычно перемножайте.
4. Убирайте постоянные множители и слагаемые меньшего порядка, но сохраняйте независимые размеры входа.
5. Для рекурсии анализируйте дерево вызовов и глубину стека; для динамических массивов учитывайте амортизированную стоимость.
