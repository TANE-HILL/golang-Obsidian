# Go map 1.24+ — новая реализация на основе Swiss Tables

## **1. Что изменилось в Go 1.24**

Начиная с [[1.1.0. Go Basics|Go]] 1.24, внутренняя реализация встроенной `map` была заменена на алгоритм Swiss Tables.

**Основная цель изменений:**
- Ускорить поиск, вставку и удаление.
- Эффективнее использовать память.
- Сократить количество сравнений реальных ключей.
- Улучшить производительность при работе с большими map.

>**Важно: синтаксис и поведение `map` для разработчика практически не изменились. Изменилась внутренняя реализация.**

## **2. Swiss Tables и группы *(Groups)***

**Вместо старой организации с [[7.2.3. Бакеты|бакетами]] и цепочками overflow используется структура на основе групп *(groups)*.**

**Одна группа содержит:**
- 8 слотов (slots) для хранения пар ключ-значение.
- Control word — 8 байтов метаданных, по одному байту на каждый слот.
![[Pasted image 20261102123504.png]]

**Control bytes содержат информацию о состоянии слотов:**
- <u>Empty</u> — слот пустой.
- <u>Deleted</u> — элемент удалён, но слот помечен специальным образом.
- <u>Occupied</u> — слот занят; в метаданных хранится 7-битный отпечаток хэша H2.

**Это позволяет быстро проверять состояние сразу нескольких слотов.**

## **3. Хэширование: H1 и H2**

**В Swiss Tables 64-битный хэш разделяется на две части:**
- **H1 *(57 бит)*** — используется для определения начальной группы и последовательности поиска *(probing)*.
- **H2 *(7 бит)*** — отпечаток хэша, который хранится в **control byte** и помогает быстро находить потенциальные совпадения.

>**Важно: H1 и H2 — не две равные половины хэша, а две части разного размера и назначения.**

## 4. Как происходит поиск

Допустим, мы ищем ключ `userID = 42`.

1. Вычисляется хэш ключа.
    
2. H1 определяет начальную группу.
    
3. H2 сравнивается с отпечатками в control bytes.
    
4. Проверяются потенциальные совпадения.
    
5. Для совпавших отпечатков сравниваются реальные ключи.
    
6. Если ключ не найден, поиск продолжается в следующих группах через probing.
    

Probing — последовательное исследование других групп по определённой последовательности, если нужный элемент не найден в начальной группе.

В Go используется quadratic probing (квадратичное пробирование).

Главное преимущество: вместо последовательного сравнения всех ключей группы можно быстро сравнить метаданные всех 8 слотов за одну операцию с использованием битовых операций.

Вероятность случайного совпадения H2 составляет 1/128 на слот. Поэтому после совпадения H2 всё равно необходимо сравнить настоящий ключ.

## 5. Удаление элементов и Tombstones

В новой реализации есть специальное состояние слота — Deleted (Tombstone).

Почему нельзя просто пометить удалённый слот как Empty?

Представим:

- Ключ A и ключ B попали в одну последовательность поиска.
    
- B оказался в следующей группе из-за коллизии.
    
- Мы удалили A.
    
- Если пометить слот A как Empty, поиск B может преждевременно остановиться на пустой группе.
    

Поэтому используется Tombstone — отметка об удалённом элементе.

- Empty — поиск может завершиться.
    
- Deleted — поиск должен продолжиться.
    
- Occupied — проверяем H2 и при совпадении сравниваем ключ.
    

При вставке Go может повторно использовать Tombstone.

## 6. Рост map и Extendible Hashing

Здесь находится одно из главных отличий новой реализации от старой.

В новой map используется Extendible Hashing (расширяемое хэширование).

Вместо одной большой структуры map организована как:

- Directory — каталог указателей на таблицы.
    
- Table — отдельная полноценная Swiss Table.
    
- Groups — группы внутри таблицы.
    
- Slots — слоты с ключами и значениями.

[leechanwoo-kor.github.io](https://leechanwoo-kor.github.io/database%20system/hashingfile02/?utm_source=chatgpt.com)

Как работает рост:

1. Map начинает с одной таблицы.
    
2. По мере заполнения таблица увеличивается в размерах.
    
3. При достижении максимального размера таблица разделяется на две.
    
4. Элементы распределяются между двумя новыми таблицами по битам хэша.
    
5. Directory обновляется, чтобы направлять ключи в нужную таблицу.
    

Важные особенности:

- Максимальная вместимость одной таблицы — 1024 слота.
    
- При разделении таблицы Directory при необходимости тоже увеличивается.
    
- Разные записи Directory могут указывать на одну и ту же таблицу.
    
- Каждая таблица растёт независимо от остальных.
    

Зачем это нужно?

При классическом Swiss Table увеличение количества групп требует перестройки всей таблицы, поскольку меняется последовательность probing.

Go решает эту проблему разделением map на независимые таблицы: при росте перестраивается только конкретная таблица, а не вся map целиком.

Это позволяет сохранить более постепенный характер роста большой map.

## 7. Старая и новая map: основные различия

|Старая (до Go 1.24)|Новая (Go 1.24+)|
|---|---|
|Buckets|Groups|
|До 8 элементов в бакете|8 слотов в группе|
|Overflow buckets|Probing|
|Tophash|Control bytes и H2|
|Выбор бакета по младшим битам хэша|Directory и Extendible Hashing|
|Incremental evacuation|Независимый рост таблиц и их разделение|

Главное преимущество новой реализации: эффективная проверка группы слотов, улучшенная локальность данных и более гибкий механизм роста.

## 8. Дополнительные особенности

- Small map optimization: если map содержит не более 8 элементов, она может храниться непосредственно в одной группе без Directory и полноценной таблицы.
    
- Хэширование: для каждой map используется собственный случайный seed.
    
- Удаление: используются Tombstones, чтобы не нарушать последовательность поиска.
    
- Порядок обхода: не гарантирован, порядок итерации рандомизирован.
    
- Конкурентность: новая реализация не сделала map потокобезопасной. Для конкурентной записи по-прежнему необходима синхронизация.
    
- Спецификация Go: Swiss Tables — деталь реализации runtime, а не гарантия языка.

## 9. Что запомнить для собеседования

1. Go 1.24 заменил старую реализацию map на Swiss Tables.
    
2. Группа содержит 8 слотов и 8 байтов control word.
    
3. H1 (57 бит) используется для поиска группы, H2 (7 бит) — для предварительной проверки ключей.
    
4. Control bytes позволяют проверять метаданные всех 8 слотов параллельно.
    
5. Вместо overflow buckets используется probing.
    
6. При удалении могут использоваться Tombstones.
    
7. Map состоит из Directory и независимых таблиц.
    
8. Для роста используется Extendible Hashing: переполненная таблица разделяется на две.
    
9. Новая реализация не обеспечивает потокобезопасность.
