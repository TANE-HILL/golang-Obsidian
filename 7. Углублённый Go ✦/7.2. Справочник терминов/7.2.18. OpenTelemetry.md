# OpenTelemetry (OTel)

**OpenTelemetry (OTel)** — набор стандартов, API, SDK и инструментов для сбора телеметрии из приложений. Он помогает наблюдать за работой системы и находить причины ошибок или задержек.

## Что собирает OpenTelemetry?

**Основные виды телеметрии — три сигнала:**
- **Traces (трейсы)** — показывают путь одного запроса через сервисы и отдельные операции внутри этого пути. Полезны для поиска места, где запрос задерживается или завершается ошибкой.
- **Metrics (метрики)** — числовые измерения во времени, например количество запросов, задержки и число ошибок.
- **Logs (логи)** — записи о событиях приложения. Их можно связывать с трейcами и другими данными, если настроена соответствующая интеграция.

## Как это работает?

1. Приложение инструментируется вручную или с помощью библиотек и интеграций.
2. Код создаёт телеметрию: spans для трассировки, метрики и, при соответствующей настройке, логи.
3. Контекст трассировки передаётся между компонентами, чтобы операции одного запроса связывались в общий trace.
4. Данные отправляются в систему хранения и анализа — напрямую или через **OpenTelemetry Collector**.

**Collector** — отдельный компонент, который может принимать телеметрию, обрабатывать её (например, фильтровать или добавлять атрибуты) и отправлять в разные системы наблюдаемости.

## OpenTelemetry — это не Grafana и не Prometheus

OpenTelemetry в первую очередь предоставляет общий способ создавать, собирать и передавать телеметрию. Он сам по себе не является полноценной системой хранения и визуализации всех данных.

- **Prometheus** обычно используют для сбора и хранения метрик.
- **Grafana** используют для визуализации данных и создания дашбордов.
- OpenTelemetry может передавать телеметрию в совместимые backend-системы; конкретная схема зависит от инфраструктуры.

## Зачем нужен OpenTelemetry?

- Понимать, где именно замедляется распределённый запрос.
- Связывать данные о работе нескольких сервисов.
- Использовать единый подход к инструментированию и передаче телеметрии.
- Упрощать смену backend-систем наблюдаемости без полной переработки инструментации приложения.

## Короткий ответ для собеседования

OpenTelemetry — это набор стандартов и инструментов для сбора телеметрии приложения. Он работает с тремя основными сигналами: traces, metrics и logs. Трейсы помогают проследить запрос через несколько сервисов, метрики показывают числовые показатели системы, а логи фиксируют события. Телеметрию можно отправлять напрямую в backend или через OpenTelemetry Collector, который умеет принимать, обрабатывать и пересылать данные.
