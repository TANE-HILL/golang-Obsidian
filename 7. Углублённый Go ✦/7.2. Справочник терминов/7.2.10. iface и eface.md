# iface и eface в [[1.1.0. Go Basics|Go]]

## Что такое **`iface`** и **`eface`**

**`iface` и `eface` — условные названия двух внутренних представлений интерфейсов в runtime Go:**
- **`iface`** — интерфейс с одним или несколькими методами, например `io.Reader`.
- **`eface`** — пустой интерфейс, то есть `interface{}` или его современный псевдоним `any`.

Это детали реализации runtime, а не конструкции, определённые спецификацией языка. Точные внутренние структуры могут меняться между версиями [[1.1.0. Go Basics|Go]].

---
## Из чего состоят

Упрощённо, оба представления хранят информацию о динамическом типе и значение, но организованы по-разному.

### `iface`: интерфейс с методами

**Концептуально содержит:**
- **`itab`** — сведения о конкретном типе и о том, как этот тип реализует нужный интерфейс, включая таблицу методов;
- **указатель на данные** — значение, хранящееся внутри интерфейса.

**`itab`** связывает конкретный тип с конкретным интерфейсом.

### `eface`: пустой интерфейс

**Концептуально содержит:**
- **информацию о динамическом типе**;
- **указатель на данные**.

У пустого интерфейса нет списка методов, который нужно сопоставлять, поэтому ему не требуется `itab` в том же смысле, что `iface`.

---
## Пример

```
var a any = 42
var r io.Reader = file
```
- `a` использует представление пустого интерфейса — концептуально `eface`.
- `r` использует представление интерфейса с методом `Read` — концептуально `iface`.

## Важный нюанс: интерфейс может быть не `nil`

```
var p *int = nil
var x any = p

fmt.Println(x == nil) // false
```

Интерфейс считается `nil`, когда у него нет ни динамического типа, ни динамического значения.

В `x` динамический тип есть — `*int`, хотя само значение указателя равно `nil`. Поэтому `x != nil`.

## Главное

- `iface` — условное внутреннее представление интерфейса с методами.
- `eface` — условное внутреннее представление пустого интерфейса (`any`).
- `iface` концептуально хранит `itab` и данные; `eface` — информацию о типе и данные.
- Это описание устройства runtime, а не гарантия спецификации Go.
- При проверке интерфейса на `nil` учитывайте возможность того, что внутри лежит типизированный `nil`.
