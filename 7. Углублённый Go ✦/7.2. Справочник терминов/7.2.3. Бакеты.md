# Бакеты *(buckets)* в Go **`map`**

## Определение

**Bucket** — группа слотов для хранения пар *«ключ — значение»* внутри [[7.2.1. Хэш функции и таблицы|хеш-таблицы]]. В реализации `map` бакет соответствует части таблицы, выбранной на основе хеша ключа.

Термин и детали ниже описывают внутреннюю реализацию `map`, а не отдельную конструкцию языка Go.

## Назначение

- Сгруппировать записи, для которых индекс бакета совпадает.
- Сократить объём данных, просматриваемых при поиске.
- Организовать хранение ключей и значений в памяти.
- Обрабатывать коллизии, когда разные ключи попадают в один бакет.

## Как выбирается бакет

1. Runtime вычисляет хеш ключа.
2. Часть битов хеша используется для выбора бакета.
3. В выбранном бакете выполняется предварительная проверка метаданных, а затем — сравнение ключей.

Хеш не гарантирует уникальность: разные ключи могут попасть в один бакет. Поэтому после выбора бакета runtime должен проверить сами ключи.

## Основной бакет в реализации Go 1.18

В материале о внутреннем устройстве `map` рассматривается реализация Go 1.18:

- один основной бакет содержит до **8 записей**;
- метаданные бакета содержат короткие значения `top hash`, используемые для предварительного отбора кандидатов;
- ключи и значения размещены раздельными областями: сначала ключи, затем значения;
- при переполнении основной бакет может ссылаться на дополнительный бакет.

Эти параметры относятся к рассмотренной версии реализации и не являются гарантией спецификации Go. Устройство `map` может меняться между версиями.

## `top hash`

`top hash` — часть хеша, сохраняемая в метаданных слота бакета.

Она помогает быстро отсеять записи, которые заведомо не соответствуют искомому ключу. Если `top hash` совпал, это ещё не означает, что ключи равны: требуется полноценное сравнение ключей.

## Переполнение бакета

Если в основном бакете заняты все доступные слоты и требуется добавить ещё одну запись, реализация может использовать дополнительный бакет, связанный с основным.

Дополнительные бакеты позволяют хранить записи сверх вместимости основного бакета, но длинные цепочки переполнения увеличивают объём работы при поиске. Поэтому runtime также отслеживает заполненность и может увеличивать таблицу.

## Связь с ростом `map`

При росте `map` runtime выделяет более крупный массив основных бакетов и постепенно переносит записи из старых бакетов в новые. Этот перенос называется **эвакуацией** (_evacuation_).

В материале по Go 1.18 указан коэффициент заполнения около **6,5 элемента на основной бакет в среднем** как один из критериев роста. Это деталь реализации указанной версии, а не постоянное правило языка.

Предварительное указание ожидаемой ёмкости может уменьшить вероятность роста и эвакуации во время заполнения:

```
m := make(map[string]int, 1000)
```

## Бакет и коллизия — не одно и то же

- **Бакет** — область хранения записей.
- **Коллизия хешей** — разные ключи получили одинаковый хеш.
- **Коллизия по индексу бакета** — разные хеши привели к одному бакету после преобразования хеша в индекс.

Несколько ключей могут находиться в одном бакете, даже если их полные хеши различаются.

## Кратко

- Бакет — группа слотов хеш-таблицы для записей с одним индексом бакета.
- В Go `map` хеш помогает выбрать бакет, но ключ всё равно проверяется.
- В реализации Go 1.18 основной бакет вмещает до 8 записей и использует `top hash` для предварительной проверки.
- При переполнении могут подключаться дополнительные бакеты.
- При росте `map` записи постепенно эвакуируются в новый массив бакетов.
- Число слотов, layout и алгоритм роста — детали реализации конкретной версии Go.
