# itab в [[1.1.0. Go Basics|Go]]

## Что такое itab

`itab` — внутренняя структура runtime [[1.1.0. Go Basics|Go]], которая связывает **конкретный [[1.1.2. Типы данных|тип]]** с **[[1.2.1. Интерфейсы в Go|интерфейсом]] с методами** и хранит информацию, необходимую для вызова методов через этот интерфейс.

Название обычно используют для описания таблицы, сопоставляющей методы конкретного типа методам интерфейса.

## Зачем нужен

Когда значение конкретного типа помещается в интерфейс, Go должен знать, как вызвать требуемые методы этого типа через интерфейс.

Концептуально `itab` содержит:

- информацию о типе интерфейса;
- информацию о конкретном типе;
- ссылки на реализации методов, соответствующих методам интерфейса.

Так runtime может выполнять вызовы методов через интерфейс, не зная конкретный тип в месте вызова.

## Связь с iface и eface

- **`iface`** — условное внутреннее представление интерфейса с методами. Оно концептуально хранит указатель на `itab` и данные значения.
- **`eface`** — условное представление пустого интерфейса (`any`). У него нет набора методов интерфейса, поэтому `itab` в таком виде не используется аналогичным образом.

## Пример

```
type Speaker interface {
    Speak()
}

type Dog struct{}

func (Dog) Speak() {
    fmt.Println("woof")
}

var s Speaker = Dog{}
s.Speak()
```

`Dog` реализует `Speaker`, потому что у него есть нужный метод `Speak`. При вызове `s.Speak()` runtime использует информацию, связывающую тип `Dog` с интерфейсом `Speaker`, чтобы вызвать реализацию метода.

## Главное

- `itab` связывает конкретный тип с интерфейсом, который он реализует.
- Он содержит сведения, необходимые для вызова методов через интерфейс.
- `itab` относится к внутреннему устройству runtime Go, а не к публичным конструкциям языка.
- Точная структура и детали работы `itab` могут меняться между версиями Go; спецификация языка их не гарантирует.
