# CI/CD

**CI/CD** — практики автоматизации проверки, сборки и доставки программного обеспечения. Они помогают быстрее и безопаснее выпускать изменения.

## CI — Continuous Integration

**Непрерывная интеграция** — разработчики регулярно объединяют изменения в общей кодовой базе, а автоматический pipeline проверяет их.

**Обычно CI запускает:**
- линтеры и статические проверки;
- тесты;
- сборку приложения.

**Цель — как можно раньше обнаружить ошибки и проблемы интеграции.**

## CD — Continuous Delivery / Continuous Deployment

**CD может означать два близких, но разных процесса:**
- **Continuous Delivery *(непрерывная доставка)*** — приложение автоматически собирается и проходит проверки, после чего готово к выпуску. Сам production-релиз может требовать ручного подтверждения.
- **Continuous Deployment *(непрерывное развёртывание)*** — каждое изменение, успешно прошедшее проверки, автоматически выкладывается в production.

## Как выглядит pipeline

**Типичный процесс:**
1. Разработчик отправляет изменения в [[4.0. Основы Git - коммиты, ветки, merge|Git]].
2. CI запускает линтеры, тесты и сборку.
3. При успехе создаётся артефакт, например бинарный файл или Docker-образ.
4. Артефакт развёртывается в тестовом окружении.
5. После необходимых проверок приложение доставляется в production — автоматически или после подтверждения.

Конкретные этапы зависят от проекта. CI/CD не гарантирует отсутствие ошибок: качество зависит от проверок, тестов и процесса релиза.

## Инструменты

Для автоматизации используют, например, GitHub Actions, GitLab CI/CD, Jenkins и другие CI/CD-системы. Конфигурация pipeline обычно хранится в репозитории рядом с кодом.

## Зачем нужен CI/CD?

- Раньше находить ошибки.
- Уменьшать объём ручных операций.
- Делать релизы повторяемыми и предсказуемыми.
- Быстрее доставлять изменения пользователям.

## Короткий ответ для собеседования

CI/CD — это автоматизация процесса проверки, сборки и выпуска приложения. CI при каждом изменении запускает проверки, например линтеры, тесты и сборку. CD автоматизирует доставку приложения: Continuous Delivery готовит его к выпуску, а Continuous Deployment автоматически развёртывает успешно проверенные изменения в production.
