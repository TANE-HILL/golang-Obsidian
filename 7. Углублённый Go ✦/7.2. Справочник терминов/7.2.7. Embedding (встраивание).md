# Embedding в Go

**Embedding *(встраивание)*** — способ включить [[1.1.2. Типы данных|тип]] в [[1.2.0. Структуры и методы|структуру]] без явного имени поля.
[[1.1.0. Go Basics|Go]] продвигает некоторые поля и методы встроенного типа, поэтому к ним можно обращаться через внешнюю структуру.

## 1. Встраивание структуры

```
type Address struct {
    City string
}

type Person struct {
    Address
}
```

Поле `Address` встроено в `Person`. К нему можно обратиться явно:
```
p := Person{
    Address: Address{City: "Chelyabinsk"},
}

fmt.Println(p.Address.City)
```

А благодаря продвижению поля можно написать короче:
```
fmt.Println(p.City)
```

## 2. Продвижение методов

Методы встроенного типа могут продвигаться к внешнему типу.
```
type Engine struct{}

func (Engine) Start() {
    fmt.Println("started")
}

type Car struct {
    Engine
}

func main() {
    car := Car{}
    car.Start()
    car.Engine.Start()
}
```

Оба вызова обращаются к методу встроенного `Engine`.

**Embedding — не наследование.** `Car` не становится типом `Engine`: он содержит поле `Engine`, а [[1.1.0. Go Basics|Go]] предоставляет удобный доступ к его методам и полям.

## 3. Затенение и неоднозначность имён

Если внешняя структура объявляет поле или метод с тем же именем, оно скрывает одноимённое продвигаемое поле или метод.

```
type Base struct {
    Name string
}

type Person struct {
    Base
    Name string
}
```
Теперь `p.Name` обращается к полю `Person`, а `p.Base.Name` — к полю встроенной структуры.

Если два встроенных поля продвигают одноимённые элементы на одинаковой глубине, обращение по короткому имени неоднозначно и не компилируется:
```
type A struct{ Name string }
type B struct{ Name string }

type Person struct {
    A
    B
}

// p.Name // ошибка: неоднозначно
// p.A.Name и p.B.Name — допустимы
```

## 4. Встраивание указателя

Можно встроить не только значение структуры, но и указатель на неё:
```
type Details struct {
    Name string
}

func (d *Details) SetName(name string) {
    d.Name = name
}

type Person struct {
    *Details
}
```

```
p := Person{Details: &Details{Name: "Alice"}}
p.SetName("Bob")
fmt.Println(p.Name) // Bob
```

Метод с указательным получателем доступен через встроенный указатель. Изменение происходит в исходном объекте `Details`.

**Осторожно:** если `Details == nil`, обращение к полю или вызов метода, который разыменовывает указатель, может привести к panic.

## 5. Embedding и интерфейсы

Встраивание может помочь типу удовлетворить интерфейсу, если встроенный тип предоставляет нужные методы.

```
type Starter interface {
    Start()
}

type Engine struct{}

func (Engine) Start() {}

type Car struct {
    Engine
}
```

`Car` реализует `Starter`, потому что метод `Start` продвигается из `Engine`. Явное объявление `Start` у `Car` не требуется.

## Главное

- Embedding позволяет встроить тип без явного имени поля.
- Поля и методы встроенного типа могут **продвигаться** к внешней структуре.
- Обращение через внешнюю структуру короче, но исходное поле остаётся доступным через имя встроенного типа.
- Собственные поля и методы могут затенять продвигаемые.
- Одинаковые имена на одинаковой глубине могут сделать обращение неоднозначным.
- Встраивание указателя позволяет работать с исходным объектом, но нужно учитывать `nil`.
- Embedding — это композиция и продвижение методов, а не классическое наследование.
