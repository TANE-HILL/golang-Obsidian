# Protocol Buffers *(Protobuf)*

**Protocol Buffers *(Protobuf)*** — формат сериализации данных и язык описания структуры сообщений, разработанный Google.

Он позволяет описывать данные в `.proto`-файлах, а затем преобразовывать их в компактный бинарный формат для передачи или хранения.

## Как это работает

1. Структуры данных и их поля описываются в файле `.proto`.
2. Компилятор `protoc` с нужными плагинами генерирует код для выбранного языка, например [[1.1.0. Go Basics|Go]].
3. Программа использует сгенерированные типы для сериализации данных в бинарный формат и обратной десериализации.

**Пример описания:**
```proto
message User {
  int64 id = 1;
  string name = 2;
}
```
- Числа `1` и `2` — **номера полей**, используемые в бинарном формате.
- После публикации схемы их нельзя бездумно менять или повторно использовать:
	это может нарушить совместимость.

## Зачем нужен Protobuf?

- Компактнее и обычно быстрее сериализуется, чем текстовые форматы вроде [[1.6.0.1. ~ JSON ~|JSON]].
- Даёт явную схему и [[1.1.2. Типы данных|типы данных]].
- Позволяет генерировать код для разных языков из одного описания.
- Помогает поддерживать общий контракт между сервисами.

## Связь с [[7.2.15. gRPC|gRPC]]

**Protobuf часто используют вместе с [[7.2.15. gRPC|gRPC]]:**
- в `.proto` описывают сообщения и RPC-методы;
- инструменты генерируют типы, клиентский код и серверные интерфейсы

**Однако Protobuf не привязан только к gRPC — его можно использовать и самостоятельно для сериализации данных.**

## Ограничения

- Бинарные данные не так удобно читать вручную, как [[1.6.0.1. ~ JSON ~|JSON]].
- Нужно следить за совместимостью схемы при изменении сообщений.
- Для работы с `.proto` обычно требуется генерация кода.

## Короткий ответ для собеседования

Protobuf — это формат сериализации и способ описания структур данных через `.proto`-файлы. Из схемы можно сгенерировать типизированный код для разных языков, а сами данные передавать в компактном бинарном виде.
Protobuf часто используется с gRPC для описания запросов, ответов и методов сервисов, но может применяться и отдельно.
