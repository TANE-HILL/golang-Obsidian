# Геттеры и сеттеры в [[1.1.0. Go Basics|Go]]

**Геттер** — [[1.2.0. Структуры и методы|метод]], который <u>возвращает</u> значение поля.  
**Сеттер** — [[1.2.0. Структуры и методы|метод]], который <u>изменяет</u> значение поля.

Их используют, когда нужно контролировать доступ к данным: например, проверять новое значение или скрывать внутреннее устройство типа.

## 1. Пример

```
type Person struct {
    age int
}

func (p *Person) Age() int {
    return p.age
}

func (p *Person) SetAge(age int) error {
    if age < 0 {
        return fmt.Errorf("age cannot be negative")
    }

    p.age = age
    return nil
}
```

Использование:
```
p := Person{}
if err := p.SetAge(25); err != nil {
    // обработка ошибки
}

fmt.Println(p.Age())
```

Поле `age` не экспортируется, поэтому другой пакет не может обратиться к нему напрямую. Методы `Age` и `SetAge` предоставляют контролируемый доступ.

## 2. Зачем они нужны

- **Проверка данных:** не допускать некорректных значений.
- **Контроль состояния:** изменять поле только через определённые правила.
- **Инкапсуляция:** скрывать детали реализации и предоставлять понятный API.
- **Возможность менять реализацию:** внешний код использует методы, а не зависит от внутреннего хранения данных.

Если поле не требует проверок или дополнительной логики, в Go часто достаточно экспортируемого поля. Геттеры и сеттеры не нужно создавать автоматически для каждого поля.

## 3. Соглашения об именовании в Go

В Go геттер обычно называют по имени свойства, без префикса `Get`:
```
func (p *Person) Age() int
```

Сеттер обычно получает префикс `Set`:
```
func (p *Person) SetAge(age int) error
```

Это соглашение, а не обязательное правило языка.

## 4. Получатель-значение или указатель

Сеттер обычно использует указательный получатель (`*Person`), чтобы изменить исходную структуру:

```
func (p *Person) SetAge(age int) {
    p.age = age
}
```

Если использовать получатель-значение (`Person`), метод изменит копию:

```
func (p Person) SetAge(age int) {
    p.age = age // меняется копия, исходный объект не изменится
}
```

Геттер может использовать получатель-значение или указатель — выбор зависит от типа и соглашений проекта.

## 5. Геттеры и сеттеры при embedding

Методы встроенного типа могут продвигаться к внешней структуре.

```
type Details struct {
    name string
}

func (d *Details) Name() string {
    return d.name
}

func (d *Details) SetName(name string) {
    d.name = name
}

type Person struct {
    *Details
}
```

Пример использования:

```
p := Person{Details: &Details{name: "Alice"}}
p.SetName("Bob")
fmt.Println(p.Name()) // Bob
```

`Name` и `SetName` доступны через `Person`, потому что методы встроенного `*Details` продвигаются. Они работают с исходным объектом `Details`.

**Важно:** если встроенный указатель `Details` равен `nil`, обращение к полю или метод, который разыменовывает его, может привести к panic. При необходимости проверяй указатель перед использованием.

## Главное

- Геттер читает значение, сеттер изменяет его.
- Они полезны, когда нужен контроль над чтением или изменением состояния.
- В Go геттер обычно называют `Age()`, а сеттер — `SetAge(...)`.
- Для изменения исходной структуры сеттер обычно использует получатель-указатель.
- Методы встроенного типа могут продвигаться через embedding.
- Не нужно создавать геттеры и сеттеры для всех полей без необходимости.
