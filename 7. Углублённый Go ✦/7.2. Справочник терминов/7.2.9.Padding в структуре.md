# Padding в [[1.2.0. Структуры и методы|структуре]] [[1.1.0. Go Basics|Go]]

## Что такое padding

**Padding** — это неиспользуемые байты, которые компилятор размещает между полями структуры или в её конце, чтобы соблюсти <u>требования выравнивания памяти</u>.

Выравнивание помогает процессору и платформе эффективно обращаться к данным. Поэтому порядок полей в `struct` может влиять на размер структуры.

## Пример

```
package main

import (
	"fmt"
	"unsafe"
)

type S1 struct {
	a bool
	b int64
	c bool
}

type S2 struct {
	a bool
	c bool
	b int64
}

func main() {
	fmt.Println(unsafe.Sizeof(S1{})) // обычно 24 на 64-битной платформе
	fmt.Println(unsafe.Sizeof(S2{})) // обычно 16 на 64-битной платформе
}
```

В типичном 64-битном окружении `int64` выравнивается по границе в 8 байт:
- **`S1`**: после `a` добавляется padding перед `b`; после `b` — padding перед `c` или в конце структуры, чтобы итоговый размер соответствовал выравниванию. Типичный размер — 24 байта.
- **`S2`**: два поля `bool` располагаются рядом, затем идёт `int64`. Padding нужен перед `b`, а общий размер обычно составляет 16 байт.

Точные размеры и правила выравнивания зависят от архитектуры и реализации [[1.1.0. Go Basics|Go]], поэтому значения в примере типичны, но не универсальны.

## Как проверить расположение полей

Пакет `unsafe` позволяет исследовать размер, выравнивание и смещения полей:
```
unsafe.Sizeof(S1{})                 // размер структуры
unsafe.Alignof(S1{})                // выравнивание структуры
unsafe.Offsetof(S1{}.b)              // смещение поля b от начала структуры
```

`unsafe` предназначен для низкоуровневых задач. Для обычной бизнес-логики, как правило, не требуется учитывать точные смещения полей.

## Как уменьшить padding

Часто помогает располагать поля от более крупных типов к более мелким, группируя поля с похожими требованиями к выравниванию. Это не универсальное правило: проверяйте реальный размер через `unsafe.Sizeof` и учитывайте читаемость кода.

## Главное

- Padding добавляется ради выравнивания, а не хранит полезные данные.
- Порядок полей может менять размер структуры.
- Размер структуры зависит от типов полей, архитектуры и правил выравнивания.
- Не меняйте порядок полей только ради экономии нескольких байтов без измерений и понимания требований к коду.
