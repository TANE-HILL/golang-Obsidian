# `unsafe.Pointer` и пакет `unsafe`

## Определение

`unsafe.Pointer` — специальный тип [[1.1.0. Go Basics|Go]] для работы с указателями в ситуациях, которые обходят обычные гарантии системы типов. Пакет `unsafe` предоставляет низкоуровневые средства для работы с памятью.

Использовать `unsafe` следует только при необходимости: ошибочное применение может привести к некорректному поведению программы, которое компилятор не всегда способен обнаружить.

## Основные элементы

|Элемент|Назначение|
|---|---|
|`unsafe.Pointer`|Указатель, который можно преобразовывать между указателями разных типов с соблюдением правил `unsafe`.|
|`unsafe.Sizeof(x)`|Размер значения `x` в байтах; не включает память, на которую `x` может ссылаться.|
|`unsafe.Alignof(x)`|Требование к выравниванию значения соответствующего типа.|
|`unsafe.Offsetof(x.f)`|Смещение поля `f` от начала структуры.|
|`unsafe.Add(ptr, n)`|Указатель на адрес, смещённый от `ptr` на `n` байт.|
|`unsafe.Slice(ptr, len)`|Срез заданной длины, начинающийся с `ptr`.|
|`unsafe.String(ptr, len)`|Строка, представляющая последовательность байтов по указанному адресу и длине.|
|`unsafe.StringData(s)`|Указатель на байты строки.|
|`unsafe.SliceData(s)`|Указатель на первый элемент базового массива среза с учётом правил для пустых срезов.|

Доступность отдельных функций зависит от версии Go. Например, `unsafe.Add`, `unsafe.Slice`, `unsafe.String`, `unsafe.StringData` и `unsafe.SliceData` появились в разных версиях после введения пакета `unsafe`; сверяйся с документацией версии Go в проекте.

## `unsafe.Pointer` и обычные указатели

Обычный указатель имеет конкретный тип, например `*int` или `*MyStruct`. Компилятор проверяет допустимость операций с ним.

`unsafe.Pointer` позволяет выполнять некоторые преобразования между указателями разных типов, но сам по себе не является универсальным разрешением на любые манипуляции с памятью.

Типичные преобразования выглядят так:

```
var x int
p := unsafe.Pointer(&x)
q := (*int)(p)
_ = q
```

Преобразование не меняет данные, на которые указывает адрес; оно меняет тип указателя. Преобразование корректно только при соблюдении правил Go для `unsafe`.

## Преобразование адресов и смещения

`unsafe.Add` позволяет получить адрес, смещённый на заданное число байтов:

```
next := unsafe.Add(ptr, offset)
```

Это низкоуровневая операция. Смещение должно оставаться в пределах допустимого объекта памяти, а указатель должен использоваться согласно правилам языка и документации `unsafe`.

Не следует заменять `unsafe.Add` арифметикой над целыми числами без необходимости. Преобразования указателей в целые числа и обратно особенно легко приводят к ошибкам.

## Размер, выравнивание и смещение

```
size := unsafe.Sizeof(value)
align := unsafe.Alignof(value)
offset := unsafe.Offsetof(s.Field)
```

- `Sizeof` возвращает размер значения в байтах.
- `Alignof` возвращает выравнивание, необходимое для значения соответствующего типа.
- `Offsetof` возвращает смещение поля структуры от её начала.

Эти значения зависят от типа и архитектуры целевой платформы. `Sizeof` не измеряет полный объём памяти, занимаемый объектами, на которые значение может ссылаться.

## Ограничения и риски

- `unsafe` обходит часть проверок системы типов, но не отменяет требования корректного доступа к памяти.
- Нельзя разыменовывать указатель, если он не указывает на корректно расположенное значение нужного типа.
- Нужно учитывать выравнивание, размер объекта и границы памяти.
- Нельзя предполагать, что layout структур и внутреннее представление типов одинаковы на всех архитектурах или во всех версиях Go.
- Неправильные преобразования могут вызвать повреждение данных, аварийное завершение или поведение, не гарантированное спецификацией.
- Код с `unsafe` сложнее поддерживать и проверять; он должен быть минимальным и сопровождаться объяснением, почему безопасного решения недостаточно.

## `unsafe` и сборщик мусора

Go runtime и сборщик мусора должны понимать, какие значения являются указателями на объекты в памяти. Неправильное сокрытие указателя, преобразование или хранение адреса может мешать корректной работе с памятью и выходить за рамки поддерживаемых гарантий.

Нельзя считать произвольное целое число, содержащее адрес, полноценной заменой указателю. Для допустимых преобразований следует использовать документированные шаблоны `unsafe`.

## Когда применяют

`unsafe` встречается в низкоуровневых библиотеках, реализации структур данных, взаимодействии с системными API и оптимизациях, где важны layout памяти или отсутствие копирования.

Перед применением стоит проверить:

1. Можно ли решить задачу обычными типами Go.
2. Есть ли документированный шаблон преобразования для нужной операции.
3. Сохраняются ли корректные тип, размер, выравнивание и время жизни объекта.
4. Нужны ли тесты на поддерживаемых архитектурах и версиях Go.

## Кратко

- `unsafe.Pointer` позволяет выполнять ограниченный набор низкоуровневых преобразований указателей.
- `Sizeof`, `Alignof` и `Offsetof` описывают размер, выравнивание и расположение полей.
- `Add`, `Slice` и строковые функции `unsafe` позволяют работать с адресами и представлениями данных по документированным правилам.
- `unsafe` не делает недопустимые операции безопасными и не гарантирует переносимость между архитектурами.
- Используй `unsafe` минимально и сверяйся с документацией конкретной версии Go.
