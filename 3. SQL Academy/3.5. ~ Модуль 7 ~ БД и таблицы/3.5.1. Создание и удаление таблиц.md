 # Создание и удаление таблиц

Перед созданием таблицы необходимо выбрать [[3.0.0. Что такое БД и СУБД|базу данных]], в которую таблица будет записана. В PostgreSQL подключение к нужной базе данных выполняется на уровне соединения с сервером, поэтому отдельный оператор `USE` не используется.

Для создания таблицы используется оператор `CREATE TABLE`. Базовый синтаксис:
```PostgreSQL
CREATE TABLE [IF NOT EXISTS] имя_таблицы (
    столбец_1 тип_данных,
    [столбец_2 тип_данных,]
    ...
    [столбец_n тип_данных,]
);
```
Например, создадим таблицу пользователей:
```PostgreSQL
CREATE TABLE Users (
    id INTEGER,
    name VARCHAR(255),
    age INTEGER
);
```

`INTEGER`, `VARCHAR(255)` — типы данных: числовой и строковый соответственно. Более подробно о них можно будет узнать в следующих статьях.

---
# Дополнительные параметры определения столбцов

Помимо названия столбца и его типа, в определение столбца можно добавлять следующие параметры:
- `PRIMARY KEY` — указывает колонку или множество колонок как [[3.0.4. Структура реляционных БД#Первичный ключ|первичный ключ]].
- `GENERATED ALWAYS AS IDENTITY` — автоматически генерирует значения для колонки при добавлении новых записей.
- `UNIQUE` — указывает, что значения в данной колонке для всех записей должны быть отличными друг от друга.
- `NOT NULL` — указывает, что значения в данной колонке не должны быть `NULL`.
- `DEFAULT` — задаёт значение по умолчанию.

Для нашей таблицы пользователей можно указать следующие параметры:
```PostgreSQL
CREATE TABLE Users (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    age INTEGER NOT NULL DEFAULT 18
);
```

Здесь:
- `id` — поле типа `INTEGER`, являющееся первичным ключом с автоматической генерацией значений;
- `name` — поле строкового типа с максимальной длиной в 255 символов, являющееся обязательным к заполнению;
- `age` — поле числового типа со значением по умолчанию `18`.

---
# **`CURRENT_TIMESTAMP`** как значение по умолчанию

`CURRENT_TIMESTAMP` удобно использовать, когда нужно автоматически записывать время создания строки.
Например, его можно использовать вместе с типом `TIMESTAMP`:
```PostgreSQL
CREATE TABLE Users (
    id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

При добавлении новой записи значение `created_at` будет автоматически установлено в момент её создания.

# Описание таблицы

Для просмотра структуры таблицы в PostgreSQL можно обратиться к `information_schema.columns`:
```PostgreSQL
SELECT
    column_name,
    data_type,
    is_nullable,
    column_default
FROM information_schema.columns
WHERE table_schema = current_schema()
  AND table_name = 'users';
```

Пример результата:

|column_name|data_type|is_nullable|column_default|
|---|---|---|---|
|id|integer|NO|generated by default as identity|
|name|character varying|NO|NULL|
|age|integer|NO|18|

В отличие от MySQL, оператор `DESCRIBE` в PostgreSQL не используется. Для получения информации о столбцах можно обращаться к системному представлению `information_schema.columns`.

# Дополнительные параметры определения таблицы

Помимо описания столбцов, при создании таблицы можно дополнительно указать параметры самой таблицы.

## Первичный ключ **`PRIMARY KEY`**

Если первичный ключ не был определён непосредственно в описании столбца, его можно указать после перечисления столбцов:
```PostgreSQL
CREATE TABLE Users (
    id INTEGER,
    name VARCHAR(255) NOT NULL,
    age INTEGER NOT NULL DEFAULT 18,
    PRIMARY KEY (id)
);
```

`PRIMARY KEY` может состоять как из одного столбца, так и из нескольких.

---
## Внешние ключи **`FOREIGN KEY`**

Предположим, что мы хотим хранить данные о компании, в которой работают пользователи. Создадим таблицу `Companies`, в которой будем хранить уникальный идентификатор и название компании:
```PostgreSQL
CREATE TABLE Companies (
    id INTEGER PRIMARY KEY,
    name VARCHAR(255) NOT NULL
);
```

Дальше добавим в таблицу `Users` поле `company`, которое будет ссылаться на запись в таблице `Companies`:
```PostgreSQL
CREATE TABLE Users (
    id INTEGER,
    name VARCHAR(255) NOT NULL,
    age INTEGER NOT NULL DEFAULT 18,
    company INTEGER,
    PRIMARY KEY (id),
    FOREIGN KEY (company) REFERENCES Companies (id)
);
```

Для того чтобы при добавлении новых записей в таблицу `Users` гарантировать, что в колонке `company` находится идентификатор, существующий в таблице `Companies`, используется **внешний ключ**.

Синтаксис:
```PostgreSQL
FOREIGN KEY (столбец_1, столбец_n)
REFERENCES внешняя_таблица (
    столбец_во_внешней_таблице_1,
    столбец_во_внешней_таблице_n
)
[ON DELETE действие]
[ON UPDATE действие]
```

Внешний ключ обеспечивает ссылочную целостность данных между таблицами.

---
# Действия при изменении или удалении связанных записей

При наличии внешних ключей можно определить поведение текущей записи при изменении или удалении записи, на которую она ссылается.

```PostgreSQL
CREATE TABLE Users (
    id INTEGER,
    name VARCHAR(255) NOT NULL,
    age INTEGER NOT NULL DEFAULT 18,
    company INTEGER,
    PRIMARY KEY (id),
    FOREIGN KEY (company)
        REFERENCES Companies (id)
        ON DELETE RESTRICT
        ON UPDATE CASCADE
);
```

## **` ON DELETE RESTRICT `**

`ON DELETE RESTRICT` означает, что если попытаться удалить компанию, на которую ссылаются записи из таблицы `Users`, база данных не позволит выполнить удаление.
```text
ERROR: update or delete on table "companies" violates foreign key constraint
```

## **` ON DELETE CASCADE `**

При использовании `ON DELETE CASCADE` удаление компании приведёт к удалению всех пользователей, ссылающихся на эту компанию.
```PostgreSQL
FOREIGN KEY (company)
REFERENCES Companies (id)
ON DELETE CASCADE
```

## **` ON DELETE SET NULL `**

При использовании `ON DELETE SET NULL` в поле `company` связанных пользователей будет записано значение `NULL`.
```PostgreSQL
FOREIGN KEY (company)
REFERENCES Companies (id)
ON DELETE SET NULL
```
- Для этого столбец `company` должен допускать значение `NULL`.

## **` ON UPDATE CASCADE `**

`ON UPDATE CASCADE` означает, что при изменении идентификатора компании соответствующие значения в поле `company` таблицы `Users` также будут изменены.
```PostgreSQL
FOREIGN KEY (company)
REFERENCES Companies (id)
ON UPDATE CASCADE
```
- Таким образом, внешние ключи позволяют не только связывать таблицы, но и задавать правила поведения связанных записей при `DELETE` и `UPDATE`.

---
# Удаление таблицы

Удаление таблицы производится с помощью оператора `DROP TABLE`:
```PostgreSQL
DROP TABLE имя_таблицы;
```
Если таблица может отсутствовать, можно использовать `IF EXISTS`:
```PostgreSQL
DROP TABLE IF EXISTS имя_таблицы;
```

> ⚠️ **Важно:** `DROP TABLE` удаляет саму таблицу вместе с содержащимися в ней данными.

---
# Главное
- `CREATE TABLE` — создание таблицы.
- `IF NOT EXISTS` — позволяет не выдавать ошибку, если таблица уже существует.
- `PRIMARY KEY` — первичный ключ.
- `GENERATED ALWAYS AS IDENTITY` — автоматическая генерация значений.
- `UNIQUE` — уникальные значения.
- `NOT NULL` — запрещает `NULL`.
- `DEFAULT` — значение по умолчанию.
- `FOREIGN KEY` — внешний ключ.
- `REFERENCES` — указывает связанную таблицу и столбец.
- `ON DELETE` — определяет поведение при удалении связанной записи.
- `ON UPDATE` — определяет поведение при изменении связанной записи.
- `DROP TABLE` — удаление таблицы.
- `information_schema.columns` — просмотр информации о столбцах таблицы.

# Практика

<u>Задание 1:</u>
Создайте таблицу **`Classrooms`** со следующими полями:
- **`id`** — обязательное поле типа **`INTEGER`**, являющееся первичным ключом с автоинкрементом;
- **`room_number`** — обязательное уникальное поле типа **`INTEGER`**;
- **`floor`** — обязательное поле типа **`INTEGER`** со значением по умолчанию **`1`**;
- **`building`** — обязательное поле типа **`VARCHAR(50)`**;
- **`description`** — поле типа **`TEXT`**;
- **`created_at`** — поле типа **`TIMESTAMP`** со значением по умолчанию, равным текущим дате и времени.
<u>Решение:</u>
```PostgreSQL
CREATE TABLE Classrooms (
    id SERIAL PRIMARY KEY,
    room_number INTEGER NOT NULL UNIQUE,
    floor INTEGER NOT NULL DEFAULT 1,
    building VARCHAR(50) NOT NULL,
    description TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

<u>Задание 2:</u>
Создайте таблицу **`Homework`** со следующими полями:
- **`id`** — обязательное поле типа **`INTEGER`**, являющееся первичным ключом с автоинкрементом;
- **`lesson_id`** — обязательное поле типа **`INTEGER`**;
- **`description`** — обязательное поле типа **`TEXT`**;
- **`due_date`** — обязательное поле типа **`DATE`**;
Для **`lesson_id`** добавьте внешний ключ на **`Lessons(id)`**. При удалении и обновлении связанной записи изменения должны применяться каскадно.
<u>Решение:</u>
```PostgreSQL
CREATE TABLE Homework (
    id SERIAL PRIMARY KEY,
    lesson_id INTEGER NOT NULL,
    description TEXT NOT NULL,
    due_date DATE NOT NULL,
    FOREIGN KEY (lesson_id) REFERENCES Lessons(id)
        ON UPDATE CASCADE
        ON DELETE CASCADE
)
```

<u>Задание 3:</u>
Удалите таблицу **`Timepair`** из базы данных.
<u>Решение:</u>
```PostgreSQL
DROP TABLE Timepair
```
