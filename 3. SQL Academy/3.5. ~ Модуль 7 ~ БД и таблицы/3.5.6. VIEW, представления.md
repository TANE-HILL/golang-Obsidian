# Представления, **` VIEW `**

Хорошо спроектированные приложения обычно предоставляют открытый интерфейс, скрывая детали реализации, что позволяет вносить изменения в дизайн без влияния на конечных пользователей.

При разработке базы данных можно достичь аналогичного результата, закрывая таблицы и предоставляя доступ к данным только через набор представлений.

Представления позволяют создавать дополнительный уровень абстракции между пользователем и [[3.0.0. Что такое БД и СУБД|базой данных]].

---
# Что такое представление

**Представление *(`VIEW`)*** — объект базы данных, являющийся результатом выполнения `SELECT`-запроса в момент обращения к представлению.

Представления иногда называют ***«виртуальными таблицами»***. Это связано с тем, что представление для пользователя выглядит как таблица, но фактически не хранит данные, а извлекает их из других таблиц в момент обращения.

Если данные в основной таблице меняются, пользователь получает актуальные данные при обращении к представлению, использующему эту таблицу. При этом обычные представления не кэшируют результаты выборки из таблицы в процессе работы.

---
# Пример создания представления

В качестве простого примера предположим, что необходимо частично скрыть адреса электронной почты в таблице `Users`.

Вместо предоставления прямого доступа к таблице `Users` можно определить представление `ViewUsers` и использовать его для доступа к данным.

```PostgreSQL
CREATE VIEW ViewUsers AS
SELECT id,
       name,
       CONCAT(SUBSTRING(email, 1, 2), '****', RIGHT(email, 4)) AS email
FROM Users;
```

Здесь адрес электронной почты преобразуется таким образом, чтобы часть информации была скрыта.

Представление в `SELECT`-запросе выглядит и используется как обычная таблица:
```PostgreSQL
SELECT * FROM ViewUsers;
```

Пример результата:

|id|name|email|
|--:|---|---|
|1|Bruce Willis|ba****.com|
|2|George Clooney|te****.com|
|3|Kevin Costner|me****.com|
|4|Donald Sutherland|ra****.net|

# Получение информации о представлении

В PostgreSQL для получения информации о столбцах представления можно использовать `information_schema.columns`.

```PostgreSQL
SELECT column_name,
       data_type,
       is_nullable
FROM information_schema.columns
WHERE table_name = 'viewusers';
```

Здесь используется `WHERE` для выбора информации только о конкретном представлении.

# Общий синтаксис представления

```PostgreSQL
CREATE [OR REPLACE]
VIEW имя_представления [(имена_полей_представления)]
AS
select_выражение;
```

`OR REPLACE` позволяет заменить существующее представление н овым определением, если представление с таким именем уже существует.

Например:
```PostgreSQL
CREATE OR REPLACE VIEW ViewUsers AS
SELECT id,
       name,
       email
FROM Users;
```

# Зачем нужны представления

## Упрощение сложных запросов

Представления используются для упрощения сложных запросов и создания абстракции между пользователем и базой данных. Они могут скрывать сложность структуры данных и предоставлять упрощённый интерфейс для доступа к данным.

Например, сложный `JOIN`-запрос можно сохранить в представлении и затем обращаться к его результату как к обычной таблице.

---
## Улучшение производительности

Представления могут инкапсулировать сложные запросы и упростить их повторное использование.

PostgreSQL также поддерживает **материализованные представления `MATERIALIZED VIEW`**, которые физически хранят результаты запроса и могут обновляться отдельно. Это позволяет использовать их для работы со сложными запросами, результаты которых не требуется получать заново при каждом обращении.

```PostgreSQL
CREATE MATERIALIZED VIEW user_statistics AS
SELECT ...
```

Материализованное представление можно обновить с помощью:
```PostgreSQL
REFRESH MATERIALIZED VIEW user_statistics;
```

---
## Обеспечение безопасности

Представления могут использоваться для ограничения доступа к конфиденциальным данным.

Например, можно создать представление, которое содержит только необходимые столбцы или строки таблицы, скрывая остальные данные от пользователя.

```PostgreSQL
CREATE VIEW PublicUsers AS
SELECT id,
       name
FROM Users;
```

В таком случае пользователю предоставляется доступ к представлению, а не ко всей исходной таблице.

---
# Итоги

Представления (`VIEW`) позволяют:
- упростить сложные `SELECT`-запросы;
- скрыть сложность структуры данных;
- предоставить единый интерфейс доступа к данным;
- ограничить доступ к отдельным столбцам и строкам;
- использовать материализованные представления для хранения результатов сложных запросов.

**Представление** — это виртуальная таблица, которая не хранит собственные данные, а получает их из исходных таблиц при обращении.

# Практика

<u>Задание 1:</u>
На основании таблицы **`Student`** создайте представление **`ViewStudent`**, содержащие только поля **`id`**, **`first_name`** и **`last_name`**.
<u>Решение:</u>
```PostgreSQL
CREATE VIEW ViewStudent AS
SELECT id, first_name, last_name
    FROM Student
```
