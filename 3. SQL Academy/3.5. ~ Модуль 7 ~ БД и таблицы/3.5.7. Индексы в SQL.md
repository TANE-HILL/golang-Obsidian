# Индексы в SQL

Когда в таблице появляется большое количество данных, поиск по ней может занимать значительное время. Например, при выполнении запроса с условием [[3.1.4. Условный оператор WHERE|WHERE]], [[3.0.0. Что такое БД и СУБД|СУБД]] без индекса может быть вынуждена проверить каждую строку таблицы.

```PostgreSQL
SELECT email
FROM Users
WHERE email LIKE 'l%';
```

Для небольших таблиц такой подход подходит, но по мере роста объёма данных становится менее эффективным.

**Индекс** — специальная структура данных, которая позволяет СУБД быстрее находить нужные строки без полного сканирования таблицы. Индекс содержит значения индексируемого столбца или столбцов и информацию, позволяющую найти соответствующие строки в таблице.

Таким образом, основная задача индексов — ускорить поиск нужных данных в таблице.

---
# Создание индекса

Индекс можно создать для столбца, который часто используется при поиске:

```PostgreSQL
CREATE INDEX idx_email
ON Users (email);
```

Здесь создаётся индекс `idx_email` для столбца `email`.

При наличии индекса оптимизатор запросов может выбрать его использование, если считает это эффективным для конкретного SQL-запроса. Если в таблице существует несколько индексов, оптимизатор выбирает подходящий вариант.

---
# Просмотр индексов в PostgreSQL

В PostgreSQL информацию об индексах можно получить из системного представления `pg_indexes`:
```PostgreSQL
SELECT indexname,
       indexdef
FROM pg_indexes
WHERE tablename = 'users';
```

Пример результата:

|indexname|indexdef|
|---|---|
|users_pkey|`CREATE UNIQUE INDEX users_pkey ON public.users USING btree (id)`|
|idx_email|`CREATE INDEX idx_email ON public.users USING btree (email)`|

PostgreSQL автоматически создаёт индекс для столбца [[3.0.4. Структура реляционных БД#Первичный ключ|первичного ключа]].

Первичный ключ гарантирует уникальность значений и не допускает `NULL`.

---
# Типы индексов в PostgreSQL

PostgreSQL поддерживает несколько типов индексов:
- **B-tree** — используется по умолчанию, подходит для операций сравнения и сортировки;
- **Hash** — используется для операций равенства;
- **GIN** — подходит для составных значений, например массивов и `JSON`;
- **GiST** — используется для различных типов данных, в том числе геометрических;
- **BRIN** — подходит для очень больших таблиц, в которых значения имеют естественный порядок.

---
# Удаление индекса

Если индекс больше не нужен, его можно удалить:
```PostgreSQL
DROP INDEX idx_email;
```

---
# Уникальные индексы

Уникальность значений можно обеспечить с помощью уникального индекса.

Например, адрес электронной почты должен быть уникальным для каждого пользователя:
```PostgreSQL
CREATE UNIQUE INDEX idx_email
ON Users (email);
```

Уникальный индекс выполняет две функции:
- ускоряет поиск по индексируемому столбцу;
- предотвращает дублирование значений.

При попытке добавить значение, которое уже существует в уникальном индексе, PostgreSQL вернёт ошибку.

```text
ERROR: duplicate key value violates unique constraint "idx_email"
DETAIL: Key (email)=(duplicate@gmail.com) already exists.
```

Для столбцов, определённых как [[3.0.4. Структура реляционных БД#Первичный ключ|первичный ключ]], отдельно создавать уникальный индекс не требуется, поскольку PostgreSQL создаёт его автоматически.

---
# Многостолбцовые индексы

Индекс может включать несколько столбцов. Например, для поиска студентов по фамилии и имени можно создать составной индекс:

```PostgreSQL
CREATE INDEX idx_full_name
ON Student (last_name, first_name);
```

Такой индекс полезен для запросов, использующих `last_name` и `first_name`, а также для запросов, использующих только `last_name`.

Для запроса, использующего только `first_name`, такой индекс обычно не будет эффективным, поскольку первым столбцом индекса является `last_name`.

Поэтому при создании составного индекса важно учитывать порядок столбцов.

---
# Как используются индексы

Индексы часто применяются [[3.0.0. Что такое БД и СУБД|СУБД]] для поиска нужных строк. Например:
```PostgreSQL
SELECT id,
       first_name,
       last_name
FROM Student
WHERE first_name LIKE 'A%'
  AND last_name LIKE 'L%';
```

Для выполнения такого запроса PostgreSQL может выбрать разные способы:
- выполнить полное сканирование таблицы;
- использовать индекс по `last_name`;
- использовать составной индекс по `last_name` и `first_name`.

Какой способ будет выбран, зависит от оптимизатора запросов и статистики базы данных.

---
# **` EXPLAIN `**

Для просмотра плана выполнения запроса используется команда `EXPLAIN`:
```PostgreSQL
EXPLAIN
SELECT id,
       first_name,
       last_name
FROM Student
WHERE first_name LIKE 'A%'
  AND last_name LIKE 'L%';
```

`EXPLAIN` показывает, каким способом PostgreSQL планирует выполнить запрос.

Например, в результате можно увидеть:
```text
Index Scan using idx_full_name on student
```

Это означает, что для выполнения запроса планируется использовать индекс.

Также можно использовать `EXPLAIN ANALYZE`. В отличие от обычного `EXPLAIN`, он фактически выполняет запрос и показывает реальную статистику выполнения:
```PostgreSQL
EXPLAIN ANALYZE
SELECT id,
       first_name,
       last_name
FROM Student
WHERE first_name LIKE 'A%'
  AND last_name LIKE 'L%';
```

С помощью `EXPLAIN ANALYZE` можно сравнить планируемые и фактические показатели выполнения запроса.

---
# Обратная сторона индексов

Индексы ускоряют операции чтения, но требуют дополнительных ресурсов.

При добавлении, удалении или изменении данных PostgreSQL должен поддерживать связанные индексы в актуальном состоянии. Поэтому большое количество индексов может замедлять [[3.3.0. INSERT - добавление данных|вставку]], [[3.3.1. UPDATE - обновление данных|обновление]] и [[3.3.2. DELETE - удаление данных|удаление]] данных.

Кроме того, индексы занимают дополнительное место на диске.

Поэтому не стоит создавать индексы для всех столбцов подряд. Индексы следует добавлять там, где они действительно помогают ускорить выполнение запросов.

---
# Главное

- Индекс ускоряет поиск данных в таблице.
- `B-tree` — стандартный тип индекса в PostgreSQL.
- Индекс можно создать с помощью `CREATE INDEX`.
- Уникальный индекс предотвращает дублирование значений.
- Составной индекс может включать несколько столбцов.
- `EXPLAIN` показывает план выполнения запроса.
- `EXPLAIN ANALYZE` показывает фактическую статистику выполнения.
- Индексы ускоряют чтение, но увеличивают стоимость операций записи и занимают место на диске.
