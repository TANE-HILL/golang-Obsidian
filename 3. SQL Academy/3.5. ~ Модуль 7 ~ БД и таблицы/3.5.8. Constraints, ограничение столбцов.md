# Ограничения столбцов *(**`Constraints`**)*

**Ограничения *(`Constraints`)*** — это правила, применяемые к данным в таблице для поддержания их точности и надёжности. Они помогают обеспечивать целостность данных и соответствие бизнес-правилам.

Ограничения могут предотвращать добавление, изменение или удаление данных, нарушающих установленные правила. Например:
- наличие нескольких записей с одинаковыми идентификаторами;
- ссылки на несуществующие записи в других таблицах;
- отсутствие обязательных данных;
- ввод некорректных значений.

---
# Основные типы ограничений

В SQL существуют следующие основные типы ограничений:

1. `PRIMARY KEY` — уникальный идентификатор записи в таблице;
2. `FOREIGN KEY` — обеспечивает ссылочную целостность между таблицами;
3. `UNIQUE` — гарантирует уникальность значений в столбце или группе столбцов;
4. `NOT NULL` — запрещает `NULL`-значения в столбце;
5. `CHECK` — проверяет соответствие данных заданному условию;
6. `DEFAULT` — устанавливает значение по умолчанию для столбца.

---
# **` PRIMARY KEY `**

**[[3.0.4. Структура реляционных БД#Первичный ключ|Первичный ключ]] *(`PRIMARY KEY`)*** — столбец или комбинация столбцов, которые однозначно идентифицируют каждую строку в таблице.

Первичный ключ не может содержать `NULL`-значения и должен быть уникальным. Таблица может иметь только один первичный ключ.
```PostgreSQL
CREATE TABLE Users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50),
    email VARCHAR(100)
);
```

Ограничение можно определить отдельно от столбца:
```PostgreSQL
CREATE TABLE Users (
    id SERIAL,
    username VARCHAR(50),
    email VARCHAR(100),
    CONSTRAINT pk_users PRIMARY KEY (id)
);
```

При попытке добавить запись с уже существующим первичным ключом СУБД выдаст ошибку:
```text
ERROR: duplicate key value violates unique constraint "users_pkey"
DETAIL: Key (id)=(1) already exists.
```

`PRIMARY KEY` связан с индексами: PostgreSQL автоматически создаёт уникальный индекс для первичного ключа.

---
# **` FOREIGN KEY `**

**Внешний ключ *(`FOREIGN KEY`)*** — столбец или группа столбцов в одной таблице, которые ссылаются на первичный ключ другой таблицы.

Он обеспечивает ссылочную целостность, гарантируя, что значения внешнего ключа соответствуют существующим значениям в связанной таблице.

```PostgreSQL
CREATE TABLE Orders (
    order_id INTEGER PRIMARY KEY,
    user_id INTEGER,
    order_date DATE,
    FOREIGN KEY (user_id) REFERENCES Users(id)
);
```

Благодаря `FOREIGN KEY`:
- нельзя добавить заказ для несуществующего пользователя;
- нельзя удалить пользователя, у которого есть связанные заказы, если не указано специальное действие.

Можно определить действия, которые должны выполняться при удалении или обновлении связанных данных:
```PostgreSQL
CREATE TABLE Orders (
    order_id INTEGER PRIMARY KEY,
    user_id INTEGER,
    order_date DATE,
    FOREIGN KEY (user_id) REFERENCES Users(id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
```

Основные варианты `ON DELETE` и `ON UPDATE`:
- `CASCADE` — автоматически удаляет или обновляет связанные записи;
- `SET NULL` — устанавливает `NULL` для внешнего ключа;
- `SET DEFAULT` — устанавливает значение по умолчанию;
- `RESTRICT` — запрещает удаление или обновление;
- `NO ACTION` — также запрещает операцию при нарушении ограничения.

Подробнее действия `CASCADE`, `SET NULL`, `RESTRICT` и другие используются при работе с внешними ключами.

---
# **` UNIQUE `**

Ограничение `UNIQUE` гарантирует, что все значения в столбце или группе столбцов уникальны.

В отличие от `PRIMARY KEY`, `UNIQUE` допускает `NULL`-значения.

```PostgreSQL
CREATE TABLE Users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE,
    email VARCHAR(100) UNIQUE
);
```

В этом примере нельзя создать несколько пользователей с одинаковым именем пользователя или адресом электронной почты.

`UNIQUE` также можно определить для нескольких столбцов:
```PostgreSQL
CREATE TABLE Users (
    id SERIAL PRIMARY KEY,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    CONSTRAINT uq_full_name UNIQUE (first_name, last_name)
);
```

В этом случае уникальной должна быть комбинация `first_name` и `last_name`.

---
# **` NOT NULL `**

Ограничение `NOT NULL` гарантирует, что столбец не может содержать `NULL`-значения.

Оно используется для обязательных полей, без которых запись не имеет смысла.

```PostgreSQL
CREATE TABLE Users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL,
    email VARCHAR(100) NOT NULL,
    bio TEXT
);
```

В этом примере `username` и `email` являются обязательными, а `bio` может содержать `NULL`.

---
# **` CHECK `**

Ограничение `CHECK` позволяет определить условие, которому должны соответствовать значения в столбце.

Это позволяет реализовать определённые бизнес-правила непосредственно на уровне базы данных.

```PostgreSQL
CREATE TABLE Products (
    product_id SERIAL PRIMARY KEY,
    product_name VARCHAR(100) NOT NULL,
    price NUMERIC(10, 2) CHECK (price > 0),
    quantity INTEGER CHECK (quantity >= 0)
);
```

Можно создать именованное ограничение:
```PostgreSQL
CREATE TABLE Employees (
    employee_id SERIAL PRIMARY KEY,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    birth_date DATE NOT NULL,
    hire_date DATE NOT NULL,
    CONSTRAINT chk_dates CHECK (hire_date > birth_date)
);
```

PostgreSQL также позволяет использовать более сложные условия:
```PostgreSQL
CREATE TABLE Users (
    id SERIAL PRIMARY KEY,
    email VARCHAR(100)
        CHECK (email ~* '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$'),
    age INTEGER CHECK (age >= 0 AND age <= 150)
);
```

---
# **` DEFAULT `**

Ограничение `DEFAULT` устанавливает значение, которое будет использовано, если при добавлении новой записи значение для столбца не указано.

```PostgreSQL
CREATE TABLE Orders (
    order_id SERIAL PRIMARY KEY,
    user_id INTEGER,
    order_date DATE DEFAULT CURRENT_DATE,
    status VARCHAR(20) DEFAULT 'Pending',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES Users(id)
);
```

В этом примере:
- `order_date` по умолчанию получает текущую дату;
- `status` получает значение `'Pending'`;
- `created_at` получает текущую дату и время.

PostgreSQL также позволяет использовать функции в качестве значений по умолчанию:
```PostgreSQL
CREATE TABLE Users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50),
    created_at TIMESTAMP DEFAULT NOW(),
    uuid_field UUID DEFAULT gen_random_uuid()
);
```

# Добавление ограничений

Ограничения можно добавлять не только при создании таблицы, но и при её изменении с помощью **`ALTER TABLE`**.

## **`PRIMARY KEY`**

```PostgreSQL
ALTER TABLE Users
ADD PRIMARY KEY (id);
```

## **`FOREIGN KEY`**

```PostgreSQL
ALTER TABLE Orders
ADD CONSTRAINT fk_user
FOREIGN KEY (user_id)
REFERENCES Users(id);
```

## **`UNIQUE`**

```PostgreSQL
ALTER TABLE Users
ADD CONSTRAINT uq_email UNIQUE (email);
```

## **`CHECK`**

```PostgreSQL
ALTER TABLE Products
ADD CONSTRAINT chk_price CHECK (price > 0);
```

## **`NOT NULL`**

```PostgreSQL
ALTER TABLE Users
ALTER COLUMN username SET NOT NULL;
```

## **`DEFAULT`**

```PostgreSQL
ALTER TABLE Orders
ALTER COLUMN status SET DEFAULT 'Pending';
```

---
# Удаление ограничений

Удаление ограничений также выполняется с помощью `ALTER TABLE`.

## **`PRIMARY KEY`**

```PostgreSQL
ALTER TABLE Users
DROP CONSTRAINT users_pkey;
```

## **`FOREIGN KEY`**

```PostgreSQL
ALTER TABLE Orders
DROP CONSTRAINT fk_user;
```

## **`UNIQUE`**

```PostgreSQL
ALTER TABLE Users
DROP CONSTRAINT uq_email;
```

## **`CHECK`**

```PostgreSQL
ALTER TABLE Products
DROP CONSTRAINT chk_price;
```

## **`NOT NULL`**

```PostgreSQL
ALTER TABLE Users
ALTER COLUMN username DROP NOT NULL;
```

## **`DEFAULT`**

```PostgreSQL
ALTER TABLE Orders
ALTER COLUMN status DROP DEFAULT;
```

# Практика использования ограничений

При проектировании базы данных следует придерживаться следующих рекомендаций:

1. Определяйте [[3.0.4. Структура реляционных БД#Первичный ключ|первичный ключ]] для каждой таблицы, чтобы однозначно идентифицировать каждую запись.
2. Используйте внешние ключи для обеспечения ссылочной целостности между связанными таблицами.
3. Применяйте `NOT NULL` для столбцов, которые должны содержать значения.
4. Используйте `UNIQUE` для столбцов, значения которых должны быть уникальными.
5. Добавляйте `CHECK` для столбцов, значения которых должны соответствовать определённым правилам.
6. Устанавливайте `DEFAULT` для столбцов, которые часто принимают одно и то же значение.
7. Давайте ограничениям понятные имена, например `CONSTRAINT pk_users PRIMARY KEY (id)`, чтобы упростить их идентификацию и управление.

Таким образом, **ограничения позволяют переносить правила целостности и корректности данных непосредственно на уровень базы данных**.

# Практика

<u>Задание 1:</u>
Сделайте столбец **`email`** таблицы **`Users`** обязательным *(**`NOT NULL`**)*.
<u>Решение:</u>
```PostgreSQL
ALTER TABLE Users
ALTER COLUMN email SET NOT NULL
```

<u>Задание 2:</u>
Установите значение по умолчанию **`0`** для столбца **`total`** таблицы **`Reservations`**.
<u>Решение:</u>
```PostgreSQL
ALTER TABLE Reservations
ALTER COLUMN total SET DEFAULT 0
```
