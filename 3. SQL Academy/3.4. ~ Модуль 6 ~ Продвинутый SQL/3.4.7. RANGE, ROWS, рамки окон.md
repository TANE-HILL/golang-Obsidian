# Рамки окон, `RANGE` и `ROWS`

**Рамка окна** определяет подмножество строк, которые используются [[3.4.4. Оконные функции SQL|оконной функцией]] при вычислении значения для текущей строки.

Рамка может изменяться от строки к строке, поэтому её можно представить как «скользящий» набор строк внутри окна.

---
# Рамка окна и партиция

**Партиция** `PARTITION BY` делит весь набор строк на группы. Оконная функция применяется отдельно к каждой партиции.

**Рамка окна** определяет, какие именно строки внутри партиции участвуют в вычислении для текущей строки.

Например:
```PostgreSQL
ROWS BETWEEN 1 PRECEDING AND CURRENT ROW
```

Для каждой строки рамка состоит из неё самой и одной предыдущей строки.
Допустим, значения `price`:

|№|`price`|Строки в рамке|`AVG(price)`|
|--:|--:|---|--:|
|1|170|170|170|
|2|220|170, 220|195|
|3|150|220, 150|185|

Первая строка содержит только себя, поскольку предыдущей строки нет. Для второй строки учитываются первая и вторая строки. Для третьей — вторая и третья.

---
# Рамка по умолчанию

Если `ROWS` или `RANGE` не указаны, рамка окна зависит от наличия `ORDER BY`.

Если `ORDER BY` отсутствует, рамка совпадает со всей партицией:

```PostgreSQL
COUNT(*) OVER (
    PARTITION BY company
)
```

Оконная функция обрабатывает все строки партиции, поэтому результат одинаков для всех строк одной партиции.

Если `ORDER BY` присутствует, по умолчанию используется:

```PostgreSQL
RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

Рамка начинается с первой строки и заканчивается текущей, включая строки с теми же значениями полей сортировки, что и у текущей строки.

---
# Определение границ рамки

Для определения рамки используются `ROWS` или `RANGE`.

Общий синтаксис:

```PostgreSQL
SELECT <оконная_функция>(<поле_таблицы>)
OVER (
    ...
    ROWS | RANGE BETWEEN <начало_рамки> AND <конец_рамки>
);
```

Например, чтобы включить две предыдущие строки и текущую:

```PostgreSQL
... ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
```

Чтобы включить текущую строку и все последующие:

```PostgreSQL
... ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING
```

---
# Возможные границы рамки

|Граница|Описание|
|---|---|
|`UNBOUNDED PRECEDING`|Все строки до текущей|
|`N PRECEDING`|`N` строк до текущей|
|`CURRENT ROW`|Текущая строка|
|`N FOLLOWING`|`N` строк после текущей|
|`UNBOUNDED FOLLOWING`|Все последующие строки|

---
# `ROWS` и `RANGE`

`ROWS` и `RANGE` определяют границы рамки по-разному.

## `ROWS`

`ROWS` основывается на **физическом положении строк** относительно текущей строки.

Например:

```PostgreSQL
ROWS BETWEEN 1 PRECEDING AND CURRENT ROW
```

означает: взять одну физически предыдущую строку и текущую.

Количество строк определяется точно.

---
## `RANGE`

`RANGE` основывается на **значениях столбцов**, указанных в `ORDER BY`.

Например, при сортировке по `price` строки с одинаковым значением `price` могут попасть в одну рамку.

Границы `RANGE` зависят от значений данных, поэтому результат может отличаться от `ROWS`.

---
# Главное

- **Партиция** (`PARTITION BY`) определяет группу строк, внутри которой работает оконная функция.
- **Рамка окна** определяет конкретные строки внутри партиции, участвующие в расчёте.
- `ROWS` определяет рамку по **физическому положению строк**.
- `RANGE` определяет рамку по **значениям полей сортировки**.
- `N PRECEDING` — `N` строк до текущей.
- `CURRENT ROW` — текущая строка.
- `N FOLLOWING` — `N` строк после текущей.
- `UNBOUNDED PRECEDING` — начало партиции.
- `UNBOUNDED FOLLOWING` — конец партиции.
- При `ORDER BY` без явной рамки по умолчанию используется `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`.

# Практика

<u>Задание 1:</u>
Из таблицы **`Payments`** выведите поля **`family_member`**, **`date`**, **`payment_id`**, стоимость покупки в поле **`payment_amount`** и колонку **`spending_last_3_payments`**, в которой должна быть сумма стоимости текущей покупки и двух покупок этого же члена семьи, которые были совершены перед ней. Если предыдущих покупок меньше двух, учитывайте только те, которые есть.
<u>Решение:</u>
```PostgreSQL
SELECT family_member, date, payment_id,
    (unit_price * amount) AS payment_amount,
    SUM(unit_price * amount) OVER (
        PARTITION BY family_member
        ORDER BY date, payment_id
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW)
    AS spending_last_3_payments
FROM Payments
```
