# Хранимые процедуры в SQL

**Хранимые процедуры** — это программные блоки, которые выполняют определённую последовательность действий в базе данных.

В PostgreSQL процедуры могут изменять данные и выполнять сложную бизнес-логику. Процедура не имеет возвращаемого значения как [[3.4.13. Хранимые функции в SQL|функция]], но может передавать данные через выходные параметры `OUT` и `INOUT`.

---
# Общая структура хранимой процедуры

В PostgreSQL процедура создаётся с помощью `CREATE PROCEDURE`:
```PostgreSQL
CREATE OR REPLACE PROCEDURE имя_процедуры(
    параметр_1 ТИП,
    параметр_2 ТИП
)
LANGUAGE plpgsql
AS $$
BEGIN
    -- логика процедуры
END;
$$;
```
- `LANGUAGE plpgsql` — указывает, что процедура написана на языке **PL/pgSQL**.
- `AS $$ ... $$` — **долларовое квотирование**, специальный способ обрамления тела процедуры. Позволяет избежать экранирования символов внутри процедуры.
- `BEGIN ... END` — тело процедуры, содержащее выполняемые команды.

---
# Простой пример процедуры

Создадим процедуру для обновления информации о студенте:
```PostgreSQL
CREATE OR REPLACE PROCEDURE update_student_info(
    student_id INT,
    new_first_name VARCHAR(50),
    new_last_name VARCHAR(50)
)
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE Student
    SET first_name = new_first_name,
        last_name = new_last_name
    WHERE id = student_id;
END;
$$;
```
Вызываем процедуру:
```PostgreSQL
CALL update_student_info(1, 'Alexander', 'Smirnov');
```
Проверяем результат:
```PostgreSQL
SELECT *
FROM Student
WHERE id = 1;
```
- Процедура принимает ID студента и новые данные, затем обновляет соответствующую запись в таблице `Student`. Для выполнения процедуры используется оператор `CALL`.

---
# Типы параметров процедур

Процедуры PostgreSQL поддерживают три основных типа параметров:
- `IN` — входные параметры;
- `OUT` — выходные параметры;
- `INOUT` — параметры, которые могут быть как входными, так и выходными.

Если режим параметра не указан, используется `IN`.

---
# Входные параметры `IN`

Входные параметры передают данные в процедуру. Это наиболее распространённый тип параметров.

```PostgreSQL
CREATE OR REPLACE PROCEDURE add_subject(
    IN subject_id INT,
    IN subject_name VARCHAR(100)
)
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO Subject (id, name)
    VALUES (subject_id, subject_name);
END;
$$;
```
Вызов с входными параметрами:
```PostgreSQL
CALL add_subject(15, 'Mathematics');
```

`IN` используется для передачи значений в процедуру.

---
# Выходные параметры `OUT`

Выходные параметры позволяют процедуре передавать значения вызывающему коду.

Например, процедура может получить информацию о студенте:
```PostgreSQL
CREATE OR REPLACE PROCEDURE get_student_info(
    IN student_id INT,
    OUT student_name VARCHAR(100),
    OUT student_age INT
)
LANGUAGE plpgsql
AS $$
BEGIN
    SELECT
        CONCAT(first_name, ' ', last_name),
        EXTRACT(YEAR FROM AGE(CURRENT_DATE, birthday))::INT
    INTO student_name, student_age
    FROM Student
    WHERE id = student_id;
END;
$$;
```

При вызове процедуры в обычном SQL для `OUT`-параметров указываются значения-заполнители:
```PostgreSQL
CALL get_student_info(1, NULL, NULL);
```

Результатом вызова будут значения выходных параметров:

|student_name|student_age|
|---|--:|
|Nikolaj Sokolov|24|

В PostgreSQL процедура с `OUT`-параметрами может возвращать данные вызывающему коду, хотя сама процедура не имеет возвращаемого значения через `RETURNS`.

---
# Входные и выходные параметры `INOUT`

`INOUT` параметры одновременно принимают значение на вход и возвращают изменённое значение.

Создадим процедуру для расчёта скидки:
```PostgreSQL
CREATE OR REPLACE PROCEDURE calculate_discount(
    INOUT price NUMERIC(10, 2),
    IN discount_percent INT
)
LANGUAGE plpgsql
AS $$
BEGIN
    price := price - (price * discount_percent / 100);
END;
$$;
```
Вызов процедуры:
```PostgreSQL
CALL calculate_discount(1000.00, 15);
```

Результат:

|price|
|--:|
|850.00|

`INOUT` параметр передаёт исходное значение в процедуру, а после выполнения содержит изменённое значение.

---
# Ключевые различия типов параметров

|Тип параметра|Направление|Использование|
|---|---|---|
|`IN`|Входящий|Передача данных в процедуру|
|`OUT`|Исходящий|Возврат результата|
|`INOUT`|Двунаправленный|Передача и изменение значения|

> ⚠️ **Важно:** при вызове процедуры через обычный SQL `OUT`-параметрам можно передать `NULL`. При вызове процедуры из другой PL/pgSQL-функции или процедуры для `OUT`/`INOUT` используются переменные, которые получат результат.

# Управление хранимыми процедурами

## Просмотр существующих процедур

В PostgreSQL информацию о процедурах можно получить через `information_schema.routines`:
```PostgreSQL
SELECT
    routine_name,
    routine_type
FROM information_schema.routines
WHERE routine_type = 'PROCEDURE'
  AND routine_schema = 'public';
```

## Удаление процедуры

```PostgreSQL
DROP PROCEDURE IF EXISTS add_student(VARCHAR, VARCHAR, DATE);
```

При удалении процедуры PostgreSQL учитывает её аргументы. Типы входных параметров используются для определения конкретной процедуры.

## Изменение процедуры

В PostgreSQL для изменения существующей процедуры можно использовать `CREATE OR REPLACE PROCEDURE`:
```PostgreSQL
CREATE OR REPLACE PROCEDURE add_student(
    student_first_name VARCHAR(50),
    student_last_name VARCHAR(50),
    student_birthday DATE
)
LANGUAGE plpgsql
AS $$
BEGIN
    INSERT INTO Student (first_name, last_name, birthday)
    VALUES (
        student_first_name,
        student_last_name,
        student_birthday
    );
END;
$$;
```

`CREATE OR REPLACE PROCEDURE` позволяет заменить реализацию существующей процедуры. При этом изменить её имя или типы аргументов с помощью этой команды нельзя — в таком случае будет создана отдельная процедура.

---
# Главное

**Хранимые процедуры** позволяют выносить последовательность действий и сложную бизнес-логику непосредственно в базу данных.

Они могут:
- принимать входные параметры `IN`;
- передавать значения через `OUT`;
- принимать и изменять значения через `INOUT`;
- выполнять `INSERT`, `UPDATE`, `DELETE` и другие SQL-команды;
- изменять данные в нескольких таблицах;
- содержать сложную логику;
- вызываться с помощью `CALL`.
