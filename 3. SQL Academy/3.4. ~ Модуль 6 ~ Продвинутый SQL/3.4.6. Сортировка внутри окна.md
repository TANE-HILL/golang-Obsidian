# Сортировка внутри окна

Сортировка внутри [[3.4.4. Оконные функции SQL|оконных функций]] позволяет упорядочивать данные внутри определённой группы или окна. Это используется при работе с временными рядами и при расчёте накопительных значений.

---
# Пример использования

Предположим, необходимо определить, как менялась общая сумма расходов на аренду для каждого пользователя со временем.

Сначала разделим данные на партиции по каждому пользователю и рассчитаем общую сумму:
```PostgreSQL
SELECT user_id,
       start_date,
       total AS reservation_price,
       SUM(total) OVER (
           PARTITION BY user_id
       ) AS total_expenses
FROM Reservations;
```
`PARTITION BY user_id` создаёт отдельную партицию для каждого пользователя.

В результате `total_expenses` содержит **итоговую сумму всех расходов пользователя**. Но такой запрос не показывает, как сумма изменялась со временем.

---
# `ORDER BY` внутри окна

Чтобы получить накопительную сумму, добавим сортировку по дате начала бронирования:
```PostgreSQL
SELECT user_id,
       start_date,
       total AS reservation_price,
       SUM(total) OVER (
           PARTITION BY user_id
           ORDER BY start_date
       ) AS cumulative_total
FROM Reservations;
```

Теперь для каждого пользователя сумма рассчитывается **последовательно по дате**.

Например, если расходы пользователя составили:

|`start_date`|`total`|`cumulative_total`|
|---|--:|--:|
|2024-01-01|100|100|
|2024-02-01|200|300|
|2024-03-01|150|450|

То есть:

```text
100
100 + 200 = 300
100 + 200 + 150 = 450
```

Таким образом, `ORDER BY start_date` превращает итоговую сумму в **накопительную**.

---
# Сортировка без явного указания рамки окна

Полный синтаксис оконной функции:
```PostgreSQL
SELECT <оконная_функция>(<поле_таблицы>)
OVER (
    [PARTITION BY <столбцы_для_разделения>]
    [ORDER BY <столбцы_для_сортировки>]
    [ROWS | RANGE <определение_диапазона_строк>]
);
```

`ROWS` и `RANGE` определяют **рамку окна** — набор строк, которые участвуют в вычислении для текущей строки.

Если используется `ORDER BY`, но рамка окна явно не указана, PostgreSQL по умолчанию использует:
```text
RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
```

Это означает:
- окно начинается с первой строки партиции;
- окно заканчивается текущей строкой;
- также учитываются строки с теми же значениями полей сортировки, что и у текущей строки.

Например:
```PostgreSQL
SUM(total) OVER (
    PARTITION BY user_id
    ORDER BY start_date
)
```
эквивалентно:
```PostgreSQL
SUM(total) OVER (
    PARTITION BY user_id
    ORDER BY start_date
    RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
)
```
> ⚠️ **Важно:** если две или более строки имеют одинаковое значение `start_date`, `RANGE` включает их в одну рамку. Для более точного управления строками используются `ROWS` и `RANGE`.

---
# Главное

- `PARTITION BY` разделяет строки на независимые группы.
- `ORDER BY` задаёт порядок строк внутри партиции.
- `SUM(...) OVER (PARTITION BY ...)` рассчитывает итоговое значение для каждой партиции.
- `SUM(...) OVER (PARTITION BY ... ORDER BY ...)` позволяет получить **накопительное значение**.
- При `ORDER BY` без явного указания рамки используется `RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW`.
- `ROWS` и `RANGE` позволяют явно задавать рамку окна.
