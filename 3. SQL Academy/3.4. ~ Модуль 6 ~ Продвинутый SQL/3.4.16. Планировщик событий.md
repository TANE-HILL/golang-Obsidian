# Планировщик событий

В реальных приложениях часто возникает необходимость выполнять определённые действия автоматически и по расписанию: очищать старые записи, обновлять статистику, формировать отчёты.

Для таких задач в PostgreSQL используют расширение **`pg_cron`**. Оно позволяет создавать запланированные задачи с помощью синтаксиса **`cron`**, аналогичного планировщику задач в Unix-системах.

---

# Когда пригодится

С помощью `pg_cron` можно автоматизировать:
- Очистку данных — удаление устаревших записей логов или временных данных.
- Обновление статистики — пересчёт агрегированных данных для аналитики.
- Генерацию отчётов — автоматическое формирование периодических отчётов.
- Обслуживание данных — перенос записей в архивные таблицы и другие регламентные операции.

---
# Как включить планировщик

Сначала `pg_cron` необходимо установить на сервер, добавить в `shared_preload_libraries` и перезапустить PostgreSQL.

После этого расширение создаётся в [[3.0.0. Что такое БД и СУБД|базе данных]]:
```PostgreSQL
CREATE EXTENSION IF NOT EXISTS pg_cron;
```

> ⚠️ **Важно:** установку и создание расширения обычно выполняет администратор. Обычным пользователям можно разрешить создание задач с помощью `GRANT USAGE ON SCHEMA cron TO user_name;`. В облачных сервисах порядок включения `pg_cron` зависит от провайдера.

---
# Одноразовый запуск

В `pg_cron` нет отдельного типа расписания для однократного запуска. Для такой задачи можно создать временную задачу и удалить её после выполнения.

Например, задача запускается каждый день в 3:00, но после первого выполнения удаляет саму себя:
```PostgreSQL
SELECT cron.schedule(
    'cleanup_old_logs_once',
    '0 3 * * *',
    $command$
    DO $$
    BEGIN
        DELETE FROM logs
        WHERE created_at < NOW() - INTERVAL '30 days';

        PERFORM cron.unschedule('cleanup_old_logs_once');
    END;
    $$;
    $command$
);
```

Здесь:
- `cron.schedule()` — создаёт запланированную задачу.
- `'cleanup_old_logs_once'` — имя задачи.
- `'0 3 * * *'` — расписание, каждый день в 3:00.
- `DELETE FROM logs ...` — команда, которую необходимо выполнить.
- `cron.unschedule()` — удаляет задачу после выполнения.

Таким образом, несмотря на ежедневное расписание, задача фактически выполнится только один раз.

# Периодический запуск

Чаще всего задачи необходимо запускать периодически — каждый день, час или минуту.

Для создания такой задачи используется `cron.schedule()`:
```PostgreSQL
SELECT cron.schedule(
    'cleanup_old_logs',
    '0 3 * * *',
    'DELETE FROM logs WHERE created_at < NOW() - INTERVAL ''30 days'''
);
```
- Эта задача будет выполняться каждый день в 3:00 и удалять записи логов старше 30 дней.

Здесь:
- `cron.schedule()` — функция для создания запланированной задачи.
- `'cleanup_old_logs'` — имя задачи.
- `'0 3 * * *'` — расписание в формате `cron`.
- Последний параметр — SQL-команда, которую необходимо выполнить.

---
# Формат cron-расписания

Cron-выражение состоит из пяти полей:
```text
минута час день_месяца месяц день_недели
```

Примеры:

|Расписание|Значение|
|---|---|
|`*/5 * * * *`|Каждые 5 минут|
|`0 * * * *`|Каждый час|
|`0 0 * * *`|Каждый день в полночь|
|`0 0 * * 0`|Каждое воскресенье в полночь|
|`0 9 1 * *`|Первого числа каждого месяца в 9:00|

Например, задача для обновления статистики каждый час:
```PostgreSQL
SELECT cron.schedule(
    'update_statistics_hourly',
    '0 * * * *',
    $$
    UPDATE product_stats
    SET
        total_sales = (
            SELECT SUM(amount)
            FROM orders
            WHERE product_id = product_stats.product_id
        ),
        last_updated = NOW()
    $$
);
```

Эта задача будет запускать `UPDATE` каждый час в начале часа.

---
# Интервалы в секундах

В `pg_cron` 1.5 и новее можно использовать интервалы от 1 до 59 секунд.

Для этого вместо cron-выражения передаётся строка с интервалом:
```PostgreSQL
SELECT cron.schedule(
    'check_status',
    '30 seconds',
    'SELECT check_status();'
);
```
- Такая задача будет запускаться каждые 30 секунд.

> ⚠️ **Важно:** интервал в секундах задаётся отдельной строкой, а не шестым полем cron-выражения.

---
# Ограничение периода выполнения

В `pg_cron` нельзя непосредственно указать дату автоматического завершения задачи.

Например, задачу ежедневной очистки логов создаём следующим образом:
```PostgreSQL
SELECT cron.schedule(
    'temporary_log_cleanup',
    '0 0 * * *',
    $$DELETE FROM logs
      WHERE created_at < NOW() - INTERVAL '30 days'$$
);
```
Чтобы задача остановилась автоматически, можно создать отдельную служебную задачу, которая через определённый период удалит основную задачу:
```PostgreSQL
DO $$
BEGIN
    PERFORM cron.unschedule('temporary_log_cleanup');
    PERFORM cron.unschedule('stop_temporary_log_cleanup');
END;
$$;
```
- Первый вызов удаляет задачу очистки, второй — саму служебную задачу.

---
# Просмотр расписания

Чтобы увидеть созданные задачи:
```PostgreSQL
SELECT *
FROM cron.job;
```

Обычный пользователь видит собственные задачи. Суперпользователь и роль с атрибутом `BYPASSRLS` могут видеть задачи других пользователей.

Для просмотра истории выполнения задач:
```PostgreSQL
SELECT *
FROM cron.job_run_details
ORDER BY start_time DESC
LIMIT 10;
```
- Таблица `cron.job_run_details` содержит информацию о запусках запланированных задач.

# Управление расписанием

## Удаление запланированной задачи

Удалить задачу можно по её имени:
```PostgreSQL
SELECT cron.unschedule('cleanup_old_logs');
```
Или по её ID:
```PostgreSQL
SELECT cron.unschedule(42);
```
- Здесь `42` — `jobid` задачи из таблицы `cron.job`.

## Изменение задачи

Расписание существующей задачи можно изменить с помощью `cron.alter_job()`:
```PostgreSQL
SELECT cron.alter_job(
    42,
    schedule := '0 */2 * * *'
);
```
Здесь `42` — `jobid` задачи из таблицы `cron.job`.

Новое расписание будет запускать задачу каждые 2 часа.

---
# Важные моменты при работе с pg_cron

1. **Права доступа:** `pg_cron` обычно устанавливается администратором. Обычным пользователям можно выдать `USAGE` на схему `cron`. Задача выполняется с правами пользователя, который её создал.
2. **Временная зона:** cron-выражения используют настройку `cron.timezone`. По умолчанию она равна `GMT`.
Текущее значение можно проверить:
```PostgreSQL
SHOW cron.timezone;
```
3. **Интервалы:** `pg_cron 1.5` и новее поддерживает интервалы от `1` до `59` секунд.
4. **Параллельные запуски:** `pg_cron` не запускает одновременно несколько экземпляров одной задачи. Если наступил следующий срок, пока задача ещё выполняется, новый запуск будет поставлен в очередь.
5. **Логирование:** при включённой настройке `cron.log_run` сведения о запусках сохраняются в таблице `cron.job_run_details`.

---

# Главное

**`pg_cron`** позволяет автоматически выполнять SQL-команды по расписанию непосредственно в PostgreSQL.

Основные функции:
- `cron.schedule()` — создание запланированной задачи.
- `cron.unschedule()` — удаление задачи.
- `cron.alter_job()` — изменение существующей задачи.
- `cron.job` — информация о запланированных задачах.
- `cron.job_run_details` — история выполнения задач.

Типичные задачи для `pg_cron`:
- удаление устаревших данных;
- обновление статистики;
- создание отчётов;
- архивирование данных;
- регулярное обслуживание базы данных.
