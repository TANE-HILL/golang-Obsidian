[[3.4.4. Оконные функции SQL|В прошлой статье]] мы кратко уже упоминали, что такое партиции и как их использовать в оконных функциях.

# Партиции в оконных функциях

Партиции — подмножества строк, выделенные для оконной функции на основе одного или нескольких столбцов таблицы. Они позволяют выполнять агрегацию или ранжирование отдельно внутри каждой группы.

---
# Применение партиций в SQL

Для использования партиции вместе с оконной функцией применяется `PARTITION BY`:
```PostgreSQL
SELECT <оконная_функция>(<поле_таблицы>)
OVER (
    PARTITION BY <столбцы_для_разделения>
);
```
- `PARTITION BY` разделяет строки на отдельные партиции, после чего оконная функция выполняется независимо внутри каждой из них.

---
# Пример использования

Рассмотрим таблицу `Rooms` с полями `home_type` и `price`.
```PostgreSQL
SELECT home_type,
       price,
       AVG(price) OVER (
           PARTITION BY home_type
       ) AS avg_price
FROM Rooms;
```

Здесь:
- `PARTITION BY home_type` делит записи на партиции по уникальным значениям `home_type`;
- `AVG(price)` вычисляет среднюю цену внутри каждой партиции;
- `avg_price` содержит среднюю цену для категории жилья текущей строки.

Например, для всех записей с `home_type = 'Private room'` в `avg_price` будет указано среднее значение `price` только для этой категории.

В отличие от `GROUP BY`, оконная функция **не объединяет строки** — исходные записи сохраняются, а результат вычисления добавляется в отдельный столбец.

---
# Партиции по нескольким колонкам

Партиционирование можно выполнять сразу по нескольким столбцам. В этом случае партиция определяется **уникальной комбинацией** значений этих столбцов.

Например, разделим жильё одновременно по категории `home_type` и наличию телевизора `has_tv`:
```PostgreSQL
SELECT home_type,
       has_tv,
       price,
       AVG(price) OVER (
           PARTITION BY home_type, has_tv
       ) AS avg_price
FROM Rooms;
```
Здесь `PARTITION BY home_type, has_tv` создаёт отдельную партицию для каждой комбинации значений `home_type` и `has_tv`.

Например:

|`home_type`|`has_tv`|Партиция|
|---|--:|---|
|`Private room`|0|`Private room + 0`|
|`Private room`|1|`Private room + 1`|
|`Entire home/apt`|0|`Entire home/apt + 0`|
|`Entire home/apt`|1|`Entire home/apt + 1`|

`AVG(price)` в каждой строке рассчитывается только по соответствующей партиции.

---
# Главное

- `PARTITION BY` разделяет строки на группы для оконной функции.
- Оконная функция выполняется отдельно внутри каждой партиции.
- Партицию можно создавать по одному или нескольким столбцам.
- При нескольких столбцах партиция определяется их комбинацией.
- В отличие от `GROUP BY`, партиционирование не объединяет строки — все исходные строки сохраняются.

---
# Практика

<u>Задание 1:</u>
Из таблицы **`Rooms`** вывести поля **`home_type`** и **`price`**, а также добавить колонку **`min_price_by_type`**, в которой необходимо вывести минимальную стоимость жилья для текущего типа жилья *(**`home_type`**)*. Для вычисления минимальной стоимости нужно использовать оконную функцию **`MIN`**.
<u>Решение:</u>
```PostgreSQL
SELECT home_type, price,
    MIN(price) OVER(PARTITION BY home_type)
    AS min_price_by_type
FROM Rooms
```

<u>Задание 2:</u>  
Из таблицы **`Rooms`** выведите поля **`id`**, **`home_type`**, **`has_tv`**, **`price`** и колонку **`avg_price_by_segment`** со средней ценой объявлений с тем же типом жилья и тем же значением **`has_tv`**. Округлите результат до двух знаков после запятой.
<u>Решение:</u>
```PostgreSQL
SELECT id, home_type, has_tv, price,
    ROUND(AVG(price) OVER(PARTITION BY home_type, has_tv), 2)
    AS avg_price_by_segment
FROM Rooms
```
