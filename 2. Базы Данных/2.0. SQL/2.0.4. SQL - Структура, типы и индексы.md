# Структура базы данных, типы и индексы

До этого мы работали с уже готовыми таблицами — [[2.0.1. Основы SQL - SELECT, FROM, GROUP BY, ORDER BY|извлекали, связывали]] и [[2.0.3. INSERT, UPDATE, DELETE - манипулирование данными|обновляли]] данные.

Но в реальных проектах ты не просто *«читаешь»* базу, а **создаёшь её структуру с нуля**: определяешь, какие таблицы нужны, какие у них поля и связи между ними.

---
# Что такое таблица

<u>Таблица</u> — это **основа любой базы данных**.

В ней хранятся строки *(данные)* и столбцы *(поля)*.

*Например:*

|id|name|email|age|
|---|---|---|---|
|1|Анна|[anna@mail.ru](mailto:anna@mail.ru)|25|
|2|Иван|[ivan@gmail.com](mailto:ivan@gmail.com)|30|

Создать таблицу можно прямо в SQL:
```PostgreSQL
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    email TEXT UNIQUE,
    age INT
);
```
- `PRIMARY KEY` — уникальный идентификатор строки;
- `NOT NULL` — поле обязательно для заполнения;
- `UNIQUE` — значение не должно повторяться.

---
# Типы данных

Каждое поле в таблице должно иметь тип данных, чтобы база знала, как с ним работать.

|Тип|Пример|Где используется|
|---|---|---|
|`INT`|`42`|числа, ID|
|`TEXT`, `VARCHAR`|`'Анна'`|строки|
|`BOOLEAN`|`true / false`|логические флаги|
|`DATE`, `TIMESTAMP`|`2025-10-23`|даты и время|

Это важно для надёжности: SQL не позволит вставить строку туда, где должно быть число.

---
# Ограничения (Constraints)

Ограничения защищают базу от ошибок.
Они гарантируют, что данные будут **целостными и логичными**.

|Ограничение|Что делает|
|---|---|
|`PRIMARY KEY`|Уникальный идентификатор|
|`NOT NULL`|Поле не может быть пустым|
|`UNIQUE`|Все значения должны быть разными|
|`FOREIGN KEY`|Связывает таблицы между собой|
|`CHECK`|Проверяет условие (например, возраст > 0)|

---
# Что такое индекс

Когда таблица становится большой, поиск в ней замедляется.
Чтобы база не *«листала»* все строки подряд, используются **индексы**.

Индекс — это как оглавление в книге: он указывает, где лежит нужная запись.
```PostgreSQL
CREATE INDEX idx_users_email ON users(email);
```

Теперь поиск по `email` будет выполняться быстрее:
```sql
WHERE email = 'ivan@gmail.com'
```
