# Зачем нужны базы данных

В программе без БД все данные хранятся **в оперативной памяти**, например:
```go
type Task struct {
	ID   int
	Text string
	Done bool
}

var tasks = []Task{
	{ID: 1, Text: "Купить хлеб", Done: false},
	{ID: 2, Text: "Позвонить маме", Done: true},
}
```

<u>Проблема:</u>
Если **перезапустить программу**, слайс очистится, и все задачи исчезнут.

Чтобы данные **не пропадали**, их нужно хранить **постоянно** — в надёжном месте, доступном даже после перезапуска программы, обновления или сбоя [[1.6.1. HTTP-сервер|сервера]].

Это место и есть **база данных (БД)**.

# Что такое база данных

**База данных** — это система для **хранения и управления информацией**.

**Она позволяет:**
- сохранять данные надолго;
- быстро искать, фильтровать, сортировать;
- связывать разные типы данных между собой;
- защищать информацию от потери.

Можно представить базу данных как **цифровой архив или Excel**, где каждая таблица — это лист с данными, а каждая строка — отдельная запись.

---
# Виды баз данных

**Все базы данных в мире делятся на два больших класса**:
- <font color="#ff0000">SQL</font> *(Structured Query Language)*
	Классические, структурированные БД: таблицы, связи, строгие типы;
	Примеры: PostgreSQL, MySQL, SQLite.
- <font color="#ff0000">NoSQL</font> *(Not Only SQL)*
	Современные, более гибкие БД: документы, ключи, графы, колонки;
	Примеры: MongoDB, Redis, Neo4j, ClickHouse.

## ~ <font color="#ff0000">SQL</font> ~ базы данных

**SQL-базы** используют **строгую структуру таблиц** и связи между ними.
Они называются **реляционными** (от английского _relation_ — “связь”).

Для работы с ними используется язык **SQL *(Structured Query Language)*** — на нём мы формулируем запросы: “добавить запись”, “получить всех пользователей”, “посчитать заказы”.

Такие базы идеально подходят для большинства бизнес-приложений — где важна точность, связи между данными и надёжность.

## ~ <font color="#ff0000">NoSQL</font> ~ базы данных

**NoSQL-базы** появились **позже**, чтобы решать другие задачи: работать с **гибкими структурами данных**, большими объёмами и высокой скоростью.

Здесь нет жёстких таблиц и схем — данные могут храниться как документы *(JSON)*, в виде пар “ключ → значение” или даже как графы связей.

Они не заменяют SQL, а **дополняют**: часто в одном проекте используют и PostgreSQL, и Redis, и Elasticsearch — каждая база решает свою задачу.

# Типы баз данных

## 1. <font color="#f79646">Реляционные</font> базы данных

#### **Что это**
Это **самый распространённый** тип баз данных — подходит примерно для 80–90% задач. Самые известные примеры - **PostgreSql**, **MySQL**, **Oracle**.
Данные хранятся в **таблицах**, где каждая строка — это запись, а каждый столбец — поле (атрибут).
Таблицы могут быть **связаны между собой** — например, города проживания связаны с пользователями по `CityId`.

![[Pasted image 20260908012054.png|313]]

#### **Особенности**
**Строгая структура** — каждая таблица имеет фиксированные поля и типы данных. Поле `user_id INT` не примет строку или дату.
**Связи между таблицами** — поддержка отношений “один ко многим” и “многие ко многим”.
**Транзакции** — можно безопасно обновить несколько записей сразу.

Используется язык **SQL** для запросов и работы с данными.

#### **Пример**
В Яндекс.Такси таблица `orders` хранит заказы: `order_id`, `user_id`, `driver_id`, `status`. Таблица `users` связана с `orders` через поле `user_id`.

#### **Когда использовать**
Когда важна точность данных, связи между таблицами и надёжность (например, финансы, заказы, пользователи).

#### **Аналогия**
Реляционная БД — это аккуратный шкаф с ящиками, где всё разложено по полочкам и легко найти нужное через связи.

## 2. <font color="#f79646">Документо-ориентированные</font> базы данных

#### **Что это**
Данные вместо таблиц данные хранятся в виде **документов** *(например, JSON)*.
Каждый документ описывает независимую сущность — как объект в [[1.1.0. Go Basics|Go]] или структуру в [[1.6.0.1. ~ JSON ~|JSON]].

Самый известный пример — **MongoDB**.
![[Pasted image 20260908012345.png|235]]

#### **Особенности**
**Гибкая структура** — у разных документов могут быть разные поля.
У одного есть `email`, у другого — нет, и это не ошибка.
**Нет строгих типов** — можно хранить строку, число или массив в одном поле.
**Нет SQL** — используется собственный API для запросов.
Связи между документами возможны, но используются редко (дорого по производительности).

#### **Пример**
Профиль пользователя в Яндекс.Такси:
```json
{
	"user_id": "123",
	"name": "Анна",
	"interests": ["спорт", "путешествия"]
}
```

#### **Когда использовать**
Когда структура данных часто меняется или записи независимы (анкеты, профили, резюме).

#### **Аналогия**
Документо-ориентированная БД — это папка с файлами, где каждый файл самодостаточен, но связи между ними минимальны.

## 3. <font color="#f79646">Графовые</font> базы данных

#### **Что это**
Графовые БД хранят данные в виде **графа**: вершины — это объекты, рёбра — связи между ними.
Пример базы — **Neo4j**.

![[Pasted image 20260908012551.png|457]]

#### **Особенности**
Вершины — сущности (например, люди, города).
Рёбра — отношения (“дружит с”, “живет в”).
Очень быстры для поиска цепочек связей.

#### **Пример**
Социальная сеть: “Я дружу с Петей”, “Петя живёт в Москве”.
Графовая база мгновенно найдёт “всех друзей, живущих в Москве”.

#### **Когда использовать**
**Для задач с большим количеством связей** — соцсети, маршруты, рекомендации.

#### **Аналогия**
Графовая БД — как карта метро: станции (вершины) связаны линиями (рёбрами), и можно быстро найти путь.

## 5. <font color="#f79646">Key-Value</font> базы данных

#### **Что это**
Самый простой тип БД — всё хранится в виде пар *“ключ → значение”*.
Примеры: **Redis**, **Memcached**, **Tarantool**, **etcd**.

![[Pasted image 20260908012723.png|351]]

#### **Особенности**
Очень быстрая работа.
Часто используется как **кэш**, чтобы ускорить доступ к часто используемым данным.
Не поддерживает связи и сложные запросы.

#### **Пример**
В Яндекс.Такси ключ `driver:456:status` может хранить значение `available`.
Redis используется для кэша или временного хранения сессий.

#### **Когда использовать**
Для хранения быстрых данных: кэш, настройки, токены, конфигурации.

#### **Аналогия**
Key-Value база — как записная книжка, где каждому имени (ключу) соответствует номер телефона (значение).

## 6. <font color="#f79646">Колонночные</font> базы данных

#### **Что это**
Данные хранятся не построчно, а **поколоночно**. Это ускоряет аналитические запросы и экономит место.
Пример: **ClickHouse**.

![[Pasted image 20260908012907.png|433]]

#### **Особенности**
Данные по каждой колонке хранятся рядом — удобно для выборки по конкретным полям. Отлично подходит для аналитики и статистики, но не для транзакций.

#### **Пример**
ClickHouse хранит поездки в Яндекс.Такси: `user_id`, `ride_cost`, `ride_date`.
Можно быстро посчитать *“среднюю стоимость поездки за месяц”*.

#### **Когда использовать**
Для аналитики, логов, статистики.

#### **Аналогия**
Колонночная БД — как полки с книгами по темам: берёшь только нужные книги с полки, не перелистывая всё подряд.

## 7. <font color="#f79646">Time-Series</font> базы данных

#### **Что это**
Специализированы для хранения данных, меняющихся во времени *(временные ряды)*. Примеры: **Prometheus**, **Graphite**, **VictoriaMetrics**.

![[Pasted image 20260908013040.png]]

#### **Особенности**
Оптимизированы для метрик: температура, загрузка CPU, скорость запросов.
Хранят пары *“время → значение”*.

#### **Пример**
**Prometheus** хранит метрику `requests_per_second` с метками времени.

#### **Когда использовать**
Для мониторинга, анализа метрик, IoT-устройств.

**Аналогия**
Time-Series база — как дневник погоды, где каждая запись привязана к дате.

# Почему <font color="#ff0000">PostgreSQL</font> ?

Это мощная, надёжная и бесплатная система, которую используют повсюду — от стартапов до крупных компаний.

#### Преимущества PostgreSQL:
- открытый исходный код и бесплатность;
- поддержка всех SQL-стандартов;
- транзакции (гарантия целостности данных);
- JSON, индексы, связи, миграции;
- работает на Windows, macOS, Linux;
- идеальная совместимость с Go.
