# Зачем нужны миграции

Когда проект растёт, появляются **новые таблицы**, **изменяются поля**, **добавляются связи**.

**Можно каждый раз выполнять SQL вручную, но быстро возникает хаос:**
- трудно понять, какая версия схемы актуальна;
- невозможно “откатиться” на предыдущую структуру;
- сложно работать в команде — у всех разная база.

Чтобы решить эту проблему, придумали **миграции** — механизм версионирования структуры БД.

---
# Что такое **миграции**

**Миграция** — это файл, который описывает одно изменение в структуре [[2.0.0. Базы данных и их виды|базы данных]]

**Например:**
- создать таблицу `transactions`,
- добавить колонку `note`,
- удалить таблицу `users`.

Каждая миграция — как “коммит” для базы:
- её можно применить (`up`) или откатить (`down`).

---
## Пример

Вот так выглядит миграция:
```sql
-- +goose Up
CREATE TABLE users (
    id SERIAL PRIMARY KEY,
    name TEXT NOT NULL
);

-- +goose Down
DROP TABLE users;
```
- `- +goose Up` — код, который выполняется при применении миграции (`migrate up`);
- `- +goose Down` — код, который выполняется при откате (`migrate down`).

---
## Зачем они нам в GoFinance

До этого ты создавал таблицы вручную (выполнял SQL в `psql`).
Теперь мы сделаем это **автоматически через Go**.

Больше не нужно писать:
```bash
docker exec -it gofinance-db psql -U postgres -d gofinance
```
и вручную вставлять `CREATE TABLE`.

Теперь всё будет одной командой:
```bash
go run cmd/migrate/main.go up
```

---
## Какой инструмент будем использовать

В [[1.1.0. Go Basics|Go]]-сообществе популярны разные утилиты для миграций:

| Инструмент     | Язык | Особенности                                              |
| -------------- | ---- | -------------------------------------------------------- |
| <u>migrate</u> | CLI  | простой и надёжный, но требует бинарник                  |
| <u>goose</u>   | Go   | можно вызывать прямо из кода, легко интегрируется с sqlx |
| <u>atlas</u>   | Go   | мощный, но сложный для новичков                          |

В проекте **GoFinance** мы используем **goose** — он идеально подходит для учебного проекта и легко встраивается в код.

## Установка Goose

в консоли IDE выполни:
```bash
go install github.com/pressly/goose/v3/cmd/goose@latest
```

Проверь установку:
```bash
goose --version
```

---
## Как устроен workflow миграций

1. Миграции лежат в папке `migrations/`.
2. Каждая миграция имеет формат:
```
001_create_categories.sql
002_create_transactions.sql
```
3. Goose хранит в БД служебную таблицу `goose_db_version`, чтобы знать, какие миграции уже применены.
4. Команды:
```bash
goose up     # применить все новые миграции
goose down   # откатить последнюю
goose status # посмотреть, какие применены
```

## Настраиваем миграции в проекте

### Обновлённая структура проекта:
```
gofinance/
├── cmd/
│   ├── api/
│   │   └── main.go
│   └── migrate/
│       └── main.go          # новая точка входа для миграций
├── internal/
│   ├── db/
│   │   └── connect.go
│   └── models/
│       ├── category.go
│       └── transaction.go
└── migrations/
    ├── 001_create_categories.sql
    └── 002_create_transactions.sql
```

### 1. Подключение к базе

📄 `internal/db/connect.go`
_(оставляем без изменений)_
```go
package db

import (
    "github.com/jmoiron/sqlx"
    _ "github.com/lib/pq"
)

func MustConnect(dsn string) *sqlx.DB {
    db := sqlx.MustConnect("postgres", dsn)
    return db
}
```

### 2. Точка входа для миграций

📄 `cmd/migrate/main.go`
*Это **новый файл**, который отвечает только за миграции.*
```go
package main

import (
    "log"
    "os"

    "github.com/joho/godotenv"
    "github.com/pressly/goose/v3"
    _ "github.com/lib/pq"
)

func main() {
    // Загружаем переменные окружения (.env)
    _ = godotenv.Load()

    // Получаем строку подключения
    dsn := os.Getenv("DATABASE_URL")

    // Подключаемся к PostgreSQL
    db, err := goose.OpenDBWithDriver("postgres", dsn)
    if err != nil {
        log.Fatalf("Ошибка подключения к БД: %v", err)
    }
    defer db.Close()

    // Указываем папку, где лежат миграции
    dir := "migrations"

    // Читаем команду (up, down, status, redo и т.д.)
    if len(os.Args) < 2 {
        log.Fatalf("Укажи команду: up | down | status | redo")
    }
    cmd := os.Args[1]

    // Запускаем нужную команду Goose
    if err := goose.Run(cmd, db, dir); err != nil {
        log.Fatalf("Ошибка при выполнении миграции: %v", err)
    }

    log.Println("✅ Команда успешно выполнена:", cmd)
}
```

### 3. Адаптируем первую миграцию (категории)

📄 `migrations/001_create_categories.sql`

***Было (вручную):***
```sql
CREATE TABLE IF NOT EXISTS categories (
    id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    type TEXT NOT NULL CHECK (type IN ('income', 'expense')),
    created_at TIMESTAMP DEFAULT NOW()
);
```

***Стало (настоящая миграция Goose):***
```sql
-- +goose Up
CREATE TABLE IF NOT EXISTS categories (
    id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    type TEXT NOT NULL CHECK (type IN ('income', 'expense')),
    created_at TIMESTAMP DEFAULT NOW()
);

-- +goose Down
DROP TABLE IF EXISTS categories;
```

Теперь Goose понимает:
- что нужно сделать при `up` (создать таблицу),
- и как откатить при `down` (удалить таблицу).

### 4. Создаём новую миграцию

📄 `migrations/002_create_transactions.sql`:
```sql
-- +goose Up
CREATE TABLE IF NOT EXISTS transactions (
    id SERIAL PRIMARY KEY,
    category_id INT REFERENCES categories(id) ON DELETE CASCADE,
    amount NUMERIC(10,2) NOT NULL,
    note TEXT,
    created_at TIMESTAMP DEFAULT NOW()
);

-- +goose Down
DROP TABLE IF EXISTS transactions;
```

---
### Применяем миграции

Теперь можно запустить миграции через Go:
```bash
go run ./cmd/migrate up
```

Goose выполнит **все новые файлы** в порядке номеров (`001`, `002`, …).

Пример вывода:
```
2025/10/25 12:03:44 OK   001_create_categories.sql
2025/10/25 12:03:44 OK   002_create_transactions.sql
✅ Команда успешно выполнена: up
```

### Проверяем статус

```bash
go run ./cmd/migrate status
```

Результат:
```
goose: status for migrations folder: migrations
   Applied At                  Migration
   ============================================
   2025-10-25 12:03:44         001_create_categories.sql
   2025-10-25 12:03:44         002_create_transactions.sql
```

### Откат миграции

Если нужно откатить последнюю миграцию:
```bash
go run ./cmd/migrate down
```
или применить заново последнюю:
```bash
go run ./cmd/migrate redo
```

### Что в итоге

Теперь у тебя:
- Миграции **автоматические и версионируемые**
- Таблицы создаются одной командой
- Можно откатывать изменения
- Всё хранится в Git и воспроизводимо у любого участника проекта
---
Следующий шаг — **транзакции**:
- научимся делать несколько SQL-операций “одним атомарным действием”, чтобы не потерять данные, даже если что-то пойдёт не так.

# Важно запомнить

| Термин                                 | Что это значит                              |
| -------------------------------------- | ------------------------------------------- |
| **Миграция**                           | файл с изменением структуры БД              |
| **Up**                                 | применить изменения                         |
| **Down**                               | отменить изменения                          |
| **Status**                             | показать, какие миграции применены          |
| **Version table (`goose_db_version`)** | таблица, где goose хранит “состояние” схемы |
