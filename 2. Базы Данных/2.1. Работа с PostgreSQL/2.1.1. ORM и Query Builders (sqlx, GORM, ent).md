# Зачем нам ORM и Query Builders

[[2.1.0. Подключение PostgreSQL|На прошлом уроке]] научились подключаться к базе данных и проверять соединение.
Но просто “подключиться” — мало. Нужно **рабаотать с таблицами и данными**:
- создавать, читать, обновлять, удалять - **CRUD**.

Можно писать *“сырые”* SQL-запросы:
```go
db.Exec("INSERT INTO categories (name, type) VALUES ($1, $2)", name, ctype)
```

Это рабочий способ, но в больших проектах он быстро превращается в хаос:
- сложно поддерживать код;
- легко допустить SQL-инъекцию;
- неудобно маппить строки из БД в структуры Go.

Для этого придумали **ORM (Object Relational Mapping)** и **Query Builders** — инструменты, которые упрощают взаимодействие с базой.

---
# Как можно работать с базой в [[1.1.0. Go Basics|Go]]

| Подход                                | Описание                                                                      | Пример                                                                        |
| ------------------------------------- | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| **1. Чистый SQL (database/sql)**      | Мы сами пишем SQL-запросы и выполняем их                                      | `db.Exec("INSERT INTO categories (name, type) VALUES ($1, $2)", name, ctype)` |
| **2. Query Builder (например, sqlx)** | SQL остаётся, но работать с ним удобнее, результат сразу маппится в структуры | `db.Select(&cats, "SELECT * FROM categories")`                                |
| **3. ORM (например, GORM)**           | Работает с таблицами как с объектами Go. SQL генерируется автоматически       | `db.Create(&Category{Name: "Еда", Type: "expense"})`                          |

---
## Разберём термины

| **Инструмент**    | Что делает                                  | Пример                                             |
| ----------------- | ------------------------------------------- | -------------------------------------------------- |
| **SQL-запросы**   | Мы сами пишем `SELECT`, `INSERT` и т.д.     | `db.Query("SELECT * FROM users")`                  |
| **Query Builder** | Генерирует SQL через удобные функции        | `qb.Select("*").From("users").Where("id = ?", id)` |
| **ORM**           | Автоматически маппит таблицы в структуры Go | `db.Create(&user)`                                 |

# Подход 1. Чистый SQL (`database/sql`)

Это стандартный способ, который есть “из коробки” в [[1.1.0. Go Basics|Go]].

### Основные функции:

| Метод                                    | Для чего                                                                | Что возвращает                                     | Мини-пример                                                                       |
| ---------------------------------------- | ----------------------------------------------------------------------- | -------------------------------------------------- | --------------------------------------------------------------------------------- |
| **`Exec(query, args...)`**               | Выполнить запрос **без результата строк**: `INSERT`, `UPDATE`, `DELETE` | `sql.Result`(`RowsAffected()`, `LastInsertId()`* ) | `res, err := db.Exec("UPDATE categories SET name=$1 WHERE id=$2", "Продукты", 1)` |
| **`Query(query, args...)`**              | `SELECT`, который возвращает **несколько строк**                        | `*sql.Rows`                                        | `rows, err := db.Query("SELECT id,name FROM categories")`                         |
| **`QueryRow(query, args...)`**           | `SELECT` **одной строки** (ожидается максимум 1 запись)                 | `*sql.Row`                                         | `err := db.QueryRow("SELECT name FROM categories WHERE id=$1", 1).Scan(&name)`    |
| **`rows.Next()`**                        | Сдвинуть курсор к **следующей строке**                                  | `bool`                                             | `for rows.Next() { ... }`                                                         |
| **`rows.Scan(&dest...)`**                | Прочитать **текущую строку** в переменные                               | `error`                                            | `rows.Scan(&id, &name)`                                                           |
| **`row.Scan(&dest...)`**                 | Прочитать **одну запись** из `QueryRow`                                 | `error`                                            | `db.QueryRow("SELECT count(*) FROM categories").Scan(&n)`                         |
| **`rows.Close()`**                       | Освободить ресурсы результата                                           | `error`                                            | `defer rows.Close()`                                                              |
| **`Begin()` / `Commit()`/ `Rollback()`** | Транзакции                                                              | `*sql.Tx`                                          | `tx, _ := db.Begin(); _, err := tx.Exec(...); tx.Commit()`                        |

### Основные операции:
#### Добавить (<font color="#e36c09">Create</font>):
```go
db.Exec("INSERT INTO categories (name, type) VALUES ($1, $2)", "Еда", "expense")
```
#### Прочитать (<font color="#e36c09">Read</font>):
```go
rows, _ := db.Query("SELECT id, name, type FROM categories")
defer rows.Close()

for rows.Next() {
    var id int
    var name, ctype string
    rows.Scan(&id, &name, &ctype)
    fmt.Println(id, name, ctype)
}
```
Пояснение:
- `rows, _ := db.Query("SELECT id, name, type FROM categories")` — выполняем `SELECT`, получаем курсор `rows` (несколько строк).
    (_В реальном коде проверьте `err`!_)
- `defer rows.Close()` — гарантируем освобождение ресурсов результата, когда функция завершится.
- `for rows.Next() {` — идём по строкам результата, пока они есть.
- `var id int` — переменная под колонку `id`.
- `var name, ctype string` — переменные под колонки `name` и `type`.
- `rows.Scan(&id, &name, &ctype)` — читаем текущую строку в переменные (порядок — как в `SELECT`).
- `fmt.Println(id, name, ctype)` — выводим строку (для примера проверки).

#### Обновить (<font color="#e36c09">Update</font>):
```go
db.Exec("UPDATE categories SET name=$1 WHERE id=$2", "Продукты", 1)
```
#### Удалить (<font color="#e36c09">Delete</font>):
```go
db.Exec("DELETE FROM categories WHERE id=$1", 1)
```

### Что нужно знать
- Всё делаешь вручную: писать SQL, сканировать данные в переменные.
- Код быстро становится большим и повторяющимся.
- Хорошо, если хочешь **глубоко понимать, как работает SQL**.
- Плохо, если проект растёт — слишком много рутины.

# Подход 2. Query Builder (пример: **`sqlx`**)

`sqlx` — это не “автоматизация SQL”, а **удобная надстройка** над `database/sql`.

Она делает две важные вещи:
1. Позволяет **сразу сканировать данные в структуры** Go;
2. Даёт удобные функции (`Get`, `Select`, `NamedExec`).

---
### **Основные функции в `sqlx`**
*(методичка, их не нужно учить)*

|Метод|Для чего используется|Что возвращает|Мини-пример|Особенности / комментарии|
|---|---|---|---|---|
|**`db.Get(dest, query, args...)`**|Получить **одну строку** и записать её в структуру|`error`|`db.Get(&cat, "SELECT * FROM categories WHERE id=$1", 1)`|Сам вызывает `QueryRow` и `Scan`. Удобно для “одной записи”.|
|**`db.Select(dest, query, args...)`**|Получить **несколько строк** и записать их в срез структур|`error`|`db.Select(&cats, "SELECT * FROM categories")`|Автоматически перебирает все строки и сканирует их.|
|**`db.Exec(query, args...)`**|Выполнить запрос без результата (`INSERT`, `UPDATE`, `DELETE`)|`sql.Result`|`db.Exec("DELETE FROM categories WHERE id=$1", 2)`|Как в `database/sql`, но можно использовать именованные параметры.|
|**`db.NamedExec(query, arg)`**|Выполнить SQL-запрос с **именованными параметрами**|`sql.Result`|`db.NamedExec("INSERT INTO categories (name,type) VALUES (:name,:type)", cat)`|Подставляет поля структуры или map по имени.|
|**`db.NamedQuery(query, arg)`**|То же, но возвращает строки (`SELECT`)|`*sqlx.Rows`|`rows, _ := db.NamedQuery("SELECT * FROM cats WHERE type=:type", map[string]interface{}{"type":"income"})`|Потом читаешь `rows.StructScan(&cat)`.|
|**`rows.StructScan(&dest)`**|Сканировать одну строку результата в структуру|`error`|`for rows.Next() { rows.StructScan(&cat) }`|Поля сопоставляются по тегам `db:"..."`.|
|**`db.PrepareNamed(query)`**|Подготовить шаблон запроса с именами|`*sqlx.NamedStmt`|`stmt, _ := db.PrepareNamed("INSERT INTO categories (name,type) VALUES (:name,:type)")`|Удобно при многократных вставках.|
|**`db.Beginx()`**|Начать транзакцию (`sqlx.Tx`)|`*sqlx.Tx`|`tx := db.Beginx(); tx.Exec(...); tx.Commit()`|Аналог `Begin`, но с удобствами `sqlx`.|
|**`db.Rebind(query)`**|Преобразует `?` в `$1`, `$2`для PostgreSQL|`string`|`db.Rebind("INSERT INTO users VALUES(?)")`|Автоматически вызывается при `NamedExec`.|

---
## Основные операции в sqlx

### Добавить (Create)
```go
db.Exec("INSERT INTO categories (name, type) VALUES ($1, $2)", "Еда", "expense")
```
(почти как раньше — но можно и лучше 👇)

### Прочитать (Read)
```go
type Category struct {
    ID   int    `db:"id"`
    Name string `db:"name"`
    Type string `db:"type"`
}

var cats []Category
db.Select(&cats, "SELECT * FROM categories ORDER BY id")
```
> db.Select() сам пройдётся по строкам и заполнит срез структур cats.

### Обновить (Update)
```go
db.Exec("UPDATE categories SET name=$1 WHERE id=$2", "Продукты", 1)
```

### Удалить (Delete)
```go
db.Exec("DELETE FROM categories WHERE id=$1", 1)

```

---
## Дополнительные возможности **`sqlx`**

- `db.Get(&cat, "SELECT * FROM categories WHERE id=$1", 1)` — вернуть одну запись.
- `NamedExec` позволяет подставлять параметры по имени:
```go
db.NamedExec("INSERT INTO categories (name, type) VALUES (:name, :type)",
map[string]interface{}{"name": "Фриланс", "type": "income"})
```

---
## Плюсы и минусы **`sqlx`**

|Плюсы|Минусы|
|---|---|
|Простота, читаемость, контроль над SQL|Всё равно вручную пишешь SQL|
|Удобное сканирование в структуры|Нет “связей” между таблицами|
|Подходит для микросервисов и REST API|Нужно помнить синтаксис SQL|

# Подход 3. ORM (пример: **GORM**)

GORM — это “высокоуровневая” обёртка над SQL.
Ты **не пишешь SQL** напрямую — ORM сам превращает твои действия в запросы.

## Основные функции в GORM
*(методичка, не нужно их учить, просто подсматривай)*

|Метод|Для чего используется|Что возвращает|Мини-пример|Особенности / комментарии|
|---|---|---|---|---|
|**`db.Create(&obj)`**|Добавить новую запись|`*gorm.DB`|||
|(с ошибкой внутри)|`db.Create(&Category{Name: "Еда", Type: "expense"})`|Сам формирует `INSERT`. После выполнения `obj.ID` будет заполнен.|||
|**`db.Find(&dest)`**|Прочитать все записи|`*gorm.DB`|`var cats []Category; db.Find(&cats)`|Делает `SELECT * FROM table`. Можно добавлять фильтры (`Where`, `Limit`, `Order`).|
|**`db.First(&dest, id)`**|Получить запись по ID|`*gorm.DB`|`var cat Category; db.First(&cat, 1)`|Возвращает первую найденную. Если не найдено — ошибка `ErrRecordNotFound`.|
|**`db.Where(cond, args...).Find(&dest)`**|Фильтр с условием|`*gorm.DB`|`db.Where("type = ?", "income").Find(&cats)`|Генерирует `WHERE type='income'`.|
|**`db.Model(&obj).Update(column, value)`**|Обновить одно поле|`*gorm.DB`|`db.Model(&cat).Update("Name", "Продукты")`|Формирует `UPDATE table SET name='...' WHERE id=...`.|
|**`db.Model(&obj).Updates(map[string]interface{}{})`**|Обновить несколько полей|`*gorm.DB`|`db.Model(&cat).Updates(map[string]interface{}{"Name": "Продукты", "Type": "expense"})`|Можно передавать map или структуру.|
|**`db.Delete(&obj, id)`**|Удалить запись|`*gorm.DB`|`db.Delete(&Category{}, 2)`|Делает `DELETE FROM table WHERE id=2`.|
|**`db.AutoMigrate(&model{})`**|Создать/обновить таблицу под структуру|`error`|`db.AutoMigrate(&Category{})`|Сам создаёт таблицу и колонки. Не трогает существующие данные.|
|**`db.Transaction(func(tx *gorm.DB) error {...})`**|Выполнить несколько операций в транзакции|`error`|`db.Transaction(func(tx *gorm.DB) error { tx.Create(...); tx.Save(...); return nil })`|Если вернуть ошибку → `ROLLBACK`, иначе `COMMIT`.|
|**`db.Preload("Relation")`**|Подгрузить связанные данные|`*gorm.DB`|`db.Preload("Tasks").Find(&users)`|Работает с `has one`, `has many`, `belongs to`.|
|**`db.Raw(sql, args...).Scan(&dest)`**|Выполнить свой SQL и записать результат в структуру|`*gorm.DB`|`db.Raw("SELECT * FROM categories WHERE id=?", 1).Scan(&cat)`|Полезно, если нужно вручную писать SQL.|

## Основные операции в GORM

```go
import (
    "gorm.io/driver/postgres"
    "gorm.io/gorm"
)

type Category struct {
    ID   uint   `gorm:"primaryKey"`
    Name string
    Type string
}

// подключаемся
dsn := os.Getenv("DATABASE_URL")
db, _ := gorm.Open(postgres.Open(dsn), &gorm.Config{})

// создаём таблицу (если нет)
db.AutoMigrate(&Category{})
```

---
### Добавить (Create)
```go
db.Create(&Category{Name: "Еда", Type: "expense"})
```

### Прочитать (Read)
```go
var cats []Category
db.Find(&cats)
```

### Обновить (Update)
```go
db.Model(&Category{}).Where("id = ?", 1).Update("name", "Продукты")
```

### Удалить (Delete)
```go
db.Delete(&Category{}, 1)
```

---
## Что делает GORM
- `db.Create()` → генерирует SQL `INSERT INTO ...`
- `db.Find()` → генерирует `SELECT * FROM ...`
- `db.Update()` → `UPDATE ... SET ...`
- `db.Delete()` → `DELETE FROM ...`

Ты не видишь SQL, но ORM **делает всё то же самое под капотом**.

---

### Плюсы и минусы

| **Плюсы**                                           | **Минусы**                              |
| --------------------------------------------------- | --------------------------------------- |
| Очень быстро писать CRUD                            | Труднее контролировать SQL              |
| Поддерживает связи <br>*(`has many`, `belongs to`)* | Иногда генерирует неэффективные запросы |
| Есть миграции и автосоздание таблиц                 | Медленнее на старте, больше магии       |

## 1️⃣ Работа с `sqlx` — <u>удобный SQL в Go</u>

### Что такое `sqlx`

`sqlx` — это как `database/sql`, но **с удобными функциями**:
- позволяет напрямую маппить результаты в структуры;
- не требует вручную доставать значения из строк;
- проще работать с параметрами запроса.

---
### Пример: создаём таблицу категорий

📄 `internal/db/migrations.sql`
*(в реальном проекте — будет миграция, ее пройдем в следующем уроке)*
```sql
CREATE TABLE IF NOT EXISTS categories (
    id SERIAL PRIMARY KEY,
    name TEXT NOT NULL,
    type TEXT NOT NULL CHECK (type IN ('income', 'expense')),
    created_at TIMESTAMP DEFAULT NOW()
);
```

---
### Пример работы с таблицей

📄 `internal/db/categories.go`
```go
package db

import (
    "github.com/jmoiron/sqlx"
)

type Category struct {
    ID        int    `db:"id"`
    Name      string `db:"name"`
    Type      string `db:"type"`
    CreatedAt string `db:"created_at"`
}

func CreateCategory(db *sqlx.DB, name, ctype string) error {
    _, err := db.Exec(`
        INSERT INTO categories (name, type)
        VALUES ($1, $2)
    `, name, ctype)
    return err
}

func GetAllCategories(db *sqlx.DB) ([]Category, error) {
    var cats []Category
    err := db.Select(&cats, "SELECT * FROM categories ORDER BY id")
    return cats, err
}
```

---
### Разбор
- `db.Exec()` — выполняет команду без возвращаемых строк (`INSERT`, `UPDATE`, `DELETE`)
- `db.Select(&cats, "...")` — выполняет `SELECT` и сразу **заполняет срез структур**
- теги `db:"..."` указывают, из каких колонок брать данные

---
### Проверим в `main.go`

📄 `cmd/api/main.go`:
```go
package main

import (
    "fmt"
    "log"
    "os"

    "github.com/jmoiron/sqlx"
    _ "github.com/lib/pq"
    "github.com/joho/godotenv"
    "gofinance/internal/db"
)

func main() {
    godotenv.Load()
    connStr := os.Getenv("DATABASE_URL")

    dbase, err := sqlx.Connect("postgres", connStr)
    if err != nil {
        log.Fatal(err)
    }
    defer dbase.Close()

    fmt.Println("✅ Подключено к PostgreSQL")

    // Добавляем категории
    db.CreateCategory(dbase, "Еда", "expense")
    db.CreateCategory(dbase, "Фриланс", "income")

    cats, _ := db.GetAllCategories(dbase)
    fmt.Println("Категории в базе:")
    for _, c := range cats {
        fmt.Printf("- %s (%s)\n", c.Name, c.Type)
    }
}
```

---
### Результат
```
✅ Подключено к PostgreSQL
Категории в базе:
- Еда (expense)
- Фриланс (income)
```

## 2️⃣ <u>Работа с ORM</u> *(**GORM**)*

### Что делает GORM

GORM умеет:
- автоматически создавать таблицы;
- добавлять/обновлять/удалять записи без SQL-запросов;
- связывать таблицы через `struct`отношения (`has many`, `belongs to`).

---
### Пример подключения:
```go
package main

import (
    "fmt"
    "log"
    "os"

    "gorm.io/driver/postgres"
    "gorm.io/gorm"
)

type Category struct {
    ID   uint   `gorm:"primaryKey"`
    Name string
    Type string
}

func main() {
    dsn := os.Getenv("DATABASE_URL")
    db, err := gorm.Open(postgres.Open(dsn), &gorm.Config{})
    if err != nil {
        log.Fatal(err)
    }

    db.AutoMigrate(&Category{}) // создаёт таблицу, если её нет

    db.Create(&Category{Name: "Зарплата", Type: "income"})
    db.Create(&Category{Name: "Аренда", Type: "expense"})

    var cats []Category
    db.Find(&cats)

    fmt.Println("Категории:")
    for _, c := range cats {
        fmt.Printf("- %s (%s)\n", c.Name, c.Type)
    }
}
```
### Что происходит:
1. `gorm.Open()` — создаёт подключение.
2. `db.AutoMigrate()` — автоматически создаёт таблицу.
3. `db.Create()` — вставляет запись.
4. `db.Find()` — выбирает все записи.
5. Всё без SQL — ORM сам генерирует нужные запросы.

---
### Преимущества ORM
- Меньше кода
- Не нужно писать SQL
- Простые ассоциации между таблицами

Но!
❌ Меньше контроля над производительностью
❌ Нужно понимать, что делает ORM под капотом

## 4. Репозиторий категорий

`internal/db/category_repo.go`:
```go
package db // пакет для работы с базой данных (всё, что связано с PostgreSQL)

import (
    "context"                 // нужен для передачи контекста запроса (например, отмены)
    "gofinance/internal/models" // импортируем структуру Category, куда будем сохранять данные из БД
    "github.com/jmoiron/sqlx"   // библиотека sqlx — облегчает работу с SQL в Go
)

// CategoryRepo — структура-репозиторий.
// В ней хранится подключение к базе данных и методы для работы с таблицей categories.
type CategoryRepo struct {
    db *sqlx.DB // объект подключения к PostgreSQL
}

// NewCategoryRepo — "конструктор" репозитория.
// Принимает подключение (*sqlx.DB) и возвращает готовый репозиторий.
func NewCategoryRepo(db *sqlx.DB) *CategoryRepo {
    return &CategoryRepo{db: db}
}

// Create — метод для добавления новой категории в таблицу.
func (r *CategoryRepo) Create(ctx context.Context, name, ctype string) (models.Category, error) {
    var cat models.Category // переменная, в которую запишем результат (созданную категорию)

    // SQL-запрос для вставки данных.
    // $1 и $2 — это плейсхолдеры, вместо которых подставятся значения переменных name и ctype.
    // RETURNING говорит PostgreSQL вернуть указанные поля (id, name, type, created_at),
    // чтобы мы могли сразу получить созданную запись без отдельного SELECT.
    query := `
        INSERT INTO categories (name, type)
        VALUES ($1, $2)
        RETURNING id, name, type, created_at;
    `

    // Выполняем запрос к базе.
    // GetContext делает три вещи:
    // 1️⃣ Отправляет SQL-запрос.
    // 2️⃣ Подставляет значения name и ctype.
    // 3️⃣ Сканирует (чтёт) результат запроса в структуру cat.
    if err := r.db.GetContext(ctx, &cat, query, name, ctype); err != nil {
        // Если произошла ошибка (например, нет соединения с БД) — возвращаем пустую структуру и ошибку.
        return models.Category{}, err
    }

    // Если всё успешно — возвращаем заполненную структуру без ошибок.
    return cat, nil
}

// List — метод для получения списка всех категорий из базы данных.
func (r *CategoryRepo) List(ctx context.Context) ([]models.Category, error) {
    var cats []models.Category // создаём срез, куда сохраним все найденные категории

    // SQL-запрос для выборки всех записей из таблицы categories.
    // ORDER BY id — сортирует записи по возрастанию ID (по порядку добавления).
    err := r.db.SelectContext(ctx, &cats, `
        SELECT id, name, type, created_at
        FROM categories
        ORDER BY id;
    `)

    // Возвращаем срез категорий и ошибку (если она была).
    return cats, err
}
```

Здесь мы описываем **всю работу с таблицей `categories`**.
Теперь хендлеры не обращаются к SQL напрямую — они просто вызывают методы:
- `Create()` — добавляет категорию в базу и возвращает созданный объект;
- `List()` — получает все категории и маппит их в срез структур.

## 5. Хендлеры *(**HTTP-ручки**)*

`internal/handlers/categories.go`:
```go
package handlers // пакет для HTTP-обработчиков (ручек API)

import (
    "encoding/json"  // для чтения и записи JSON
    "net/http"       // стандартный пакет Go для работы с HTTP-запросами
    "strings"        // для работы со строками (например, TrimSpace)

    "github.com/jmoiron/sqlx" // библиотека sqlx — надстройка над database/sql
    "gofinance/internal/db"   // импортируем пакет db (репозиторий с SQL-логикой)
)

// CategoryHandlers — структура, которая объединяет все хендлеры,
// связанные с категориями. Внутри она хранит ссылку на репозиторий,
// через который идёт взаимодействие с базой данных.
type CategoryHandlers struct {
    repo *db.CategoryRepo // ссылка на слой работы с БД
}

// NewCategoryHandlers — "конструктор" хендлеров категорий.
// Он принимает подключение к БД (*sqlx.DB),
// создаёт репозиторий категорий и возвращает готовый объект CategoryHandlers.
// Это позволяет держать логику БД и логику HTTP раздельно.
func NewCategoryHandlers(dbase *sqlx.DB) *CategoryHandlers {
    return &CategoryHandlers{repo: db.NewCategoryRepo(dbase)}
}

// CreateCategory — обработчик POST /categories.
// Отвечает за добавление новой категории доходов/расходов.
func (h *CategoryHandlers) CreateCategory(w http.ResponseWriter, r *http.Request) {
    // Проверяем, что запрос пришёл с методом POST.
    // Если кто-то попробует GET или DELETE — вернём 405.
    if r.Method != http.MethodPost {
        http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
        return
    }

    // Объявляем временную структуру для приёма JSON из запроса.
    // Пример запроса:
    // {
    //   "name": "Еда",
    //   "type": "expense"
    // }
    var in struct {
        Name string `json:"name"`
        Type string `json:"type"`
    }

    // Декодируем (читаем) JSON из тела запроса и сохраняем в структуру in.
    // Если JSON некорректный (например, синтаксическая ошибка) — вернём 400.
    if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
        http.Error(w, "Invalid JSON", http.StatusBadRequest)
        return
    }

    // Очищаем пробелы в названии.
    in.Name = strings.TrimSpace(in.Name)

    // Проверяем данные перед записью:
    // - имя категории не может быть пустым,
    // - тип должен быть либо "income", либо "expense".
    if in.Name == "" || (in.Type != "income" && in.Type != "expense") {
        http.Error(w, "Name required, type must be income|expense", http.StatusBadRequest)
        return
    }

    // Вызываем метод Create() у репозитория,
    // передавая контекст запроса и данные категории.
    // Контекст нужен, чтобы запрос можно было отменить, если клиент отключился.
    cat, err := h.repo.Create(r.Context(), in.Name, in.Type)
    if err != nil {
        // Если произошла ошибка при работе с БД — возвращаем 500 (Internal Server Error).
        http.Error(w, "Database error: "+err.Error(), http.StatusInternalServerError)
        return
    }

    // Если всё успешно — отправляем ответ клиенту.
    // Указываем тип контента, чтобы клиент понял, что ответ в JSON.
    w.Header().Set("Content-Type", "application/json")

    // Устанавливаем код ответа 201 (Created) — значит, объект успешно создан.
    w.WriteHeader(http.StatusCreated)

    // Кодируем структуру cat в JSON и отправляем клиенту.
    json.NewEncoder(w).Encode(cat)
}

// ListCategories — обработчик GET /categories.
// Возвращает список всех категорий из базы данных.
func (h *CategoryHandlers) ListCategories(w http.ResponseWriter, r *http.Request) {
    // Проверяем, что запрос — с методом GET.
    if r.Method != http.MethodGet {
        http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
        return
    }

    // Получаем все категории из базы через репозиторий.
    // repo.List возвращает срез структур Category.
    cats, err := h.repo.List(r.Context())
    if err != nil {
        // Если при обращении к БД произошла ошибка — вернём 500.
        http.Error(w, "Database error: "+err.Error(), http.StatusInternalServerError)
        return
    }

    // Устанавливаем заголовок Content-Type, чтобы клиент понял, что это JSON.
    w.Header().Set("Content-Type", "application/json")

    // Преобразуем список категорий в JSON и отправляем клиенту.
    json.NewEncoder(w).Encode(cats)
}
```

Здесь мы описали две ручки:

| Метод  | Путь          | Что делает                       |
| ------ | ------------- | -------------------------------- |
| `POST` | `/categories` | создаёт новую категорию          |
| `GET`  | `/categories` | возвращает список всех категорий |

**Важно понимать:**
- хендлер **не знает SQL** — он просто вызывает методы репозитория;
- вся валидация *(`name`, `type`)* происходит **в хендлере**, до обращения к базе.

## 6. Точка входа

`cmd/api/main.go`:
```go
package main // пакет main — точка входа программы

import (
    "fmt"   // пакет для форматированного вывода текста (например, Printf)
    "log"   // для логирования ошибок и сообщений
    "net/http" // стандартный пакет Go для создания HTTP-сервера
    "os"    // работа с системными переменными окружения (.env, PATH и т.д.)

    "github.com/jmoiron/sqlx" // библиотека sqlx — упрощает работу с SQL в Go
    _ "github.com/lib/pq"     // драйвер PostgreSQL (импортируется только ради регистрации, поэтому с подчёркиванием)
    "github.com/joho/godotenv" // библиотека для загрузки переменных окружения из файла .env

    "gofinance/internal/db"       // пакет с логикой подключения к базе данных
    "gofinance/internal/handlers" // пакет с HTTP-обработчиками (ручками API)
)

func main() {
    // Загружаем файл .env, чтобы переменные окружения из него
    // стали доступны через os.Getenv().
    // Если файла .env нет (например, на продакшене) — программа не упадёт.
    _ = godotenv.Load()

    // Получаем из окружения строку подключения к PostgreSQL.
    // Пример значения: postgres://postgres:password@localhost:5432/gofinance?sslmode=disable
    dsn := os.Getenv("DATABASE_URL")

    // Подключаемся к базе данных с помощью sqlx.
    // Функция MustConnect создаёт соединение или завершает программу с ошибкой, если база недоступна.
    dbase := db.MustConnect(dsn)

    // Гарантируем, что соединение будет закрыто при завершении main().
    // defer означает "выполни это в конце функции".
    defer dbase.Close()

    // Создаём экземпляр обработчиков категорий.
    // Хендлеры — это функции, которые отвечают на HTTP-запросы.
    // Мы передаём подключение к БД, чтобы они могли читать и записывать данные.
    cats := handlers.NewCategoryHandlers(dbase)

    // Регистрируем путь /categories.
    // http.HandleFunc связывает URL с функцией, которая будет обрабатывать запросы по этому адресу.
    http.HandleFunc("/categories", func(w http.ResponseWriter, r *http.Request) {
        // В зависимости от HTTP-метода выбираем, какую функцию вызывать.
        switch r.Method {
        case http.MethodGet:
            // GET /categories — получить список категорий.
            cats.ListCategories(w, r)
        case http.MethodPost:
            // POST /categories — создать новую категорию.
            cats.CreateCategory(w, r)
        default:
            // Если метод не поддерживается — вернём ошибку 405 (Method Not Allowed).
            http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
        }
    })

    // Читаем переменную окружения PORT — на каком порту запускать сервер.
    port := os.Getenv("PORT")

    // Если переменная PORT не указана (например, в .env её нет) —
    // по умолчанию используем порт 8080.
    if port == "" {
        port = "8080"
    }

    // Выводим сообщение в консоль, чтобы знать, что сервер успешно запущен.
    fmt.Printf("🚀 Server running on <http://localhost>:%s\n", port)

    // Запускаем HTTP-сервер.
    // Первый аргумент — адрес (":8080" означает "слушать на всех интерфейсах").
    // Второй — обработчик (nil значит использовать зарегистрированные через HandleFunc маршруты).
    // log.Fatal выведет ошибку, если сервер по какой-то причине не сможет запуститься.
    log.Fatal(http.ListenAndServe(":"+port, nil))
}

```
