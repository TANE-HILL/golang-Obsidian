# Зачем нужны транзакции

Представь: в нашем приложении **GoFinance** пользователь делает перевод между счетами.

- Со счёта **А** нужно снять 100₽
- На счёт **Б** зачислить 100₽

Что будет, если после первого запроса сервер упадёт?
Деньги исчезнут!
Потому что первая операция прошла, а вторая — нет.

---
## Решение — транзакции

Транзакция (transaction) — это **набор SQL-операций**, которые **либо выполняются все, либо не выполняется ни одна**. Если внутри транзакции что-то пошло не так — всё откатывается, и база остаётся в исходном состоянии.

---
## Пример из жизни

Транзакция — это как “корзина” покупок:

- Пока ты не нажал “Оформить заказ”, ничего не произошло.
- Если на кассе ошибка — отменяется весь чек, а не одна позиция.

---
# Принцип работы

|Шаг|SQL-команда|Что делает|
|---|---|---|
|1️⃣|`BEGIN`|Начало транзакции|
|2️⃣|_(несколько запросов)_|Выполняются изменения|
|3️⃣|`COMMIT`|Подтверждает всё — данные сохраняются|
|❌|`ROLLBACK`|Отмена — возвращает всё назад|

---
## Пример в чистом SQL

```sql
BEGIN;

UPDATE accounts SET balance = balance - 100 WHERE id = 1;
UPDATE accounts SET balance = balance + 100 WHERE id = 2;

COMMIT;
```

Если на любом этапе ошибка — можно сделать `ROLLBACK`.

---
## Как это выглядит в Go

Go поддерживает транзакции через методы пакета `database/sql` и `sqlx`.

### Основные методы

|Метод|Что делает|Возвращает|
|---|---|---|
|`db.Begin()`|Начинает транзакцию|`*sql.Tx`|
|`tx.Exec()`|Выполняет SQL внутри транзакции|`sql.Result`|
|`tx.Query()` / `tx.QueryRow()`|Делает выборку данных внутри транзакции|`*sql.Rows` / `*sql.Row`|
|`tx.Commit()`|Подтверждает изменения|`error`|
|`tx.Rollback()`|Откатывает изменения|`error`|


### Пример в коде (на `sqlx`)

```go
tx, err := db.Beginx() // начинаем транзакцию
if err != nil {
    log.Fatal(err)
}

_, err = tx.Exec(`UPDATE accounts SET balance = balance - 100 WHERE id = 1`)
if err != nil {
    tx.Rollback() // откат, если ошибка
    log.Fatal(err)
}

_, err = tx.Exec(`UPDATE accounts SET balance = balance + 100 WHERE id = 2`)
if err != nil {
    tx.Rollback()
    log.Fatal(err)
}

err = tx.Commit() // если всё прошло успешно — сохраняем
if err != nil {
    log.Fatal(err)
}

```

---
### Что здесь происходит

1. `db.Beginx()` — открываем новую транзакцию.
2. Все запросы (`Exec`, `Query`) выполняются **на объекте `tx`**, а не `db`.
3. Если ошибка — вызываем `tx.Rollback()`.
4. Если всё прошло успешно — `tx.Commit()` фиксирует изменения.

## 1. Модель транзакции

📄 `internal/models/transaction.go`:
```go
package models

// Transaction — структура, описывающая запись в таблице transactions.
// Теги db нужны sqlx для маппинга колонок БД на поля структуры,
// а json — чтобы отдавать корректный JSON-ответ клиенту.
type Transaction struct {
    ID         int     `db:"id" json:"id"`
    CategoryID int     `db:"category_id" json:"category_id"`
    Amount     float64 `db:"amount" json:"amount"`
    Note       string  `db:"note" json:"note"`
    CreatedAt  string  `db:"created_at" json:"created_at"`
}
```

---
## 2. Репозиторий транзакций

📄 `internal/db/transaction_repo.go`:
```go
package db

import (
    "context"
    "gofinance/internal/models"
    "github.com/jmoiron/sqlx"
)

// TransactionRepo — структура, которая хранит подключение к БД
// и методы работы с таблицей transactions.
type TransactionRepo struct {
    db *sqlx.DB
}

// NewTransactionRepo — конструктор репозитория.
func NewTransactionRepo(db *sqlx.DB) *TransactionRepo {
    return &TransactionRepo{db: db}
}

// Create — добавляет новую транзакцию в таблицу.
// Важно: выполняется внутри транзакции SQL (BEGIN -> COMMIT).
func (r *TransactionRepo) Create(ctx context.Context, t models.Transaction) (models.Transaction, error) {
    tx, err := r.db.Beginx() // начинаем SQL-транзакцию
    if err != nil {
        return models.Transaction{}, err
    }

    query := `
        INSERT INTO transactions (category_id, amount, note)
        VALUES ($1, $2, $3)
        RETURNING id, category_id, amount, note, created_at;
    `

    var tr models.Transaction
    if err := tx.GetContext(ctx, &tr, query, t.CategoryID, t.Amount, t.Note); err != nil {
        // ❌ ошибка — откатываем все изменения
        tx.Rollback()
        return models.Transaction{}, err
    }

    // ✅ подтверждаем все операции
    if err := tx.Commit(); err != nil {
        return models.Transaction{}, err
    }

    return tr, nil
}
```

## 3. HTTP-хендлер

📄 `internal/handlers/transactions.go`:
```go
package handlers

import (
    "encoding/json"
    "net/http"
    "github.com/jmoiron/sqlx"
    "gofinance/internal/db"
    "gofinance/internal/models"
)

type TransactionHandlers struct {
    repo *db.TransactionRepo
}

func NewTransactionHandlers(dbase *sqlx.DB) *TransactionHandlers {
    return &TransactionHandlers{repo: db.NewTransactionRepo(dbase)}
}

// POST /transactions — создаёт новую транзакцию (вставку в БД).
func (h *TransactionHandlers) CreateTransaction(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodPost {
        http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
        return
    }

    var in struct {
        CategoryID int     `json:"category_id"`
        Amount     float64 `json:"amount"`
        Note       string  `json:"note"`
    }

    if err := json.NewDecoder(r.Body).Decode(&in); err != nil {
        http.Error(w, "Invalid JSON", http.StatusBadRequest)
        return
    }

    tr, err := h.repo.Create(r.Context(), models.Transaction{
        CategoryID: in.CategoryID,
        Amount:     in.Amount,
        Note:       in.Note,
    })
    if err != nil {
        http.Error(w, "Database error: "+err.Error(), http.StatusInternalServerError)
        return
    }

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusCreated)
    json.NewEncoder(w).Encode(tr)
}

```

## 4. Обновляем `main.go`

📄 `cmd/api/main.go`:
*(добавляем внизу, **не трогаем категории**)*
```go
trans := handlers.NewTransactionHandlers(dbase)

http.HandleFunc("/transactions", func(w http.ResponseWriter, r *http.Request) {
    switch r.Method {
    case http.MethodPost:
        trans.CreateTransaction(w, r)
    default:
        http.Error(w, "Method Not Allowed", http.StatusMethodNotAllowed)
    }
})
```

---
## Что изменилось по сравнению с прошлым уроком (ORM / Query)

| Было                                                     | Стало                                                             |
| -------------------------------------------------------- | ----------------------------------------------------------------- |
| Мы писали **отдельные SQL-запросы** (`INSERT`, `SELECT`) | Теперь объединяем их в одну **транзакцию**                        |
| Ошибка в одном запросе не влияла на остальные            | Теперь — если ошибка в одном, **откатывается всё**                |
| Использовали `db.Exec`, `db.Get`, `db.Select`            | Теперь используем `tx.Exec`, `tx.Get`, `tx.Commit`, `tx.Rollback` |
| Работали “прямо” с базой                                 | Теперь работаем через **объект транзакции `tx`**                  |
| Обработка ошибок шла после каждого запроса               | Теперь добавляется логика **отката (Rollback)**                   |

## Проверка отката (Rollback)

Чтобы убедиться, что откат работает — можно временно добавить искусственную ошибку:
```go
if t.Amount < 0 {
    tx.Rollback()
    return models.Transaction{}, fmt.Errorf("нельзя добавить отрицательную сумму")
}
```
И попробовать:
```bash
curl -X POST <http://localhost:8080/transactions> \
  -H "Content-Type: application/json" \
  -d '{"category_id":1,"amount":-500,"note":"Ошибка"}'
```

📘 В ответ сервер отправит `500 Database error`, а в базе запись **не появится**.

# Итоги

| Концепция         | Что делает                                                  |
| ----------------- | ----------------------------------------------------------- |
| `Beginx()`        | начинает SQL-транзакцию                                     |
| `Commit()`        | фиксирует все изменения                                     |
| `Rollback()`      | откатывает, если произошла ошибка                           |
| `tx.GetContext()` | выполняет SQL внутри транзакции                             |
| **Главная цель**  | Гарантировать, что данные в БД всегда в целостном состоянии |
