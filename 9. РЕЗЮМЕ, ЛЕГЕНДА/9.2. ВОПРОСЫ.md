# 2. Go: map, slice, array

## 1. Как устроена map внутри Go?

Map в Go реализована на основе хеш-таблицы. Она позволяет хранить пары ключ-значение и быстро получать значение по ключу.

Когда мы добавляем элемент, Go вычисляет хеш ключа и использует его для определения места хранения.

При поиске по ключу происходит примерно следующее:

1. Вычисляется хеш ключа.
    
2. По хешу определяется группа, в которой может находиться элемент.
    
3. Проверяются подходящие ключи.
    
4. При совпадении возвращается соответствующее значение.
    

В Go map предоставляет в среднем O(1) для поиска, вставки и удаления, хотя в худших случаях операция может быть медленнее.

Важно: map не потокобезопасна. Одновременная запись из нескольких горутин без синхронизации может привести к runtime panic.

## 2. Чем отличаются старая и новая реализации map?

В Go 1.24 появилась новая реализация map на основе Swiss Tables.

**Старая реализация:**

- Использовала бакеты.
    
- Каждый бакет мог хранить до 8 пар ключ-значение.
    
- При большом количестве коллизий использовались дополнительные overflow-бакеты.
    
- Для поиска приходилось проверять элементы бакета и связанные overflow-бакеты.
    

**Новая реализация:**

- Основана на подходе Swiss Tables.
    
- Использует группы по 8 слотов.
    
- Для каждого слота хранится управляющий байт, содержащий информацию о состоянии слота и часть хеша.
    
- Сначала проверяются управляющие байты, чтобы быстрее отсеивать неподходящие ключи.
    
- Для больших таблиц используется дополнительная структура directory, которая помогает находить нужную группу.
    

Основная цель новой реализации — улучшить производительность поиска, вставки и удаления, а также эффективность использования памяти.

Важно: с точки зрения разработчика API map практически не изменился. Внутреннюю реализацию не нужно контролировать вручную.

## 3. Что произойдёт при конкурентном чтении и записи в map?

Обычная map в Go не потокобезопасна.

Если несколько горутин одновременно записывают данные в одну map или одна записывает, а другая читает, возникает data race. В некоторых случаях runtime может завершить программу с ошибкой `concurrent map read and map write` или `concurrent map writes`.

Для защиты можно использовать:

- `sync.Mutex` — блокировать доступ к map на время операции.
    
- `sync.RWMutex` — разрешать несколько одновременных читателей, но блокировать запись.
    
- `sync.Map` — специализированная конкурентная структура из стандартной библиотеки.
    

Пример с Mutex:

```
type SafeMap struct {
    mu   sync.RWMutex
    data map[string]int
}

func (m *SafeMap) Get(key string) int {
    m.mu.RLock()
    defer m.mu.RUnlock()

    return m.data[key]
}

func (m *SafeMap) Set(key string, value int) {
    m.mu.Lock()
    defer m.mu.Unlock()

    m.data[key] = value
}
```

## 4. Что такое хеш-таблица и как она работает?

Хеш-таблица — это структура данных, которая позволяет хранить значения по ключу и быстро получать их.

Для этого используется хеш-функция, которая преобразует ключ в числовое значение.

Например:

```
key = "user123"

hash("user123") = 45821
```

На основании хеша определяется место хранения элемента.

Иногда разные ключи могут давать одинаковый хеш или попадать в одну и ту же область хранения. Это называется коллизией.

Для обработки коллизий используются разные методы:

- Метод цепочек — несколько элементов хранятся в одной области через дополнительные структуры.
    
- Открытая адресация — при занятом слоте ищется другое подходящее место.
    

В Go реализация map зависит от версии языка и использует механизмы группировки элементов и обработки коллизий.

## 5. Чем массив отличается от слайса?

**Массив (array)** — это фиксированная последовательность элементов одного типа. Его размер является частью типа.

**Слайс (slice)** — это структура, которая предоставляет удобный способ работать с частью массива или динамической последовательностью элементов.

Основные отличия:

|Массив|Слайс|
|---|---|
|Фиксированный размер|Динамическая длина|
|Размер входит в тип|Размер не входит в тип|
|При присваивании копируются элементы|При присваивании копируется заголовок|
|Не имеет append|Поддерживает append|

Пример:

```
var arr [3]int

slice := []int{1, 2, 3}
slice = append(slice, 4)
```

Слайс внутри ссылается на массив, поэтому несколько слайсов могут использовать одну и ту же область памяти.

## 6. Что такое слайс и как он устроен внутри?

Слайс — это структура, которая состоит из трёх полей:

1. Pointer — указатель на первый элемент backing array.
    
2. Length — количество элементов, доступных через слайс.
    
3. Capacity — максимальное количество элементов, которое можно разместить без выделения нового backing array.
    

Упрощённо:

```
type SliceHeader struct {
    Data uintptr
    Len  int
    Cap  int
}
```

Например:

```
numbers := make([]int, 3, 5)
```

Здесь:

- Len = 3.
    
- Cap = 5.
    
- Backing array содержит место для 5 элементов.
    

Важно: это упрощённое представление. В реальном Go для работы с unsafe используются специальные типы, а не ручное создание такого заголовка.

## 7. Как работает append?

Функция `append` добавляет элементы в слайс.

Например:

```
numbers := []int{1, 2, 3}

numbers = append(numbers, 4)
```

Если в backing array достаточно capacity, новый элемент записывается в существующий массив, а длина слайса увеличивается.

Если capacity недостаточно, Go выделяет новый backing array, копирует туда существующие элементы и добавляет новые.

Поэтому результат `append` обязательно нужно присваивать обратно:

```
numbers = append(numbers, 4)
```

Потому что функция может вернуть новый слайс с другим backing array.

## 8. Что происходит при нехватке capacity?

Если при вызове `append` длина слайса после добавления элементов превышает capacity, Go выделяет новый backing array.

Дальше:

1. Создаёт новый массив подходящего размера.
    
2. Копирует туда старые элементы.
    
3. Добавляет новые элементы.
    
4. Возвращает новый слайс с обновлёнными pointer, len и cap.
    

Увеличение capacity не всегда происходит ровно в два раза. Конкретный алгоритм зависит от размера слайса и реализации runtime.

Пример:

```
numbers := make([]int, 2, 2)

numbers = append(numbers, 3)
```

Теперь старого массива недостаточно, поэтому будет выделен новый.

## 9. Что произойдёт, если несколько слайсов ссылаются на один backing array?

Они будут использовать одну и ту же область памяти.

Поэтому изменение элемента через один слайс может быть видно через другой.

Пример:

```
a := []int{1, 2, 3, 4}

b := a[:2]

b[0] = 100

fmt.Println(a) // [100 2 3 4]
```

Это происходит потому, что оба слайса ссылаются на один backing array.

Но если при append одному из слайсов не хватит capacity, Go выделит новый массив. После этого изменения уже не будут общими.

# 3. Go: интерфейсы

## 1. Что такое интерфейс в Go?

Интерфейс — это тип, который определяет набор методов, которые должен реализовать другой тип.

Например:

```
type Speaker interface {
    Speak()
}
```

Любой тип, у которого есть метод `Speak()` с подходящей сигнатурой, автоматически реализует этот интерфейс.

В Go не нужно явно указывать, что структура реализует интерфейс.

Интерфейсы позволяют писать более гибкий и слабо связанный код.

## 2. Что такое duck typing?

Duck typing — это подход, при котором важны не конкретный тип объекта и его происхождение, а наличие необходимых методов.

В Go это реализовано через неявную реализацию интерфейсов.

Например:

```
type Speaker interface {
    Speak()
}

type Dog struct{}

func (d Dog) Speak() {
    fmt.Println("Woof")
}
```

Структура `Dog` реализует интерфейс `Speaker`, хотя мы нигде явно этого не объявляли.

Если тип имеет все методы интерфейса с нужными сигнатурами, он считается его реализацией.

## 3. Как устроено внутреннее представление интерфейса?

Упрощённо интерфейс в Go состоит из двух частей:

1. Динамический тип.
    
2. Динамическое значение.
    

Например:

```
var x interface{} = 42
```

Внутри интерфейса хранится информация о том, что динамический тип — `int`, а значение — `42`.

Для непустого интерфейса используется структура `iface`, которая содержит ссылку на таблицу методов и указатель на данные.

Для пустого интерфейса `any` используется структура `eface`, которая содержит информацию о типе и указатель на данные.

Это упрощённое описание внутреннего устройства runtime.

## 4. Что такое typed nil?

Typed nil — это ситуация, когда интерфейс содержит конкретный тип, значение которого равно nil.

Например:

```
type MyError struct{}

func (e *MyError) Error() string {
    return "error"
}

func getError() error {
    var err *MyError = nil
    return err
}

func main() {
    err := getError()

    fmt.Println(err == nil) // false
}
```

Почему?

Потому что интерфейс содержит два компонента:

- Динамический тип: `*MyError`.
    
- Динамическое значение: `nil`.
    

Сам интерфейс при этом не равен nil, поскольку тип внутри него присутствует.

Это частая причина неожиданных ошибок при работе с интерфейсами, особенно с `error`.

Чтобы вернуть настоящий nil, нужно вернуть `nil` непосредственно:

```
func getError() error {
    return nil
}
```

# 4. Go: конкурентность

## 1. Что такое горутина и чем она отличается от потока ОС?

Горутина — это лёгкая единица конкурентного выполнения в Go, которой управляет runtime.

Поток ОС создаётся и планируется операционной системой, а горутины планируются Go runtime и выполняются на потоках ОС.

Основные отличия:

- Горутины значительно легче потоков ОС.
    
- Для создания горутины требуется меньше ресурсов.
    
- Runtime самостоятельно распределяет горутины по потокам.
    
- Горутины могут приостанавливаться и продолжать выполнение на других потоках.
    
- Можно создавать большое количество горутин.
    

Go использует модель планировщика G-M-P:

- G — goroutine.
    
- M — machine, поток ОС.
    
- P — processor, необходимый для выполнения Go-кода на потоке.
    

Именно P связывает планировщик горутин с потоками ОС.

## 2. Какие механизмы синхронизации есть в Go?

В Go есть несколько основных механизмов синхронизации:

**Mutex**

Используется для взаимного исключения. Только одна горутина может владеть блокировкой одновременно.

**RWMutex**

Позволяет нескольким горутинам одновременно читать данные, но запись выполняется эксклюзивно.

**WaitGroup**

Позволяет дождаться завершения группы горутин.

**Channel**

Используется для передачи данных между горутинами и синхронизации их работы.

**Once**

Гарантирует выполнение определённого действия только один раз.

**Cond**

Позволяет горутинам ожидать наступления определённого условия.

Также есть атомарные операции из пакета `sync/atomic`.

## 3. Как синхронизировать работу нескольких горутин?

Зависит от задачи.

Если несколько горутин работают с общей структурой данных, можно использовать `Mutex` или `RWMutex`.

Если нужно дождаться завершения нескольких горутин, подойдёт `WaitGroup`.

Если нужно передавать данные между горутинами, можно использовать каналы.

Пример с WaitGroup:

```
var wg sync.WaitGroup

for i := 0; i < 3; i++ {
    wg.Add(1)

    go func() {
        defer wg.Done()

        fmt.Println("Worker started")
    }()
}

wg.Wait()
```

В этом примере основная горутина ждёт, пока все три рабочие горутины завершатся.

## 4. Что такое deadlock и как он возникает?

Deadlock — это взаимная блокировка, при которой несколько горутин ожидают друг друга и не могут продолжить выполнение.

Например:

```
ch := make(chan int)

ch <- 10

fmt.Println("Done")
```

Здесь используется небуферизированный канал. Отправка блокируется, пока другая горутина не начнёт получать данные.

Но получателя нет, поэтому программа зависает. В данном случае runtime обнаружит deadlock.

Другой пример — две горутины захватили разные мьютексы и каждая ждёт мьютекс, удерживаемый другой.

Чтобы избегать deadlock:

- Соблюдать единый порядок захвата блокировок.
    
- Не удерживать блокировки дольше необходимого.
    
- Не выполнять длительные операции под мьютексом без необходимости.
    
- Правильно организовывать отправку и получение данных из каналов.
    

## 5. Можно ли гарантировать последовательность выполнения горутин?

По умолчанию нет. Планировщик Go самостоятельно определяет, когда и на каком потоке выполнять горутины.

Если нужно обеспечить определённый порядок, его необходимо реализовать явно.

Для этого можно использовать:

- Каналы для передачи сигналов и данных.
    
- Mutex для последовательного доступа к общим ресурсам.
    
- WaitGroup для ожидания завершения группы горутин.
    
- Другие механизмы синхронизации.
    

Например, если вторая операция должна выполниться только после первой, первая горутина может отправить сигнал в канал, а вторая будет ждать его получения.

Важно: запуск горутин в определённом порядке не означает, что они выполнятся в этом же порядке.

# 5. PostgreSQL

## 1. Какие типы индексов есть в PostgreSQL?

В PostgreSQL есть несколько основных типов индексов.

**B-tree**

Самый распространённый тип. Подходит для сравнений, сортировки, поиска по равенству и диапазонам.

Например:

```
CREATE INDEX idx_users_email
ON users(email);
```

**Hash**

Используется для поиска по точному равенству.

**GIN**

Подходит для работы со значениями, содержащими множество элементов: массивами, JSONB и полнотекстовым поиском.

**GiST**

Используется для различных структур данных и сложных типов поиска, например геометрических данных и диапазонов.

**SP-GiST**

Подходит для структур с разбиением пространства поиска, например деревьев и некоторых геометрических структур.

**BRIN**

Хранит информацию о диапазонах страниц таблицы. Особенно полезен для очень больших таблиц, где значения физически коррелируют с порядком хранения, например по дате создания.

## 2. Какие плюсы и минусы использования индексов?

**Плюсы:**

- Ускоряют поиск данных.
    
- Уменьшают количество читаемых страниц таблицы.
    
- Помогают выполнять сортировку.
    
- Могут ускорять JOIN и фильтрацию.
    

**Минусы:**

- Занимают дополнительное место на диске.
    
- Замедляют INSERT, UPDATE и DELETE, потому что индексы тоже нужно обновлять.
    
- Требуют обслуживания.
    
- Избыточные индексы могут ухудшать общую производительность базы.
    

Поэтому индексы нужно создавать под реальные запросы, а не индексировать каждую колонку подряд.

## 3. Как найти медленный запрос в PostgreSQL?

Есть несколько способов.

**1. pg_stat_statements**

Расширение PostgreSQL, которое собирает статистику выполнения SQL-запросов.

Позволяет увидеть:

- Количество выполнений.
    
- Среднее время выполнения.
    
- Общее время выполнения.
    
- Количество прочитанных и возвращённых строк.
    

**2. Логи PostgreSQL**

Можно настроить логирование медленных запросов через параметр:

```
log_min_duration_statement = 500
```

В этом случае будут логироваться запросы, выполнение которых заняло более 500 миллисекунд.

**3. EXPLAIN ANALYZE**

Позволяет посмотреть план выполнения конкретного запроса и фактическое время выполнения.

## 4. Как читать EXPLAIN ANALYZE и что смотреть?

`EXPLAIN` показывает план, который PostgreSQL собирается использовать для выполнения запроса.

`EXPLAIN ANALYZE` дополнительно выполняет запрос и показывает фактические показатели.

Например:

```
EXPLAIN ANALYZE
SELECT *
FROM users
WHERE email = 'test@example.com';
```

На что обращаю внимание:

- **Seq Scan** — последовательное сканирование таблицы.
    
- **Index Scan** — поиск через индекс с обращением к таблице.
    
- **Index Only Scan** — получение данных непосредственно из индекса, если это возможно.
    
- **Actual Time** — фактическое время выполнения узла плана.
    
- **Rows** — количество фактически обработанных строк.
    
- **Estimated Rows** — оценка количества строк планировщиком.
    
- **Buffers** — информация о чтении страниц из памяти и с диска, если включён `BUFFERS`.
    

Если вижу, что запрос выполняет Seq Scan по большой таблице, проверяю, можно ли использовать индекс.

Также смотрю, насколько оценки планировщика совпадают с фактическими результатами, нет ли лишних сортировок, дорогих JOIN и большого количества чтений.

Важно: Seq Scan сам по себе не является проблемой. Если таблица небольшая или запрос возвращает значительную часть данных, последовательное сканирование может быть быстрее индекса.

# 6. Сети и Linux

## 1. Чем TCP отличается от UDP? Когда использовать каждый протокол?

**TCP** — протокол с установлением соединения. Он обеспечивает надёжную передачу данных.

Основные свойства:

- Устанавливает соединение через three-way handshake.
    
- Гарантирует доставку данных или сообщает об ошибке.
    
- Сохраняет порядок передачи байтов.
    
- Использует подтверждения получения и повторную передачу потерянных данных.
    
- Управляет потоком и перегрузкой.
    

**UDP** — протокол без установления соединения.

Основные свойства:

- Не гарантирует доставку.
    
- Не гарантирует порядок получения пакетов.
    
- Не выполняет автоматическую повторную передачу потерянных пакетов.
    
- Имеет меньшие накладные расходы.
    

**Когда использовать:**

TCP подходит для HTTP/1.1, HTTP/2, передачи файлов, работы с базами данных и других сценариев, где важна надёжная доставка.

UDP подходит для DNS, голосовой связи, видеозвонков и других сценариев, где важна скорость и допустима потеря отдельных пакетов.

Также на UDP работает QUIC, который используется в HTTP/3.

## 2. Чем HTTP отличается от HTTPS?

HTTP — протокол прикладного уровня, который используется для передачи данных между клиентом и сервером.

HTTPS — это HTTP, работающий поверх защищённого соединения TLS.

HTTPS обеспечивает:

- Шифрование передаваемых данных.
    
- Проверку подлинности сервера с помощью сертификата.
    
- Контроль целостности передаваемых данных.
    

То есть при использовании HTTP данные могут передаваться в открытом виде, а HTTPS защищает их от перехвата и изменения при передаче.

Обычно HTTP использует порт 80, HTTPS — 443.

## 3. Как проверить загрузку CPU и использование оперативной памяти?

В Linux есть несколько стандартных инструментов.

**top**

Показывает процессы, загрузку CPU, использование памяти и другие показатели в реальном времени.

**htop**

Более удобная интерактивная версия top.

**ps**

Позволяет получить информацию о процессах.

Например:

```
ps aux
```

Для сортировки по потреблению CPU:

```
ps aux --sort=-%cpu
```

Для сортировки по памяти:

```
ps aux --sort=-%mem
```

**free**

Показывает использование оперативной памяти:

```
free -h
```

**vmstat**

Позволяет смотреть общую статистику по памяти, процессам и системе:

```
vmstat 1
```

Если нужно разобраться с проблемами производительности Go-приложения, дополнительно можно использовать `pprof`, чтобы анализировать CPU-профиль, аллокации и потребление памяти непосредственно приложением.
