отделил от текущего состояния резюме.

состав данных на момент отклика, при

видимости проверяются отдельно при 
обращении к профилю.

техническую попытку доставки и 
подтверждение внешней системы.

Проверял падение процесса после

Проект: интеграционные сервисы передачи 
готовых документов из медицинских систем 
в личный кабинет. Задачи по доступности 
файлов, версиям результатов и технической 
диагностике; без интерпретации 
медицинских показателей.
Достижения:
Разделил получение сообщения о 
готовности исследования и фактическую 
публикацию файла. Документ появляется 
в кабинете после проверки доступности 
объекта и связи с пациентом, поэтому 
уведомление больше не ведет на еще не 
загруженный результат.
Исправленный результат оформляется 
новой редакцией с явной связью с 
предыдущей. Старую редакцию нельзя 
случайно выдать как актуальную, а 
служебная история сохраняет причину 
замены и источник обновления.
При сопоставлении данных нескольких 
клиник отказался от поиска пациента 
только по ФИО и дате рождения. 
Автоматическая публикация использует 
подтвержденную связь идентификаторов; 
неоднозначный документ остается в 
отдельной очереди разбора.
RabbitMQ-задачи получения файлов 
получили разные исходы для временной 
недоступности источника и нарушения 
контракта. Первое повторяется с 
задержкой, второе передается на разбор 
с технической причиной без медицинских 
данных в сообщении об ошибке.
В API скачивания проверяется 
принадлежность документа и 
действующее основание доступа 
представителя. Прямая ссылка сама по 
себе не дает право получить файл; 
обращение фиксируется в журнале 
доступа.
Для сопровождения сделал сверку 
объявленных и опубликованных 
документов за период. Выборка по 
PostgreSQL помогает найти пропущенный 
результат без повторного импорта всей 
истории; интеграционные тесты 
воспроизводят поздний файл и замену 
редакции во время обработки.
Стек: Go, PostgreSQL, SQL, Redis, RabbitMQ, 
REST API, HTTP, Docker, GitLab CI/CD, Linux, 
unit-тесты, интеграционное тестирование.
