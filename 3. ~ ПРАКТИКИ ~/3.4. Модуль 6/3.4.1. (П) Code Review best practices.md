# <u>Задание</u>

Ниже приведён фрагмент программы, которая запускает несколько горутин, имитирующих обработку запросов.
**Необходимо провести code review**, оставить **5–7 комментариев**, а затем написать **исправленную версию кода**.
#### <u>Формат решения</u>
1. **Комментарии ревьюера**
Пример:
> “Канал done может переполниться, если воркеров меньше, чем задач. Лучше заменить его на ….”
2. **Исправленный код** — финальный вариант.
3. **Сравнение с решением
#### <u>Код для ревью</u>
```go
package main
import (
	"fmt"
	"time"
)
type Request struct {
	ID int
}
func worker(id int, requests <-chan Request, done chan bool) {
	for r := range requests {
		fmt.Println("Worker", id, "processing request", r.ID)
		time.Sleep(time.Millisecond * 100)
		done <- true
	}
}
func main() {
	requests := make(chan Request)
	done := make(chan bool)
	for i := 1; i <= 3; i++ {
		go worker(i, requests, done)
	}
	for i := 1; i <= 5; i++ {
		requests <- Request{ID: i}
	}
	close(requests)
	for i := 0; i < 5; i++ {
		<-done
	}
	fmt.Println("All requests processed")
}
```
#### <u>Что нужно сделать</u>
1. **Изучи код внимательно.**
    Он работает, но не идеально.
2. **Оставь комментарии в стиле Code Review.**
    Например:
    - Что может пойти не так при одновременном выполнении?
    - Что можно улучшить в архитектуре?
    - Есть ли риск блокировки?
    - Что произойдёт, если количество задач или воркеров изменится?
3. **Внеси исправления** — напиши исправленный вариант программы.
4. **Сравни с решением в конце**, чтобы понять, насколько близко твои предложения совпадают с реальным ревью.

---
# <u>Решение</u>

#### Комментарий:
1. **Логика работы и архитектура программы понятны** - в целом, неплохо, но допущены две небольшие ошибки. Сейчас объясню, как их можно исправить, не меняя принцип работы программы (затем разберу и его):
	- <u>Первый момент</u>: `done <- true` сейчас находится **внутри цикла** `range requests` в функции `worker` - из-за этого горутина при **каждой итерации цикла задач** как бы отправляет сообщение, что она завершила свою работу. А задач в этом коде больше, чем горутин (*5 против 3*). **Поэтому возникает deadlock**.
	- <u>Второй момент</u>: даже если мы вынесем `done <- true` в конец функции `worker`, **deadlock всё равно будет возникать при выполнении программы**. Это происходит потому что сейчас **горутины запускаются в количестве трёх штук**, а результата `<-done` ожидает **цикл из пяти итераций**. **Правильно будет:** `for i := 0; i < 5; i++ {...` **заменить на** `for i := 0; i < 3; i++ {`.
2. Теперь, когда **код работает** и выводится корректный результат, можно углубиться и разобрать его архитектуру.
3. Первое, что бросается в глаза - `time.Sleep`. Он здесь, в целом, не нужен - убираем строку полностью.
4. Решение с каналом `done` в качестве сигнала завершения горутин - рабочее, однако, **идиоматичнее и красивее для этих целей использовать** `WaitGroup` **из пакета** `sync` (*тогда, например, при изменении количества горутин в будущем, не придётся менять количество итераций в цикле ожидания `<-done`*). Для этого мы удаляем из кода всё, что касается `done` и делаем следующее:
	- В `func main` объявляем новую переменную: `wg := sync.WaitGroup{}`;
	- В цикле, перед созданием горутины, добавляем метод `wg.Add(1)` - тогда, вместе с горутиной, в каждой итерации будет создаваться 1 "слот" для её ожидания;
	- Указатель на `wg` передаём в функцию `go worker(i, requests, &wg)`, тогда в теле функции будет: `func worker(id int, requests <-chan Request, wg *sync.WaitGroup) {...`;
	- Внутри функции в самом начале добавляем `defer wg.Done()`;
	- В конце `func main`, перед выводом, добавляем `wg.Wait()`.
5. Структура `Request`, в целом, не нужна, поскольку содержит только одно поле: `ID int`. Её можно смело убрать. Тогда канал будет работать с типом int: `requests := make(chan int)`. Тогда внутри цикла "передачи задач" мы пишем: `requests <- i`, а вывод внутри функции меняем на: `fmt.Println("Worker", id, "processing request", r)`.

Исправленный код:
```Go
package main  
  
import (  
    "fmt"  
    "sync")  
  
func worker(id int, requests <-chan int, wg *sync.WaitGroup) {  
    defer wg.Done()  
    for r := range requests {  
       fmt.Println("Worker", id, "processing request", r)  
    }  
}  
  
func main() {  
    requests := make(chan int)  
    wg := sync.WaitGroup{}  
    for i := 1; i <= 3; i++ {  
       wg.Add(1)  
       go worker(i, requests, &wg)  
    }  
  
    for i := 1; i <= 5; i++ {  
       requests <- i  
    }  
  
    close(requests)  
    wg.Wait()  
    fmt.Println("All requests processed")  
}
```
