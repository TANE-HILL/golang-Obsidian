# Зачем нужны panic, recover и defer

В прошлом уроке мы узнали, что в [[1.1.0. Go Basics|Go]] [[1.3.0. Ошибки и обработка ошибок|ошибки]] — это **[[1.1.1. Переменные|значения]]**, которые мы возвращаем и проверяем.

Это позволяет **контролировать программу вручную**: если ошибка есть — вернуть, если нет — продолжить.

Но бывают ситуации, когда программа **не может безопасно продолжить работу вообще** — и тогда обычная [[1.3.0. Ошибки и обработка ошибок|ошибка]] уже не подходит.

---
# Что такое ~ <font color="#ff0000">panic</font> ~

`panic` — это **встроенная функция**, которая **моментально прерывает** нормальное выполнение программы.

Когда вызывается `panic`, Go начинает **сворачивать стэк вызовов**, выполняя все `defer`, а затем завершает программу с ошибкой.
#### Простой пример:
```go
func main() {
    fmt.Println("Начало программы")
    panic("критическая ошибка: нет соединения с базой данных")
    fmt.Println("Эта строка не будет выполнена")
}
```
**Вывод:**
```Run
Начало программы
panic: критическая ошибка: нет соединения с базой данных

goroutine 1 [running]:
main.main()
    /tmp/main.go:3 +0x...
exit status 2
```

**Разбор построчно:**
- `panic(...)` мгновенно останавливает выполнение функции.
- Программа «сворачивает» стек: выходит из всех функций, вызывая их `defer`.
- В конце печатается **traceback** — путь, по которому программа дошла до ошибки.
- После этого процесс завершается с кодом 2 (ошибка).

---
# Почему не использовать [[1.3.0. Ошибки и обработка ошибок|ошибку]] вместо <font color="#ff0000">panic</font>

`panic` и `error` решают **<u>разные задачи</u>**.

|Ситуация|Что делает `error`|Что делает `panic`|
|---|---|---|
|Обычный сбой (например, пользователь ввёл неверные данные)|возвращает ошибку, программа продолжает работать|не подходит|
|Критический сбой (например, повредился системный файл, нет конфига, ошибка в логике кода)|возвращать ошибку бессмысленно, программа не сможет продолжить|вызывает `panic` и завершает программу|
#### Сравнение: <font color="#ff0000">ошибка</font> против <font color="#ff0000">паники</font>

#### Вариант 1 — с ошибкой (контролируемая ситуация):
```go
func readFile(filename string) (string, error) {
    data, err := os.ReadFile(filename)
    if err != nil {
        return "", fmt.Errorf("не удалось открыть файл: %w", err)
    }
    return string(data), nil
}

func main() {
    content, err := readFile("data.txt")
    if err != nil {
        fmt.Println("Ошибка:", err)
        return
    }
    fmt.Println("Файл прочитан:", content)
}

```

**Разбор:**
- Это **ожидаемая** ошибка: файла может просто не быть.
- Мы сообщаем пользователю, что делать, и корректно завершаем работу.

#### Вариант 2 — с panic (фатальная ситуация):
```go
func mustReadFile(filename string) string {
    data, err := os.ReadFile(filename)
    if err != nil {
        panic(fmt.Sprintf("невозможно продолжить: файл %s не найден", filename))
    }
    return string(data)
}

func main() {
    fmt.Println("Загружаем конфиг...")
    content := mustReadFile("config.yaml")
    fmt.Println("Конфиг:", content)
}

```

**Разбор:**
- Если конфиг отсутствует — программа **не может работать вообще**.
- Ошибка не имеет смысла, потому что нет «дальше».
- Мы намеренно вызываем `panic`, чтобы программа **остановилась** и сообщила, что инициализация невозможна.

# Ещё одно сравнение: логическая ошибка

#### Ошибка через panic:
```go
func getUserRole(id int) string {
    switch id {
    case 1: return "admin"
    case 2: return "user"
    default:
        panic(fmt.Sprintf("неизвестная роль id=%d", id))
    }
}
```

Здесь мы явно говорим: «такого ID быть не может, это ошибка в коде, а не входных данных».
Если это случилось — пусть программа упадёт, чтобы мы заметили баг.

#### Ошибка через error:
```go
func getUserRole(id int) (string, error) {
    switch id {
    case 1: return "admin", nil
    case 2: return "user", nil
    default:
        return "", fmt.Errorf("роль с id=%d не найдена", id)
    }
}
```

📘 Здесь ошибка **ожидаема** — кто-то мог запросить несуществующую роль.

Мы спокойно возвращаем `error` и даём программе решить, что делать дальше (например, показать сообщение пользователю).

---
# Ключевое различие

- `error` — **предсказуемая, контролируемая ситуация**.
    Программа знает, что делать, и продолжает работу.
- `panic` — **непредсказуемая, критическая ошибка**.
    Программа не может безопасно продолжить и должна **остановиться**.

---
# Когда использовать ~ <font color="#ff0000">panic</font> ~

> Важно: panic — крайняя мера.
> Её не используют для обычных ошибок, только для **фатальных ситуаций**
#### Типичные случаи:
1. **Невозможное состояние**, которое не должно случиться:
```go
func getRole(id int) string {
	switch id {
	case 1: return "admin"
	case 2: return "user"
	default:
		panic(fmt.Sprintf("неизвестный id роли: %d", id))
	}
}
```
Здесь `panic` помогает поймать логическую ошибку в коде разработчика.

2. **Ошибка инициализации**, без которой программа не имеет смысла:
```go
var config Config    
func init() {
	data, err := os.ReadFile("config.yaml")
	if err != nil {
		panic("не удалось загрузить конфиг: " + err.Error())
	}
        // ... парсим конфиг
}    
```

3. **Ошибка системного уровня** (например, в пакете, который не может вернуть error, но обязан прекратить работу).

# Что делает ~ <font color="#ff0000">defer</font> ~

`defer` — это инструкция, которая откладывает выполнение [[1.1.5. Функции и передача данных|функции]] **до выхода** из текущей функции (независимо от того, произошёл `panic` или нет).

```go
func main() {
    defer fmt.Println("Завершаем программу")
    fmt.Println("Начало работы")
}
```
**Вывод:**
```Run
Начало работы
Завершаем программу
```

**Разбор:**
- `defer` добавляет функцию в **список отложенных действий**.
- Эти функции выполняются **в обратном порядке** (LIFO), когда текущая функция заканчивается.
- Даже если произошёл `panic`, `defer` всё равно выполнится.

#### Пример с ~ <font color="#ff0000">panic</font> ~ и ~ <font color="#ff0000">defer</font> ~ :
```go
func main() {
    defer fmt.Println("1. Завершаем работу (defer)")
    fmt.Println("2. Работаем")
    panic("3. Сбой системы")
    fmt.Println("4. Этого не будет")
}
```
**Вывод:**
```Run
2. Работаем
3. Завершаем работу (defer)
panic: 3. Сбой системы
```

**Разбор:**
- `defer` срабатывает **перед завершением функции**, даже при `panic`.
- Это удобно для закрытия файлов, соединений и других ресурсов.

# Что такое ~ <font color="#ff0000">recover</font> ~

`recover` — это функция, которая **останавливает** панику и **возвращает управление** в нормальный поток выполнения.

Но важно: `recover` **<u>работает только внутри</u> `defer`**.
Если вызвать его вне `defer` — он просто вернёт `nil`.

#### Пример без ~ <font color="#ff0000">recover</font> ~ :
```go
func crash() {
    panic("что-то пошло не так")
}

func main() {
    fmt.Println("Начало")
    crash()
    fmt.Println("Эта строка не выполнится")
}

```

Программа завершится с ошибкой и трассировкой (panic).

#### Пример с ~ <font color="#ff0000">recover</font> ~ :
```go
func safe() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Поймали панику:", r)
        }
    }()

    fmt.Println("Выполняем опасный код")
    panic("ошибка: деление на ноль")
}

func main() {
    safe()
    fmt.Println("Программа продолжает работу")
}
```
**Вывод:**
```Run
Выполняем опасный код
Поймали панику: ошибка: деление на ноль
Программа продолжает работу
```

**Разбор построчно:**
- `defer func() {...}` создаёт анонимную функцию, которая сработает **при выходе из `safe`**, даже если там `panic`.
- `recover()` возвращает значение, переданное в `panic`.
- Если `panic` не было — `recover()` возвращает `nil`.
- Если `panic` был — мы «ловим» его, выводим сообщение и **останавливаем сворачивание стека**, программа продолжается.

---
# Как работает связка: <font color="#ff0000">panic</font> → <font color="#ff0000">defer</font> → <font color="#ff0000">recover</font>

1. В какой-то функции вызывается `panic("...")`.
2. Go начинает «сворачивать» стек — завершает функции в обратном порядке.
3. На каждом уровне выполняются все отложенные (`defer`) вызовы.
4. Если внутри одного из `defer` есть `recover()` → panic **останавливается**, и выполнение продолжается после этой функции.

---
# Реальный пример: безопасный сервер

```go
func handleRequest() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("Ошибка во время обработки запроса:", r)
        }
    }()

    // Симулируем сбой
    panic("непредвиденная ошибка в обработчике")
}

func main() {
    fmt.Println("Сервер запущен")
    handleRequest()
    fmt.Println("Сервер продолжает работать")
}
```
**Вывод:**
```Run
Сервер запущен
Ошибка во время обработки запроса: непредвиденная ошибка в обработчике
Сервер продолжает работать
```

**Разбор:**
- Каждая обработка запроса обёрнута в `defer + recover`.
- Даже если внутри произошла паника, сервер не падает целиком.
- Это реальный паттерн: **изолировать паники** в «рабочих» горутинах и перехватывать их.

---
# Когда стоит использовать <font color="#ff0000">recover</font>

<u>Можно и нужно, если:</u>
- ты пишешь **долгоживущий процесс** (сервер, фоновые горутины), и хочешь защитить его от крашей;
- нужно **логировать** паники, чтобы не терять информацию, но не падать.

<u>Не нужно, если:</u>
- это обычная ошибка, которую можно вернуть через `error`;
- ты пытаешься «спрятать» ошибки, вместо того чтобы исправить их причину.

---
#### Взаимодействие <font color="#ff0000">panic</font> и <font color="#ff0000">defer</font>:
```go
func example() {
    defer fmt.Println("A")
    defer fmt.Println("B")
    panic("C")
    defer fmt.Println("D") // не выполнится
}
```
**Вывод:**
```
B
A
panic: C
```

**Разбор:**
- Отложенные функции выполняются **в обратном порядке** (B, потом A).
- `D` не зарегистрировался, потому что код не дошёл до него.
- После выполнения defer-ов программа всё равно завершится с `panic`.

---
# Полезный паттерн: «<font color="#ff0000">safe call</font>»

#### Часто делают универсальную обёртку для безопасного вызова:
```go
func safeCall(fn func()) {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("panic пойман:", r)
        }
    }()
    fn()
}

func main() {
    safeCall(func() {
        fmt.Println("начало")
        panic("сбой")
    })
    fmt.Println("программа продолжает работу")
}
```
**Вывод:**
```
начало
panic пойман: сбой
программа продолжает работу
```

# <font color="#ff0000">Defer</font> и ресурсы

Главное назначение `defer` — **гарантировать освобождение ресурсов**, даже при ошибках или панике.

**Пример:**
```go
func readFile(name string) {
    f, err := os.Open(name)
    if err != nil {
        panic(err)
    }
    defer f.Close() // закроется даже при panic

    buf := make([]byte, 64)
    _, err = f.Read(buf)
    if err != nil {
        panic(err)
    }
    fmt.Println(string(buf))
}
```

**Разбор:**
- `defer f.Close()` регистрирует закрытие файла.
- Даже если позже произойдёт `panic`, файл всё равно закроется.
- Это делает `defer` мощным инструментом для **безопасного управления ресурсами**.
