# Что такое <font color="#ff0000">Go Modules</font>

Когда проект становится чуть больше “Hello, World”, в нём появляются зависимости — другие [[1.5.1. Пакеты и зависимости|пакеты]], которые ты подключаешь.

Например, библиотека для красивого вывода текста, работы с JSON или запросов к API.

📦 **Go Modules (или просто go mod)** — это инструмент, который помогает:
- подключать внешние библиотеки;
- сохранять их версии;
- не ломать проект при обновлениях;
- воспроизводить ту же сборку на любом компьютере.

---
# Как это было раньше (и почему стало проще)?

Раньше [[1.1.0. Go Basics|Go]] требовал хранить проекты в папке `$GOPATH` и вручную тянуть все зависимости.

Теперь каждый проект — **самодостаточный модуль**, живущий где угодно (на рабочем столе, в GitHub и т.д.), и внутри него есть файлы:
- `go.mod` — список зависимостей и их версий
- `go.sum` — контрольные суммы (о нём чуть позже)

---
# Создание нового модуля

Создадим папку проекта и инициализируем модуль:
```bash
mkdir myproject
cd myproject
go mod init myproject
```
После этого появится файл:
```go
module myproject
go 1.23
```
🧠 Что это значит:
- `module myproject` — имя твоего модуля (как «название пакета»);
- `go 1.23` — версия языка [[1.1.0. Go Basics|Go]], под которую всё собрано.

# Подключаем первую зависимость

Допустим, ты хочешь использовать библиотеку [`github.com/fatih/color`](https://pkg.go.dev/github.com/fatih/color) для вывода цветного текста.

Создай файл `main.go`:
```go
package main
import (
    "fmt"
    "github.com/fatih/color"
)
func main() {
    color.Green("Привет, Go!")
    fmt.Println("Это обычный текст")
}
```
Теперь в консоли выполни:
```bash
go mod tidy
```
🪄 Что делает команда:
1. Находит все импорты в коде (`github.com/fatih/color`);
2. Скачивает нужную библиотеку;
3. Добавляет запись в `go.mod`;
4. Создаёт (или обновляет) файл `go.sum`.

#### Что появится в go.mod:
```go
module myproject
go 1.23
require github.com/fatih/color v1.16.0
```
💡 Здесь `require` показывает, какие библиотеки нужны проекту и какую версию Go выбрал.

# Что такое ~ <font color="#ff0000">go.sum</font> ~ и зачем он нужен

Когда Go скачивает внешние зависимости, он проверяет, **что они не были изменены** (например, не подменены кем-то).

Для этого создаётся файл **`go.sum`** — там Go хранит контрольные суммы (`hash`) всех зависимостей.

Пример:
```
github.com/fatih/color v1.16.0 h1:U1bqv8W/...
github.com/mattn/go-colorable v0.1.13 h1:0wzW...
github.com/mattn/go-isatty v0.0.20 h1:2zDU+8...
```
🧠 Простыми словами:
- `go.mod` говорит: “Вот список библиотек и их версии”.
- `go.sum` говорит: “Вот контрольные коды, чтобы убедиться, что они не изменились”.

Если ты передашь проект коллеге, `go.sum` гарантирует, что он соберёт **точно ту же версию**.

---
# Про ~ <font color="#ff0000">go sum</font> ~ кратко:

#### Проблема, которую решает `go.sum`:
Когда ты устанавливаешь внешнюю библиотеку (например, `github.com/fatih/color`), Go скачивает её **из интернета** — обычно с GitHub.

И вот тут <u>возникает риск</u>:
- кто-то может <u>изменить код</u> этой библиотеки в будущем;
- библиотека <u>может быть взломана</u>;
- ты можешь <u>случайно обновить её на другую версию </u>без контроля.

В результате твой проект, который вчера работал, **вдруг начнёт вести себя по-другому** — хотя ты ничего не менял.

---
# Что делает ~ <font color="#ff0000">go.mod</font> ~

`go.mod` <u>хранит список зависимостей и их версии</u>:
```go
module myproject
go 1.23
require github.com/fatih/color v1.16.0
```
То есть:
> “Мне нужна библиотека color версии v1.16.0”.

Но что, если автор этой библиотеки **удалит тег** `v1.16.0` и создаст новый — с тем же номером, но другим содержимым?

[[1.1.0. Go Basics|Go]] тогда скачает **другой код**, а ты даже не узнаешь об этом.

#### 💾 И вот тут появляется `go.sum`:
`go.sum` — это **страховка**.
Он хранит **контрольные суммы (hash)** для каждой скачанной зависимости.

Хэш — это короткий цифровой «отпечаток» файла.
Если библиотека изменится хоть на один байт, хэш тоже изменится.
#### Пример:
Допустим, у тебя в `go.sum` записано:
```
github.com/fatih/color v1.16.0 h1:U1bqv8W/abc123...
```
Когда Go скачивает библиотеку `color v1.16.0`, он проверяет:
> “Совпадает ли реальный хэш скачанного кода с тем, что записан в go.sum?”
- ✅ Если совпадает — всё хорошо, библиотека подлинная.
- ❌ Если не совпадает — Go выдаст ошибку и **не даст собрать проект**.

#### Пример вживую:
Попробуй:
```bash
go mod tidy
```
После этого появится `go.sum`.

Если ты **удалишь** библиотеку из кэша и заново запустишь `go mod verify`, Go сравнит хэши:
```bash
go mod verify
```
Результат будет примерно такой:
```
all modules verified
```
А если какая-то зависимость была изменена или повреждена — появится ошибка вроде:
```
verifying github.com/fatih/color@v1.16.0: checksum mismatch
```

#### Таким образом:
- `go.mod` — это **список нужных библиотек и их версий**;
- `go.sum` — это **доказательство, что ты используешь именно тот код**, который был скачан при прошлой установке.
Go **не доверяет версиям на словах** — он проверяет по факту:
если код не совпадает, он просто откажется собирать проект.

# Добавляем зависимости <u>вручную</u>

Иногда нужно добавить зависимость, не изменяя код.
Для этого есть команда `go get`.

Пример:
```bash
go get github.com/gorilla/mux@latest
```
Она:
1. Скачает пакет;
2. Добавит его в `go.mod`;
3. Пересчитает `go.sum`.

После этого можно сразу использовать:
```go
import "github.com/gorilla/mux"
```

---
# <u>Обновление и очистка зависимостей</u>

Когда проект растёт, список пакетов быстро меняется.
Чтобы поддерживать порядок, есть несколько команд:

|Команда|Что делает|
|---|---|
|`go mod tidy`|Добавляет недостающие и удаляет неиспользуемые|
|`go get -u`|Обновляет все зависимости до новых версий|
|`go get -u=patch`|Только мелкие обновления (без новых фич)|
|`go mod verify`|Проверяет целостность `go.sum`|
|`go list -m all`|Показывает все зависимости|

# Что такое ~ <font color="#ff0000">vendor</font> ~ и зачем он нужен

По умолчанию [[1.1.0. Go Basics|Go]] хранит все скачанные пакеты в кэше:
📁 `~/go/pkg/mod`
(это общая папка для всех проектов).

Но иногда — например, на продакшн-серверах без интернета — нужно, чтобы **всё лежало в проекте**.
Тогда создаётся папка `vendor`, в которую Go копирует все зависимости.

Сделать это просто:
```bash
go mod vendor
```
Теперь можно собрать проект так:
```bash
go build -mod=vendor
```
Go возьмёт библиотеки **из локальной папки**, а не из интернета.

# Создание собственного модуля

Теперь допустим, ты хочешь написать **свою библиотеку**, которую смогут подключать другие.
#### Шаг 1. <u>Создай модуль</u>:
```bash
mkdir mathutils
cd mathutils
go mod init github.com/username/mathutils
```
**Пошагово:**
`mkdir mathutils` — создаём папку проекта с именем **mathutils**.  
`cd mathutils` — переходим внутрь папки проекта, все последующие команды будут выполняться здесь.  
`go mod init` — инициализирует **модуль Go** в текущей папке.

#### Шаг 2. <u>Добавь код</u>:
`sum.go`:
```go
package mathutils
func Sum(a, b int) int {
    return a + b
}
```

#### Шаг 3. <u>Опубликуй в GitHub</u>:
1. Создай новый репозиторий с тем же именем (`github.com/username/mathutils`);
2. Загрузить туда код:
```go
git add . //Добавляем все файлы в индекс git
git commit -m "first release" //Создаём коммит с сообщением "first release" — это «снимок» текущего состояния кода.
git push origin main //Отправляем коммит(ы) в удалённый репозиторий origin (это GitHub), в ветку main.
```
3. Создай тег (версию):
```go
git tag v1.0.0 //Создаём git-тег v1.0.0 — метка версии по SemVer
git push origin v1.0.0 //Публикуем тег в GitHub. Теперь версия v1.0.0 доступна всем    
```

**Теперь любую программу можно собрать с твоим пакетом:**
```bash
go get github.com/username/mathutils@v1.0.0
```

---
# Как выпускать новые версии
- `v1.0.0` → первая стабильная версия
- `v1.1.0` → добавлены функции
- `v1.1.1` → исправлены ошибки

Новая версия публикуется просто:
```bash
git tag v1.1.0
git push origin v1.1.0
```
Если ты делаешь **v2 и выше**, нужно добавить суффикс `/v2` в `go.mod`:
```go
module github.com/username/mathutils/v2
```
И импортировать так:
```go
import "github.com/username/mathutils/v2"
```
