# Зачем нужны пакеты ~ <font color="#ff0000">package</font> ~

Когда проект становится больше, чем один файл, код быстро превращается в кашу.

Представь, если бы всё приложение было написано в одном `.go` файле — десятки функций, структур и логики вперемешку.

Чтобы не утонуть в этом хаосе, [[1.1.0. Go Basics|Go]] предлагает **пакеты (packages)** — это способ **организовать код по смыслу**.

**Пакет** — это просто **папка с Go-файлами**, которые объединены общей задачей.

Например:
```
project/
 ├── main.go          # Точка входа
 ├── user/
 │    └── user.go     # Логика работы с пользователями
 ├── auth/
 │    └── auth.go     # Авторизация
 └── utils/
      └── strings.go  # Утилиты, вспомогательные функции
```

#### Как работает импорт?
Каждый файл начинается с объявления, к какому пакету он относится.

Например, создадим пакет **`user`**, который будет отвечать за работу с пользователями:
#### 📄 `user/user.go`
```go
package user
type User struct {
    Name string
}
// Экспортируемая функция (с заглавной буквы)
func New(name string) User {
    return User{Name: name}
}
```
Здесь:
- `package user` — объявляем, что этот файл принадлежит пакету `user`;
- `User` и `New` — экспортируемые (публичные), потому что начинаются с **заглавной буквы**;
- функция `New` возвращает структуру `User`.
#### `main.go`
```go
package main
import (
    "fmt"
    "project/user"
)
func main() {
    u := user.New("Alice")
    fmt.Println(u.Name)
}
```
Что происходит:
- Мы импортируем пакет `"project/user"`;
- Вызываем **экспортируемую** функцию `user.New`;
- Получаем экземпляр структуры `User`.

Вывод программы:
```
Alice
```

# Экспортируемые и неэкспортируемые элементы

Go использует **регистр букв** вместо ключевых слов `public/private`.

| Пример             | Видимость | Комментарий                |
| ------------------ | --------- | -------------------------- |
| `func PrintName()` | Публичная | Доступна из других пакетов |
| `func printName()` | Приватная | Только внутри пакета       |
Это простое, но мощное правило помогает держать код “чистым” и не засорять глобальное пространство.

# Встроенные и внешние зависимости

<u>В Go есть два типа зависимостей</u>:
1. **Встроенные (стандартная библиотека)**
    Например, `fmt`, `net/http`, `time`. Они идут “из коробки” и не требуют установки.
2. **Внешние (через go mod)**
    Это сторонние библиотеки, например:
```bash
go get github.com/gorilla/mux
```
    После этого Go скачает пакет в кеш и добавит запись в `go.mod`.

---
# Пакет ~ <font color="#ff0000">main</font> ~

Это особый пакет — точка входа программы.
В нём обязательно должна быть функция:
```go
package main
func main() {
    // программа стартует здесь
}
```
<u>Все остальные пакеты — это модули</u>, которые ты подключаешь к `main` или друг к другу.

---
# Практический пример

Создадим простую структуру:
```
calculator/
 ├── go.mod
 ├── main.go
 └── math/
      └── math.go
```
`math/math.go`:
```go
package math
func Add(a, b int) int {
    return a + b
}
```
`main.go`:
```go
package main
import (
    "fmt"
    "calculator/math"
)
func main() {
    result := math.Add(2, 3)
    fmt.Println("Результат:", result)
}
```
Запусти:
```bash
go run .
```
Вывод:
```
Результат: 5
```

---
# Что происходит под капотом
1. Go находит `go.mod` — определяет, где “корень” проекта.
2. Из `import "calculator/math"` понимает, что пакет находится в папке `math`.
3. Компилирует оба пакета и связывает их в один исполняемый файл.
