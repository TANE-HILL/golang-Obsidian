# Зачем нужен ~ <font color="#ff0000">Context</font> ~

**Когда [[1.6.1. HTTP-сервер|сервер]] обрабатывает HTTP-запрос, он может выполнять долгие действия:**
- ждать ответ от базы данных;
- получать данные из внешнего API;
- выполнять длительные вычисления.

Если клиент закроет вкладку или соединение прервётся, сервер **должен прекратить все связанные операции**, чтобы не расходовать зря процессорное время и память.

**Для этого в Go есть специальный механизм — `context.Context`.**


# Как работает ~ <font color="#ff0000">Context</font> ~

**Контекст** — это объект, который “живёт” ровно столько, сколько **живёт сам запрос**.
Когда запрос завершился (успешно или нет) — контекст **автоматически закрывается**.

Каждый `http.Request` в Go уже содержит свой контекст:
```go
ctx := r.Context()
```

Из него можно:
- узнать, **отменён ли запрос** (`<-ctx.Done()`);
- получить **ошибку** отмены (`ctx.Err()`);
- **передать значения** между функциями (например, userID, traceID);
- задать **таймаут** или **дедлайн** выполнения.

---
#### <u>Без контекста</u>:
```go
func handleSlow(w http.ResponseWriter, r *http.Request) {
    fmt.Println("Начали обработку запроса")

    // Долго выполняем (например, обращаемся к внешнему API)
    time.Sleep(5 * time.Second)

    fmt.Fprintln(w, "Обработка завершена")
}
```
- **Если клиент закроет вкладку** — сервер **всё равно “доспит” 5 секунд**;
- **Горутин становится больше**, память расходуется зря.

#### <u>С контекстом</u>:
```go
func handleSlow(w http.ResponseWriter, r *http.Request) {
    ctx := r.Context()
    fmt.Println("Начали обработку запроса")

    select {
    case <-time.After(5 * time.Second):
        fmt.Fprintln(w, "Обработка завершена")
    case <-ctx.Done():
        fmt.Println("⛔ Запрос отменён клиентом:", ctx.Err())
        return
    }
}
```
- `r.Context()` **даёт контекст запроса**;
- `ctx.Done()` — канал, который **закрывается, если клиент разорвал соединение**;
- `select` **позволяет “реагировать” на отмену, не дожидаясь конца** `time.After`.

---
#### **<u>Таймаут</u> (timeout)** — это ограничение по времени.

Если операция **не закончилась за заданный период** — она **прерывается** с ошибкой `context deadline exceeded`.

#### <u>Без таймаута</u>:
```go
ctx := context.Background() // обычный контекст без ограничений
time.Sleep(3 * time.Second)
fmt.Println("Готово")
```
- Даже если что-то зависло — программа будет ждать “вечно”.

#### <u>C таймаутом</u>:
```go
ctx, cancel := context.WithTimeout(context.Background(), 2*time.Second)
defer cancel() // обязательно, чтобы освободить ресурсы таймера

select {
case <-time.After(3 * time.Second): // имитация долгой работы
    fmt.Println("✅ Задача завершена")
case <-ctx.Done(): // сработал таймаут (или отмена)
    fmt.Println("⏰ Время вышло:", ctx.Err())
}
```
1. Создали контекст с таймаутом 2 секунды.
2. Подождали: либо “работа” закончится через 3с, либо контекст даст сигнал `Done()`.
3. Раньше сработает таймаут → ветка `ctx.Done()` → `context.DeadlineExceeded`.

#### <u>Вывод</u>:
```Run
⏰ Время вышло: context deadline exceeded
```
- Теперь программа ждёт максимум 2 секунды — и останавливается.

#### <u>Зачем конструкция select</u>?

`select` — это способ “подождать первое из нескольких событий”.
_Реагируем на то, что случится раньше._
```go
select {
case <-doWork:           // работа завершилась
    fmt.Println("Готово")
case <-ctx.Done():       // пришёл сигнал отмены/таймаута
    fmt.Println("Остановились:", ctx.Err())
}
```
- `ctx.Done()` — **канал**. Он закрывается, когда контекст **отменён** или **вышел по таймауту/дедлайну**.
- `ctx.Err()` — **почему** отменили:
    - `context.Canceled` — отменили вручную или клиент закрыл соединение;
    - `context.DeadlineExceeded` — сработал таймаут/дедлайн.

#### <u>Что такое context.Background()</u>?

Это “чистый лист” — базовый, **никем не управляемый** контекст.
Его используют как **корень** дерева контекстов, когда вы создаёте новый (через `WithCancel/WithTimeout/WithValue`).

В HTTP-хендлерах **обычно не нужен** `Background()`, потому что у вас уже есть `r.Context()` — контекст **конкретного запроса**.

# Виды контекста в Go

**Контекст** — это инструмент, который управляет временем жизни операций.

В [[1.1.0. Go Basics|Go]] есть несколько функций, которые создают **разные типы контекста** — в зависимости от того, как именно ты хочешь управлять процессом.

| <u>Функция</u>                     | <u>Что делает</u>                          | <u>Когда применять</u>                                |
| ---------------------------------- | ------------------------------------------ | ----------------------------------------------------- |
| `context.Background()`             | **Создаёт базовый “пустой” контекст**          | Используется как корень (в `main`, тестах и примерах) |
| `context.WithCancel(ctx)`          | **Позволяет отменить выполнение вручную**      | Когда нужно иметь кнопку “Стоп”                       |
| `context.WithTimeout(ctx, d)`      | **Отменяет контекст по таймауту (через `d`)**  | Чтобы не ждать бесконечно                             |
| `context.WithDeadline(ctx, t)`     | **То же, но указываем точное время окончания** | Когда дедлайн приходит извне                          |
| `context.WithValue(ctx, key, val)` | **Добавляет данные (например, userID)**        | Для передачи метаданных запроса                       |

---

# 1. <u>Отмена вручную</u> ~ <font color="#ff0000">context.WithCancel</font> ~

Код запускает горутину и нужно иметь способ **аккуратно завершить** её работу.

```go
package main

import (
    "context"
    "fmt"
    "time"
)

func main() {
    parent := context.Background()              // базовый контекст
    ctx, cancel := context.WithCancel(parent)   // контекст, который можно отменить

    // эмулируем длительную работу
    go func() {
        time.Sleep(500 * time.Millisecond)
        cancel() // вручную отправляем сигнал отмены
    }()

    select {
    case <-time.After(2 * time.Second): // “работа” длилась бы 2 секунды
        fmt.Println("✅ Работа завершена")
    case <-ctx.Done(): // получили сигнал отмены
        fmt.Println("⛔ Остановлено вручную:", ctx.Err())
    }
}
```
- `context.WithCancel(parent)` — создаёт копию контекста, которую можно **остановить** с помощью `cancel()`;
- `cancel()` — отправляет сигнал всем, кто слушает `ctx.Done()`;
- `ctx.Done()` — канал, который закрывается, когда контекст отменён;
- `ctx.Err()` — показывает причину (`context.Canceled`).

#### Вывод:
```
⛔ Остановлено вручную: context canceled
```

#### Применять когда:
- нужно вручную завершить работу фоновой горутины;
- при остановке сервера или отмене цепочки задач.

---
# <u>2. Ограничение по времени</u> ~ <font color="#ff0000">context.WithTimeout</font> ~

**Автоматически прервать операцию** через заданное время.

```go
package main

import (
    "context"
    "fmt"
    "time"
)

func main() {
    ctx, cancel := context.WithTimeout(context.Background(), 1*time.Second)
    defer cancel() // важно, чтобы освободить ресурсы

    select {
    case <-time.After(1500 * time.Millisecond): // “работа” длится дольше таймаута
        fmt.Println("✅ Успели вовремя")
    case <-ctx.Done(): // таймаут сработал
        fmt.Println("⏰ Не успели:", ctx.Err())
    }
}
```
- `context.WithTimeout` создаёт контекст, который **сам отменится через 1 секунду**;
- `defer cancel()` обязательно вызывает освобождение ресурсов таймера;
- `ctx.Done()` сработает, когда выйдет таймаут;
- `ctx.Err()` вернёт `context.DeadlineExceeded`.

#### Вывод:
```
⏰ Не успели: context deadline exceeded
```

#### Применять когда:
- при запросах к внешним сервисам или БД;
- при обработке HTTP-запросов, где нужно задать максимальное время выполнения.

---
# <u>3. До конкретного времени</u> ~ <font color="#ff0000">context.WithDeadline</font> ~

Иногда важна **не длительность**, а **точный момент**, когда работа должна завершиться.

*Например, “всё должно закончиться к 12:00:00”:*
```go
package main

import (
    "context"
    "fmt"
    "time"
)

func main() {
    deadline := time.Now().Add(750 * time.Millisecond) // дедлайн через 0.75 секунды
    ctx, cancel := context.WithDeadline(context.Background(), deadline)
    defer cancel()

    <-ctx.Done() // ждём, пока дедлайн не наступит
    fmt.Println("🕓 Сработал дедлайн:", ctx.Err())
}
```
- `WithDeadline` создаёт контекст, который **автоматически отменится в заданное время**;
- `ctx.Done()` закроется, когда наступит дедлайн;
- `ctx.Err()` снова покажет `context.DeadlineExceeded`.

#### Вывод:
```
🕓 Сработал дедлайн: context deadline exceeded

```

#### Применять когда:
- когда общий дедлайн передаётся из внешней системы (например, общий таймаут API-запроса).

---

# <u>4. Передача метаданных</u> ~ <font color="#ff0000">context.WithValue</font> ~

Контекст можно использовать не только для отмены, но и для **передачи мелких данных**, связанных с конкретным запросом.

*Например, ID пользователя, trace ID или локаль.*

```go
package main

import (
    "context"
    "fmt"
)

type ctxKey string

const requestIDKey ctxKey = "requestID"

func main() {
    // создаём контекст с дополнительным значением
    ctx := context.WithValue(context.Background(), requestIDKey, "req-123")

    // передаём дальше в функцию
    logWithID(ctx)
}

func logWithID(ctx context.Context) {
    id, _ := ctx.Value(requestIDKey).(string)
    fmt.Println("📦 RequestID:", id)
}
```
- `context.WithValue()` создаёт новый контекст, добавляя в него значение;
- `ctx.Value(key)` возвращает значение по ключу;
- тип ключа (`ctxKey`) лучше объявить самостоятельно, чтобы избежать конфликтов;
- такие данные доступны во всех функциях, куда передаётся этот контекст.

#### Вывод:
```
📦 RequestID: req-123
```

#### Применять когда:
- `WithValue` — не способ передавать бизнес-данные (например, задачи или пользователей). Он используется **только для метаданных** (requestID, userID, language и т.п.).

---
# РЕЗЮМЕ по видам контекста

| <u>Вид контекста</u> | <u>Что делает</u>              | <u>Пример использования</u>          |
| -------------------- | ------------------------------ | ------------------------------------ |
| `WithCancel`         | **Отмена вручную**             | *Управление фоновой горутиной*       |
| `WithTimeout`        | **Отмена по времени**          | *HTTP-запрос, ожидание ответа от БД* |
| `WithDeadline`       | **Отмена к заданному моменту** | *Глобальные дедлайны API*            |
| `WithValue`          | **Передача данных**            | *userID, traceID, локаль*            |
| `ContextBackground`  | **Создание пустого контекста** | *Базовый корневой контекст*          |

# Контекст в реальных проектах

Context используется:
- в HTTP-серверах: `r.Context()`;
- в запросах к базе: `db.QueryContext(ctx, ...)`;
- при вызове внешних API;
- при управлении горутинами;
- в worker-процессах (чтобы завершать задачи при остановке приложения).

# Добавление ~ <font color="#ff0000">Context</font> ~ в проект Task Manager

#### <u>1. Новый обработчик</u> `HandleSlowTask`

Этот обработчик будет **имитировать долгую задачу** (например, работу с внешним API). Если клиент закроет вкладку — сервер **автоматически остановит выполнение**.

**`handlers/tasks.go` (новая функция в конце):**
```go
package handlers

import (
    "context"
    "fmt"
    "net/http"
    "time"
)

// HandleSlowTask — пример обработки долгого запроса.
// Он показывает, как сервер реагирует на отмену запроса клиентом.
func HandleSlowTask(w http.ResponseWriter, r *http.Request) {
    // Получаем контекст запроса (живет столько же, сколько и соединение)
    ctx := r.Context()

    fmt.Println("🕓 Начали долгую обработку запроса...")

    // Используем select, чтобы реагировать на два исхода:
    // 1) работа завершится успешно
    // 2) клиент закроет соединение
    select {
    case <-time.After(5 * time.Second): // имитация долгой работы
        w.WriteHeader(http.StatusOK)
        w.Write([]byte("✅ Задача выполнена"))
    case <-ctx.Done(): // клиент отменил запрос
        fmt.Println("⛔ Клиент прервал запрос:", ctx.Err())
        return
    }
}
```
##### Построчно:
- `ctx := r.Context()` - Берём контекст текущего запроса;
- `time.After(5 * time.Second)` - Симулируем долгую операцию;
- `select` - Ждём, что произойдёт первым;
- `<-ctx.Done()` - Канал, который закрывается, если клиент прервал запрос;
- `ctx.Err()` - Возвращает причину отмены (например, `context.Canceled`).

#### <u>2. Подключаем маршрут в</u> `main.go`

Теперь нужно добавить новый путь `/slow`, чтобы можно было протестировать поведение сервера с контекстом.

**`main.go`:**
```go
package main

import (
    "fmt"
    "net/http"
    "taskmanager/handlers"
)

func main() {
    mux := http.NewServeMux()

    // Основные маршруты для задач
    mux.HandleFunc("/tasks", handlers.TasksHandler)
    mux.HandleFunc("/tasks/", handlers.TaskByIDHandler)

    // Новый маршрут для демонстрации контекста
    mux.HandleFunc("/slow", handlers.HandleSlowTask)

    fmt.Println("Сервер запущен на <http://localhost:8080>")
    http.ListenAndServe(":8080", mux)
}
```
##### Пояснение:
- Мы просто добавили новый путь `/slow` к маршрутам;
- Остальные обработчики (`/tasks`, `/tasks/{id}`) **остались без изменений**;
- Этот путь нужен **только для демонстрации работы контекста** —
    в реальных проектах контекст встроен прямо в обычные обработчики.

#### <u>3. Проверка</u>

**Запуск сервера в консоли:**
```bash
go run main.go
```

**Запрос:**
```bash
curl <http://localhost:8080/slow>
```

**Быстрая остановка команды - `Ctrl+C`, вывод в консоли:**
```

⛔ Клиент прервал запрос: context canceled
```

**Сервер получил сигнал отмены до завершения *"обработки"* и прекратил работу.**

#### <u>4. Таймаут на уровне сервера</u>

Добавляем в обработчик **таймаут** (например, 2 секунды).
Если операция занимает дольше — сервер сам её остановит.

**`handlers/tasks.go` (обработчик `HandleSlowTask`):**
```go
// HandleSlowTask — пример долгого запроса с таймаутом.
func HandleSlowTask(w http.ResponseWriter, r *http.Request) {
    // Создаём контекст с таймаутом 2 секунды
    ctx, cancel := context.WithTimeout(r.Context(), 2*time.Second)
    defer cancel() // важно: освободить ресурсы таймера

    fmt.Println("🕓 Начали долгую обработку запроса (с таймаутом)...")

    // Ждём: или операция завершится, или сработает таймаут
    select {
    case <-time.After(5 * time.Second): // имитация долгой работы
        w.WriteHeader(http.StatusOK)
        w.Write([]byte("✅ Задача выполнена"))
    case <-ctx.Done(): // контекст отменён (таймаут или клиент закрыл соединение)
        w.WriteHeader(http.StatusGatewayTimeout)
        w.Write([]byte("⏰ Таймаут: операция заняла слишком много времени"))
        fmt.Println("⛔ Работа прервана:", ctx.Err())
        return
    }
}
```
##### Пояснение:
- **`context.WithTimeout(r.Context(), 2*time.Second)`**
	*Создаёт новый контекст, который живёт максимум 2 секунды*
- **`defer cancel()`**
	*Освобождает ресурсы таймера даже при раннем выходе*
- **`<-ctx.Done()`**
	*Срабатывает, если истёк таймаут или клиент закрыл соединение*
- **`ctx.Err()`**
	*Показывает причину — `context.DeadlineExceeded` или `context.Canceled`*

#### <u>5. Проверка таймаут</u>

**Запрос в консоли:**
```bash
curl <http://localhost:8080/slow>
```

**Через 2 секунды ответ:**
```
⏰ Таймаут: операция заняла слишком много времени
```

**В логах сервера:**
```
🕓 Начали долгую обработку запроса (с таймаутом)...
⛔ Работа прервана: context deadline exceeded
```
