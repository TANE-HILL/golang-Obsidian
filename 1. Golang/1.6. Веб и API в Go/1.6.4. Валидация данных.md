
# Зачем нужна валидация данных

<u>Проблема</u>: клиент может отправить **что угодно**:
- пустое поле, невалидный JSON, пропущенный параметр или даже совсем другой формат.

Без проверки твой сервер просто “поверит” входящим данным и может:
- записать “пустую” задачу;
- упасть с ошибкой при обращении к `nil`;
- вернуть бессмысленные данные в ответ.

Пример некорректного запроса:
```JSON
{
  "title": ""
}
```

<u>Решение</u>: добавить валидацию.

---
# Валидация в проекте <font color="#ff0000">Task Manager</font>

#### 1. Базовая логика валидации на ~ <font color="#ff0000">if</font> ~

Фрагмент обработчика `createTask`:
```Go
var newTask Task

if err := json.NewDecoder(r.Body).Decode(&newTask); err != nil {
    http.Error(w, "Невалидный JSON", http.StatusBadRequest)
    return
}

if newTask.Title == "" {
    http.Error(w, "Поле 'title' обязательно для заполнения", http.StatusBadRequest)
    return
}
```
#### <u>Разбор построчно</u>:
- `Decode` пытается распарсить JSON из тела запроса;
- если JSON повреждён — сразу возвращаем `400 Bad Request`;
- если поле `title` пустое — тоже `400`, с понятным сообщением.

#### 2. Вынос валидации в отдельную функцию

Чтобы не дублировать проверку в `createTask`, `updateTask` и т.д., создаём новую функцию в `utils/validation.go`:
```Go
func validateTask(t Task) error {
    if t.Title == "" {
        return errors.New("поле 'title' не может быть пустым")
    }
    return nil
}
```

Теперь так выглядит `createTask`:
```Go
func createTask(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodPost {
        http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
        return
    }

    var newTask Task
    if err := json.NewDecoder(r.Body).Decode(&newTask); err != nil {
        http.Error(w, "Невалидный JSON", http.StatusBadRequest)
        return
    }

    // ✅ Теперь просто вызываем функцию проверки
    if err := validateTask(newTask); err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    newTask.ID = len(tasks) + 1
    tasks = append(tasks, newTask)

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusCreated)
    json.NewEncoder(w).Encode(newTask)
}
```

# Единый формат ошибок

Пока мы использовали `http.Error()`, ошибки выглядели как обычный текст:
```go
http.Error(w, "Поле 'title' не может быть пустым", http.StatusBadRequest)
```

<u>Это работает, но</u>:
- ответ не в JSON;
- формат отличается от успешных ответов;
- фронтенду сложно обрабатывать ошибки программно.

Чтобы всё выглядело единообразно, создадим **структуру для ошибок** и **вспомогательную функцию**, которая будет отправлять их в JSON-формате.

#### В `utils/validation.go` добавим функцию `writeError`:
```Go
package utils

import (
    "encoding/json"
    "errors"
    "net/http"
)

func ValidateTask(t Task) error {
    if t.Title == "" {
        return errors.New("поле 'title' не может быть пустым")
    }
    return nil
}

type ErrorResponse struct {
    Error string `json:"error"`
}

func WriteError(w http.ResponseWriter, code int, msg string) {
    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(code)
    json.NewEncoder(w).Encode(ErrorResponse{Error: msg})
}
```
- `validateTask` - проверяет данные;
- `writeError` - отправляет ошибки в едином формате.
W
Теперь любая ошибка возвращается в таком виде:
```JSON
{"error": "поле 'title' не может быть пустым"}
```

## Как меняется код

**Было**:
```Go
if err := validateTask(newTask); err != nil {
    http.Error(w, err.Error(), http.StatusBadRequest)
    return
}
```
**Стало**:
```Go
if err := validateTask(newTask); err != nil {
    utils.writeError(w, http.StatusBadRequest, err.Error())
    return
}
```
#### ◼︎ Теперь клиент всегда получает JSON с полем `error`.


# Обновляем обработчик `createTask`

Итоговый вариант:
```Go
func createTask(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodPost {
        writeError(w, http.StatusMethodNotAllowed, "Метод не поддерживается")
        return
    }

    var newTask Task
    if err := json.NewDecoder(r.Body).Decode(&newTask); err != nil {
        utils.writeError(w, http.StatusBadRequest, "Невалидный JSON")
        return
    }

    if err := validateTask(newTask); err != nil {
        utils.writeError(w, http.StatusBadRequest, err.Error())
        return
    }

    newTask.ID = len(tasks) + 1
    tasks = append(tasks, newTask)

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusCreated)
    json.NewEncoder(w).Encode(newTask)
}
```

## Добавляем ту же проверку в обновление задачи

Чтобы при изменении задачи нельзя было отправить пустое название,

вставляем ту же проверку в `updateTask`:

```go
if err := utils.ValidateTask(updated); err != nil {
    utils.WriteError(w, http.StatusBadRequest, err.Error())
    return
}
```

Эту строчку нужно вставить **после** декодирования JSON и **до** обновления задачи в списке.

Так валидация будет работать одинаково при создании и при редактировании.
