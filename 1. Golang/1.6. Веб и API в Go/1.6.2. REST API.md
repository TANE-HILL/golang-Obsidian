# Зачем нужен ~ <font color="#ff0000">REST API</font> ~

Когда приложение (например, мобильное или фронтенд-веб) хочет общаться с [[1.6.1. HTTP-сервер|сервером]] — ему нужен **понятный интерфейс обмена данными**.

Таким интерфейсом и является
**API** _(Application Programming Interface)_.

**REST** _(Representational State Transfer)_ — это **архитектурный стиль** организации такого интерфейса.

Он определяет, _как клиент и сервер должны взаимодействовать_ с помощью HTTP.

# Основная идея ~ <font color="#ff0000">REST</font> ~

REST использует обычные [[1.6.1. HTTP-сервер|HTTP]]-механизмы, но с чёткими правилами:
- данные разделяются на **ресурсы** (например, `users`, `tasks`, `orders`);
- каждый ресурс имеет свой **URL-путь** (`/users`, `/users/1`, `/tasks/5`);
- действие выбирается **HTTP-методом** (`GET`, `POST`, `PUT`, `DELETE`);
- ответы имеют понятные **статус-коды** (`200`, `201`, `404`, `400`);
- обмен идёт чаще всего в формате **JSON**.

#### Пример из жизни:

> Представь: ты пишешь менеджер задач (Task Manager).
> Тогда API можно спроектировать так:

| <u>Действие</u>          | <u>Метод</u> | <u>Путь</u>   | <u>Описание</u>    |
| ------------------------ | ------------ | ------------- | ------------------ |
| **Получить все задачи**  | `GET`        | `/tasks`      | *Вернуть список*     |
| **Получить одну задачу** | `GET`        | `/tasks/{id}` | *Вернуть по ID*      |
| **Создать задачу**       | `POST`       | `/tasks`      | *Добавить новую*     |
| **Обновить задачу**      | `PUT`        | `/tasks/{id}` | *Полностью обновить* |
| **Удалить задачу**       | `DELETE`     | `/tasks/{id}` | *Удалить*            |

# Почему [[1.1.0. Go Basics|Go]] удобен для <u>REST</u>

- **`net/http`** — запускает сервер и принимает запросы.
- **`encoding/json`** — читает и пишет JSON.

> Этих двух пакетов достаточно, чтобы сделать рабочий REST API.

5. **Запуск сервера** — Go-программа, слушающая `localhost:8080`.

# **➊ Модель данных**

Каждая задача в нашем приложении должна иметь:
- уникальный номер (ID),
- название (Title),
- и статус — выполнена или нет (Done).

Всё это можно описать в виде структуры [[1.1.0. Go Basics|Go]].

Создадим новый файл:
```
project/
 └── models/
      └── task.go
```
В этом файле будет находиться **описание нашей модели** (структуры `Task`).

#### 📄 `models/task.go`:
```go
type Task struct {
    ID    int    `json:"id"`
    Title string `json:"title"`
    Done  bool   `json:"done"`
}
```

**Построчно:**

- `package models` — имя пакета, совпадает с названием папки.
    Так Go понимает, что этот файл относится к части проекта, где хранятся модели данных.
- `type Task struct { ... }` — объявляем тип “Задача”.
- `ID int` — числовой идентификатор задачи.
- `Title string` — текст или заголовок задачи.
- `Done bool` — флаг, показывающий, выполнена задача (`true`) или нет (`false`).
- `json:"..."` — **теги**.
    Они нужны, чтобы при обмене данными с клиентом Go знал,
    как поля должны называться в JSON.
    Например, `Title` в коде превратится в `"title"` в JSON.

> 💡 Почему мы вынесли это в отдельный файл:
- модель данных часто используется в разных местах — и в обработчиках, и при работе с базой;
- если хранить её отдельно, код остаётся чистым и структурированным;
- потом можно легко добавить другие модели (например, `User`, `Project` и т.д.) в ту же папку `models`.

#### “База” в памяти (для примеров):
```go
var tasks = []Task{
    {ID: 1, Title: "Изучить Go", Done: true},
    {ID: 2, Title: "Написать первый сервер", Done: false},
}
```

**Построчно:**
- `var tasks = []Task{ ... }` — создаём срез (список) задач прямо в памяти.
- В реальном проекте тут будет база данных. Для понимания REST нам достаточно слайса.

# **➋ Обработчики**

Когда пользователь (или браузер, или Postman) обращается по адресу, например:
```
GET /tasks
```
сервер должен понять, что от него хотят, и вызвать соответствующую функцию, которая подготовит и отправит ответ.

Такая функция в Go называется **обработчиком** (_handler_).

<u>Обработчик</u> — это обычная функция Go, но с особой сигнатурой:
```go
func(w http.ResponseWriter, r *http.Request)
```
- `w` — (writer) то, **куда** сервер записывает ответ клиенту (тело, код, заголовки);
- `r` — (request) то, **что** прислал клиент (метод, путь, параметры, JSON и т.д.).

[[1.1.0. Go Basics|Go]] вызывает эту функцию **каждый раз**, когда приходит запрос на определённый путь.

То есть, если пользователь откроет `/tasks`, сработает один обработчик, а если `/tasks/1` — другой.

#### Где хранить обработчики?
Чтобы проект был аккуратным, создадим для них отдельную папку:
```
project/
 ├── main.go
 ├── handlers/
 │     └── tasks.go
 └── models/
       └── task.go
```

📄 `handlers/tasks.go`

#### Подключение пакета

В начале файла `handlers/tasks.go` нужно указать:
```go
package handlers

import (
    "encoding/json"
    "net/http"
)
```

Здесь мы говорим, что файл принадлежит пакету `handlers` и подключаем нужные стандартные библиотеки:
- **`net/http`** — чтобы работать с запросами и ответами;
- **`encoding/json`** — чтобы конвертировать данные Go в JSON.
#### **Обработчик**: получить все задачи (GET /tasks):
```go
func getTasks(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodGet {
        http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
        return
    }

    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(tasks)
}
```
#### **Разбор построчно:**
1. `func getTasks(w, r)` — создаём функцию-обработчик, которая реагирует на запрос.
2. Проверка метода:
```go
if r.Method != http.MethodGet {
    http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
    return
}
```
<u>Мы говорим серверу: </u>
*«Этот обработчик предназначен только для метода GET. Если клиент случайно отправит `POST` или `DELETE` — возвращаем ошибку `405 Method Not Allowed`..»*

3. Заголовки (`Header`):
```go
w.Header().Set("Content-Type", "application/json")
```
Каждый HTTP-ответ содержит **заголовки** — это “метаданные” о сообщении. То есть маленькие подсказки для клиента: _что я тебе отправляю и как это читать_.

`Content-Type` — один из самых важных заголовков.
Он говорит: **в каком формате содержится тело ответа**.
- Если сервер шлёт HTML → `text/html`
- Если отправляет изображение → `image/png`
- Если JSON → `application/json`

👉 **В нашем случае мы отправляем JSON, поэтому всегда перед записью данных в ответ устанавливаем этот заголовок.**

Почему только один заголовок?> 
> Потому что остальные (например, `Content-Length`, `Date`, `Server`) <u>Go добавляет сам</u>.
> `Content-Type` <u>нужно указать вручную</u> — клиент без него может не понять формат данных.

#### Кодирование данных в JSON:
```go
json.NewEncoder(w).Encode(tasks)
```
Вот тут происходит вся “магия”.
- `json.NewEncoder(w)` — создаёт **“кодировщик JSON”**, который пишет результат **прямо в ответ клиенту (в объект `w`)**.
- `.Encode(tasks)` — берёт нашу переменную `tasks` (список задач), **переводит её в JSON** и **отправляет в сеть**.

Go сам преобразует структуры и срезы в нужный JSON-формат, используя теги `json:"..."` из нашей модели `Task`.

#### Что реально отправляется клиенту?
В теле HTTP-ответа клиент получает вот такой JSON:
```json
[
  {"id":1, "title":"Изучить Go", "done":true},
  {"id":2, "title":"Написать первый сервер", "done":false}
]
```
Это не “текст внутри кода” — Go автоматически собрал JSON из наших структур и передал его браузеру или инструменту (Postman, curl и т.д.) по HTTP.
#### Что произошло по шагам:
1. Клиент делает запрос `GET /tasks`
2. Go вызывает нашу функцию `getTasks`
3. Функция проверяет, что метод — `GET`
4. Устанавливает заголовок `Content-Type: application/json`
5. Преобразует данные `tasks` в JSON и записывает их в ответ
6. Клиент получает JSON и может отобразить список задач

**Что получит клиент:**
```json
[
  {"id":1, "title":"Изучить Go", "done":true},
  {"id":2, "title":"Написать первый сервер", "done":false}
]
```

# **➌ Обработчик ~ <font color="#ff0000">GET /tasks/{id}</font> ~**

Теперь добавим возможность **получать конкретную задачу по её ID** — например, если пользователь хочет увидеть только задачу №2 из списка.

📄 В этом же файле (`tasks.go`) новый обработчик:
```go
func getTaskByID(w http.ResponseWriter, r *http.Request) {
    idStr := strings.TrimPrefix(r.URL.Path, "/tasks/")
    id, err := strconv.Atoi(idStr)
    if err != nil {
        http.Error(w, "Некорректный ID", http.StatusBadRequest)
        return
    }

    for _, t := range tasks {
        if t.ID == id {
            w.Header().Set("Content-Type", "application/json")
            json.NewEncoder(w).Encode(t)
            return
        }
    }

    http.Error(w, "Задача не найдена", http.StatusNotFound)
}
```
Этот код позволяет обращаться по адресу вроде `http://localhost:8080/tasks/2` и получать **только одну задачу** из всего списка.
#### <u>Что происходит пошагово</u>:
1. <u>Читаем путь из запроса</u>: `r.URL.Path`:
	Объект `r` хранит всю информацию о запросе.
	Поле `r.URL.Path` — это строка с путём, например: `"/tasks/2"`.
2. <u>Достаём из пути сам ID</u>:
	`idStr := strings.TrimPrefix(r.URL.Path, "/tasks/")`
	Мы убираем часть `"/tasks/"`, чтобы осталось только `"2"`.
	Теперь в переменной `idStr` хранится строка `"2"`.
3. <u>Превращаем строку в число</u>:
	`id, err := strconv.Atoi(idStr)`
	Функция `strconv.Atoi` переводит строку в число (`int`).
	Если пользователь ввёл что-то вроде `/tasks/abc`, перевод не удастся, и `err` будет не `nil`.
4. <u>Проверяем на ошибку</u>:
```go
if err != nil {
    http.Error(w, "Некорректный ID", http.StatusBadRequest)
    return
}
```
*Если ID не число — это ошибка клиента, поэтому возвращаем:*
	`400 Bad Request.`
 5. <u>Ищем задачу с таким ID</u>:
```go
for _, t := range tasks {
    if t.ID == id {
        ...
    }
}
```
Проходим по всему срезу `tasks` и сравниваем `t.ID` с тем, что пришло в запросе.
Если нашли совпадение — значит, задача существует.
 6. <u>Отправляем найденную задачу</u>:
```go
w.Header().Set("Content-Type", "application/json")
json.NewEncoder(w).Encode(t)
return
```
- Ставим заголовок `Content-Type: application/json`, чтобы клиент понял, что данные в формате JSON.
- `json.NewEncoder(w).Encode(t)` превращает найденную задачу `t` (структуру) в JSON и сразу отправляет клиенту.
- `return` — выходим из функции, чтобы не попасть в блок ошибки ниже.
 7. <u>Если задача не найдена</u>:
```go
http.Error(w, "Задача не найдена", http.StatusNotFound)
```
Если цикл закончился и совпадений не было, отправляем ошибку **404 Not Found** — “такой задачи нет”.

#### <u>Пример результата</u>
Запрос:
```
GET <http://localhost:8080/tasks/2>
```
Ответ сервера:
```json
{
  "id": 2,
  "title": "Написать первый сервер",
  "done": false
}
```
Если запрашиваем несуществующую задачу (`/tasks/10`):
```
Задача не найдена
```
(код ответа `404`)

#### Зачем это нужно
- Этот обработчик показывает, как сервер может **реагировать на динамические пути** — не только `/tasks`, но и `/tasks/2`, `/tasks/5`, и т.д.
- В будущем вместо ручного `TrimPrefix` мы будем использовать маршрутизатор (`mux`), который сам “разберёт” путь и достанет нужный параметр.

# **➍ Обработчик ~ <font color="#ff0000">POST /tasks</font> ~**

Теперь добавим возможность **добавлять новую задачу**.
Для этого клиент (например, Postman или браузер) будет отправлять запрос:
```
POST /tasks
```
и передавать в теле запроса JSON с данными, например:
```json
{"title": "Выучить REST API", "done": false}
```

📄 В том же файле обработчик:
```go
func createTask(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodPost {
        http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
        return
    }

    var newTask Task
    if err := json.NewDecoder(r.Body).Decode(&newTask); err != nil {
        http.Error(w, "Невалидный JSON", http.StatusBadRequest)
        return
    }

    newTask.ID = len(tasks) + 1
    tasks = append(tasks, newTask)

    w.Header().Set("Content-Type", "application/json")
    w.WriteHeader(http.StatusCreated)
    json.NewEncoder(w).Encode(newTask)
}
```
Этот обработчик принимает JSON из тела запроса, превращает его в структуру `Task`, добавляет новую задачу в список `tasks` и возвращает клиенту созданный объект.
#### <u>Что происходит пошагово</u>:
1. <u>Проверяем метод запроса</u>:
```go
if r.Method != http.MethodPost {
    http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
    return
}
```
Этот путь (`/tasks`) предназначен **только для создания** задач, поэтому мы разрешаем сюда обращаться **только методом POST**. Если кто-то попытается сделать `GET` или `PUT`, сервер вернёт ошибку `405 Method Not Allowed`.
2. <u>Объявляем структуру для новой задачи</u>:
```go
var newTask Task
```
Создаём переменную, куда будем “распаковывать” JSON из тела запроса.
Структура `Task` у нас уже описана в `models/task.go`.
 3. <u>Читаем и декодируем JSON из тела запроса</u>:
```go
if err := json.NewDecoder(r.Body).Decode(&newTask); err != nil {
    http.Error(w, "Невалидный JSON", http.StatusBadRequest)
    return
}
```
- `r.Body` — это **тело запроса**, то, что клиент отправил.
    Например, JSON `{"title":"Выучить REST API","done":false}`.
- `json.NewDecoder(r.Body)` — создаёт “декодер”, который умеет читать JSON.
- `.Decode(&newTask)` — разбирает этот JSON и записывает данные прямо в структуру `newTask`.
Если клиент прислал битый JSON или неправильные поля — возвращаем ошибку **400 Bad Request**.
 4. Присваиваем ID и добавляем задачу в список:
```go
newTask.ID = len(tasks) + 1
tasks = append(tasks, newTask)
```
- Мы просто создаём новый ID на 1 больше, чем длина списка.
    (В реальных приложениях ID генерирует база данных,
    но здесь мы делаем это вручную для простоты.)
- `append` добавляет новую задачу в конец среза `tasks`.
 5. Отправляем ответ клиенту:
```go
w.Header().Set("Content-Type", "application/json")
w.WriteHeader(http.StatusCreated)
json.NewEncoder(w).Encode(newTask)
```
- Указываем `Content-Type: application/json`, потому что в ответе снова JSON.
- `w.WriteHeader(http.StatusCreated)` — ставим статус **201 Created**, чтобы клиент понял: задача успешно создана.
- `json.NewEncoder(w).Encode(newTask)` — отправляем обратно созданную задачу в JSON-виде, чтобы клиент мог сразу её отобразить.
#### <u>Пример запроса и ответа</u>:

**Запрос (от клиента):**
```
POST <http://localhost:8080/tasks>
Content-Type: application/json

{"title": "Выучить REST API", "done": false}
```
**Ответ сервера:**
```json
{
  "id": 3,
  "title": "Выучить REST API",
  "done": false
}
```
#### Что важно запомнить:
- `r.Body` — это то, что **отправил клиент** (обычно JSON).
- `json.NewDecoder(...).Decode(&obj)` — читает JSON и записывает в структуру.
- `json.NewEncoder(...).Encode(obj)` — превращает структуру обратно в JSON и отправляет клиенту.
- `201 Created` — стандартный код для успешного создания ресурса.

# **➎ Обработчик: ~ <font color="#ff0000">PUT /tasks/{id}</font> ~**

Этот обработчик позволяет **изменить уже существующую задачу** — например, поменять название или отметить её как выполненную.

**Клиент отправляет запрос**:
```
PUT /tasks/2
```
и передаёт в теле JSON с новыми данными:
```json
{"title": "Обновлённая задача", "done": true}
```
добавляем функцию:
```go
func updateTask(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodPut {
        http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
        return
    }

    idStr := strings.TrimPrefix(r.URL.Path, "/tasks/")
    id, err := strconv.Atoi(idStr)
    if err != nil {
        http.Error(w, "Некорректный ID", http.StatusBadRequest)
        return
    }

    var updated Task
    if err := json.NewDecoder(r.Body).Decode(&updated); err != nil {
        http.Error(w, "Невалидный JSON", http.StatusBadRequest)
        return
    }

    for i, t := range tasks {
        if t.ID == id {
            tasks[i].Title = updated.Title
            tasks[i].Done = updated.Done

            w.Header().Set("Content-Type", "application/json")
            json.NewEncoder(w).Encode(tasks[i])
            return
        }
    }

    http.Error(w, "Задача не найдена", http.StatusNotFound)
}
```
### Этот код:
- Принимает запрос `PUT /tasks/{id}`.
- Считывает ID из пути.
- Берёт JSON с новыми данными из тела запроса.
- Находит нужную задачу в списке `tasks`.
- Обновляет поля и возвращает обновлённый объект.

#### <u>Что происходит пошагово</u>:

1. Проверяем метод запроса:
```go
if r.Method != http.MethodPut {
    http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
    return
}
```
Разрешаем сюда только `PUT`. Если клиент попытается вызвать `GET` или `POST`, вернём **405 Method Not Allowed**.
2. Достаём ID задачи из пути:
```go
idStr := strings.TrimPrefix(r.URL.Path, "/tasks/")
id, err := strconv.Atoi(idStr)
```
- Убираем из пути `/tasks/` и остаётся только `"2"`.
- Преобразуем строку в число, чтобы можно было искать по ID.
- Если не получилось — это ошибка клиента (`400 Bad Request`).
3. Читаем обновлённые данные из тела запроса:
```go
var updated Task
if err := json.NewDecoder(r.Body).Decode(&updated); err != nil {
    http.Error(w, "Невалидный JSON", http.StatusBadRequest)
    return
}
```
- Мы ждём JSON вроде `{"title": "...", "done": true}`.
- `Decode(&updated)` запишет эти данные в структуру `updated`.
- Если JSON битый — возвращаем **400**.
4. Ищем задачу и изменяем её:
```go
for i, t := range tasks {
    if t.ID == id {
        tasks[i].Title = updated.Title
        tasks[i].Done = updated.Done
        ...
    }
}
```
- Проходим по всем задачам.
- Когда ID совпал, обновляем поля.
- Мы не пересоздаём задачу, а просто **меняем нужную** внутри списка.
5. Отправляем обратно обновлённую задачу:
```go
w.Header().Set("Content-Type", "application/json")
json.NewEncoder(w).Encode(tasks[i])
```
- Устанавливаем заголовок `Content-Type`.
- Отправляем клиенту обновлённую задачу в JSON.
- Это удобно — клиент сразу видит новые данные.
6. Если задача не найдена:
```go
http.Error(w, "Задача не найдена", http.StatusNotFound)
```
Если цикл прошёл весь список и ID не совпал ни с одной задачей, отправляем `404 Not Found`.
#### <u>Пример запроса и ответа</u>

**Запрос:**
```
PUT <http://localhost:8080/tasks/2>
Content-Type: application/json

{"title": "Обновлено", "done": true}
```
**Ответ:**
```json
{
  "id": 2,
  "title": "Обновлено",
  "done": true
}
```
Если указать несуществующий ID (`/tasks/10`), сервер ответит:
```
Задача не найдена
```
(код `404 Not Found`)
#### <u>Почему не возвращаем код 204 No Content</u>?

Иногда для `PUT` используют статус `204`, если не нужно возвращать тело.
Мы же возвращаем **обновлённый объект**, поэтому лучше оставить **200 OK** с JSON-ответом — так клиенту проще сразу обновить интерфейс.
> В этом примере мы обновляем весь объект (подход PUT). Частичное обновление — это PATCH (будет похожим, только меняем не все поля).

# **➏ Обработчик: ~ <font color="#ff0000">DELETE /tasks/{id}</font> ~**

Теперь мы реализуем возможность **удалить задачу по её ID**.
Клиент отправляет запрос:
```
DELETE /tasks/2
```
Новый обработчик:
```go
func deleteTask(w http.ResponseWriter, r *http.Request) {
    if r.Method != http.MethodDelete {
        http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
        return
    }

    idStr := strings.TrimPrefix(r.URL.Path, "/tasks/")
    id, err := strconv.Atoi(idStr)
    if err != nil {
        http.Error(w, "Некорректный ID", http.StatusBadRequest)
        return
    }

    for i, t := range tasks {
        if t.ID == id {
            tasks = append(tasks[:i], tasks[i+1:]...)
            w.WriteHeader(http.StatusNoContent)
            return
        }
    }

    http.Error(w, "Задача не найдена", http.StatusNotFound)
}
```
### Этот код:
1. Проверяет, что запрос — с методом `DELETE`.
2. Извлекает ID задачи из URL.
3. Находит задачу в списке.
4. Удаляет её из среза `tasks`.
5. Возвращает **204 No Content**, если всё прошло успешно.
6. Если ID не найден — возвращает **404 Not Found**.

#### <u>Что происходит пошагово</u>:

1. Проверяем метод запроса:
```go
if r.Method != http.MethodDelete {
    http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
    return
}

```
Этот обработчик отвечает **только за удаление**, поэтому допускаем сюда **только DELETE**. Если придёт другой метод — вернём **405**.
2. Извлекаем ID из URL:
```go
idStr := strings.TrimPrefix(r.URL.Path, "/tasks/")
id, err := strconv.Atoi(idStr)
```
- Отрезаем `/tasks/` → остаётся `"2"`.
- Превращаем строку в число через `strconv.Atoi`.
- Если число некорректное (например, `/tasks/abc`) — возвращаем **400 Bad Request**.
3. Ищем задачу и удаляем её:
```go
for i, t := range tasks {
    if t.ID == id {
        tasks = append(tasks[:i], tasks[i+1:]...)
        ...
    }
}
```
- Проходим по списку задач.
- Когда нашли нужную — используем `append` для удаления элемента из среза:    
    берём всё **до** неё и всё **после**, объединяем в новый список.
- В Go это стандартный способ удалить элемент из массива/среза.
4. Отправляем ответ:
```go
w.WriteHeader(http.StatusNoContent)
return
```
- Код **204 No Content** означает:
    «Операция прошла успешно, но тело ответа не нужно».
- Мы **не пишем JSON**, не добавляем заголовков — просто сообщаем, что всё хорошо.
5. Если задача не найдена:
```go
http.Error(w, "Задача не найдена", http.StatusNotFound)
```
Если цикл прошёл весь список и не нашёл ID — возвращаем `404 Not Found`, чтобы клиент понял, что такой задачи нет.

#### <u>Пример запроса и ответа</u>:

**Запрос:**
```
DELETE <http://localhost:8080/tasks/2>
```
**Ответ:**
```
(пустое тело)
```
и статус:
```
204 No Content
```

#### <u>Почему нет тела в ответе</u>?

Иногда, когда операция прошла успешно, **ничего возвращать не нужно**.
Например, при удалении:
- задача удалена — всё отлично, просто подтверждаем это статусом;
- тело ответа не нужно, ведь данных для отображения нет.
Поэтому принято использовать **204**, а не `200 OK` с текстом вроде `"удалено"` — это считается “чистым” REST-подходом.

| Действие      | Метод  | Пример пути | Статус    |
| ------------- | ------ | ----------- | --------- |
| Получить все  | GET    | `/tasks`    | 200       |
| Получить одну | GET    | `/tasks/1`  | 200 / 404 |
| Создать       | POST   | `/tasks`    | 201       |
| Обновить      | PUT    | `/tasks/1`  | 200 / 404 |
| Удалить       | DELETE | `/tasks/1`  | 204 / 404 |
# **➐ Регистрация маршрутов и запуск сервера**

Теперь, когда у нас есть все обработчики (`GET`, `POST`, `PUT`, `DELETE`), нужно **связать их с путями (routes)**, чтобы сервер понимал, какую функцию вызывать при каждом запросе.

📄 Файл `main.go`:
```go
package main

import (
    "fmt"
    "net/http"
)

func main() {
    http.HandleFunc("/tasks", func(w http.ResponseWriter, r *http.Request) {
        switch r.Method {
        case http.MethodGet:
            getTasks(w, r)
        case http.MethodPost:
            createTask(w, r)
        default:
            http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
        }
    })

    http.HandleFunc("/tasks/", func(w http.ResponseWriter, r *http.Request) {
        switch r.Method {
        case http.MethodGet:
            getTaskByID(w, r)
        case http.MethodPut:
            updateTask(w, r)
        case http.MethodDelete:
            deleteTask(w, r)
        default:
            http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
        }
    })

    fmt.Println("Сервер запущен на <http://localhost:8080>")
    http.ListenAndServe(":8080", nil)
}

```
### Этот код:
- Создаёт HTTP-сервер.
- Регистрирует **два маршрута**:
    `/tasks` и `/tasks/` (с хвостом).
- Для каждого маршрута — разные обработчики и методы.
- Запускает сервер на `localhost:8080`.

#### <u>Что происходит пошагово</u>:
1. `http.HandleFunc("/tasks", func(...))`
	Регистрирует анонимную функцию (замыкание) как обработчик для пути `/tasks`.
	Этот путь обслуживает **все задачи сразу**, поэтому внутри мы проверяем метод:
```go
switch r.Method {
case http.MethodGet:
    getTasks(w, r)      // вернуть все задачи
case http.MethodPost:
    createTask(w, r)    // создать новую задачу
default:
    http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
}
```
- `GET /tasks` → список всех задач
- `POST /tasks` → создать новую задачу
- всё остальное → ошибка `405 Method Not Allowed`
2. `http.HandleFunc("/tasks/", func(...))`
	Этот маршрут с “хвостом” (`/tasks/`) нужен для работы **с конкретной задачей**: например, `/tasks/2`.
	В зависимости от метода — выполняются разные действия:
```go
switch r.Method {
case http.MethodGet:
    getTaskByID(w, r)
case http.MethodPut:
    updateTask(w, r)
case http.MethodDelete:
    deleteTask(w, r)
default:
    http.Error(w, "Метод не поддерживается", http.StatusMethodNotAllowed)
}

```
- `GET /tasks/2` → получить задачу
- `PUT /tasks/2` → обновить
- `DELETE /tasks/2` → удалить
3. Запускаем сервер:
```go
fmt.Println("Сервер запущен на <http://localhost:8080>")
http.ListenAndServe(":8080", nil)
```
- `fmt.Println` — просто сообщение в консоль, чтобы понимать, что сервер запущен.
- `http.ListenAndServe(":8080", nil)` —
    запускает сервер, который **слушает порт 8080**
    и передаёт все запросы зарегистрированным обработчикам.
