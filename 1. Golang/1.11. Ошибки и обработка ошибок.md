# Зачем нужны ошибки и какую проблему они решают

#### Жизненная картина №1: «Файл отчёта»

Ты запускаешь программу: *«прочитай файл `report.csv` и посчитай сумму»*.

<u>Проблемы в реальности</u>:
- файл могут переименовать;
- путь окажется неправильным;
- прав нет;
- файл пустой.

**<u>Без ошибок</u>**: программа «молча» **вернёт нули** или **упадёт**.

**<u>С ошибками</u>**: функция чтения **вернёт конкретную причину** (*файл не найден, нет прав, повреждён*), а вызывающий код решит: **попросить другой путь, создать файл, сообщить пользователю.**

**Мини-пример**:
```go
data, err := os.ReadFile("report.csv")
if err != nil {
    // сообщаем причину и выходим
    fmt.Println("не удалось прочитать отчёт:", err)
    return
}
fmt.Println("длина файла:", len(data))

```

**Пользователь получает понятную причину, а программа остаётся под контролем, не падает.**

#### Жизненная картина №2: «Ввод пользователя»

Пользователь вводит возраст. Он может ввести «двадцать пять», `-10`, пустую строку.

**Без ошибок**: ты работаешь с **мусорным** значением.

**С ошибками**: функция парсинга/валидации вернёт «*некорректный формат*» или «*возраст вне диапазона*».

**Мини-пример:**
```go
age, err := strconv.Atoi(input)
if err != nil {
    return fmt.Errorf("возраст должен быть числом: %w", err)
}
if age < 0 || age > 120 {
    return errors.New("возраст вне допустимого диапазона [0..120]")
}
```

**Зачем**: ты отделяешь _техническую_ причину (*парсинг не удался*) от **_бизнес-логики_** (*значение не проходит проверку*).

#### Жизненная картина №3: «Многошаговая операция»

Сначала читаем конфиг, потом инициализируем кэш, потом открываем базу. Любой шаг может дать сбой.

**Без ошибок**: непонятно, на каком шаге всё сломалось.

**С ошибками и контекстом**: у тебя цепочка «**config: не найден файл**», «**cache: недоступна директория**», «**db: отказано в доступе**» — <u>легко диагностировать</u>.

# Что такое ошибка в Go

В [[1.0. Go Basics|Go]] ошибки — это **значения** (*не исключения*). Любой [[1.2. Типы данных|тип]], реализующий [[1.9. Интерфейсы в Go|интерфейс]] `error`, — это ошибка:
```go
type error interface {
    Error() string
}
```

Это значит: ошибки можно **возвращать**, **сравнивать**, **оборачивать** и **передавать между слоями**.

# Как возвращать и проверять ошибки

```go
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("деление на ноль")
    }
    return a / b, nil // nil = ошибки нет
}

func main() {
    res, err := divide(10, 0)
    if err != nil {
        fmt.Println("ошибка:", err)
        return
    }
    fmt.Println("результат:", res)
}
```

**Разбор построчно:**
- `divide(...)(float64, error)` — функция обещает вернуть результат **и** ошибку.
- `if b == 0 { return 0, errors.New(...) }` — при проблеме возвращаем «нулевой» результат и **ненулевую** ошибку.
- `return ..., nil` — успех всегда сопровождается `err == nil`.
- В `main`: «ранний возврат» при ошибке упрощает контроль потока.

# Способы создания ошибок: когда и зачем

#### Через `errors.New` — фиксированное сообщение (сигнальная/«sentinel» ошибка)

Используй, когда причина **стабильна и повторяема**:
- валидация;
- отсутствие сущности;
- запрещённое действие.

```go
var ErrInvalidAge = errors.New("некорректный возраст") // пакетный sentinel

func ParseAge(input string) (int, error) {
    age, err := strconv.Atoi(input)
    if err != nil {
        return 0, fmt.Errorf("невозможно преобразовать в число: %w", err)
    }
    if age < 0 || age > 120 {
        return 0, ErrInvalidAge
    }
    return age, nil
}
```

**Разбор построчно:**
- `var ErrInvalidAge = ...` — создаём **один объект** ошибки для сравнения через `errors.Is`.
- Внутри `ParseAge`: если формат плохой — оборачиваем чужую ошибку парсинга (об этом ниже), если диапазон нарушен — возвращаем **наш** sentinel.
- Выше по стеку можно реагировать точечно:

```go
age, err := ParseAge("150")
if errors.Is(err, ErrInvalidAge) {
    fmt.Println("попросить повторный ввод") // корректная UX-реакция
}
```

**Когда применять**: валидация доменных ограничений, отсутствие сущности (`ErrNotFound`), запрет (`ErrForbidden`) и т.п.

# Форматированное сообщение ~ <font color="#ff0000">fmt.Errorf</font> ~

Используй, когда нужно **подставить контекст** прямо в текст ошибки (имя файла, значение, шаг):
```go
func LoadProfile(path string) ([]byte, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return nil, fmt.Errorf("load profile %q: %w", path, err)
    }
    if len(data) == 0 {
        return nil, fmt.Errorf("load profile %q: файл пустой", path)
    }
    return data, nil
}
```

**Разбор построчно:**
- `fmt.Errorf("...%q...", path)` — вкладываем конкретику в сообщение.
- `%w` — **оборачивание** исходной ошибки (важно: это не просто текст; см. следующий раздел).
- Для собственного условия (пустой файл) мы формируем человекочитаемую причину — без обёртки, потому что это **наша** конечная диагностика.

**Когда применять**: добавлять **контекст шага** и **значения** (путь, id, лимиты) на каждом слое, где ошибка проходит.

#### Собственный тип ошибки — структурированные данные и машинная обработка

Когда сообщения недостаточно и вызывающему коду нужны **поля** (код, ключ, можно ли ретраить), вводим тип:
```go
type DomainError struct {
    Code    string // например: "out_of_stock", "invalid_age"
    Details string // человекочитаемое пояснение
}

func (e *DomainError) Error() string {
    return fmt.Sprintf("%s: %s", e.Code, e.Details)
}

func Reserve(items int) error {
    stock := 3
    if items > stock {
        return &DomainError{Code: "out_of_stock", Details: "запрошено больше, чем есть"}
    }
    return nil
}
```

**Разбор построчно:**
- `DomainError` несёт **машиночитаемый код** и **описание**.
- `Error()` удовлетворяет `error`.
- Выше можно «доставать» тип через `errors.As`:

```go
if err := Reserve(10); err != nil {
    var de *DomainError
    if errors.As(err, &de) && de.Code == "out_of_stock" {
        fmt.Println("показать пользователю кнопку «Уведомить о наличии»")
    }
}
```

**Когда применять**: когда обработка зависит от **класса** ошибки (коды, retry-политика, маппинг на HTTP-статусы и т.д.).

# Оборачивание ошибок: <font color="#ff0000">зачем</font> и <font color="#ff0000">как</font>

#### Зачем
1. **Не терять первопричину.** Ты видишь «не найден файл», а не только «ошибка загрузки профиля».
2. **Добавлять контекст слоя.** «repo: чтение заказа 42: …», «service: расчёт скидки: …».
3. **Точно проверять типы выше.** `errors.Is` и `errors.As` проходят **по цепочке** обёрток.

#### Как правильно оборачивать
- Используй **только** `%w` в `fmt.Errorf`, если хочешь сохранить исходную ошибку в цепочке.
- Если просто напишешь `%v`, потеряешь связь и `errors.Is/As` перестанут работать.

```go
func readConfig(path string) ([]byte, error) {
    b, err := os.ReadFile(path)
    if err != nil {
        // ✅ правильно: сохраняем оригинал
        return nil, fmt.Errorf("read config %q: %w", path, err)
    }
    return b, nil
}

func initApp() error {
    _, err := readConfig("./missing.yaml")
    if err != nil {
        // добавляем ещё один слой контекста
        return fmt.Errorf("init app: %w", err)
    }
    return nil
}

func main() {
    if err := initApp(); err != nil {
        // Точечная реакция: проверим, что в цепочке есть «файл не найден»
        if errors.Is(err, os.ErrNotExist) {
            fmt.Println("подсказать пользователю путь к конфигу")
        }
        // Извлечём системный тип ошибки:
        var pe *os.PathError
        if errors.As(err, &pe) {
            fmt.Println("операция:", pe.Op, "путь:", pe.Path)
        }
        fmt.Println("лог:", err) // полный контекст
    }
}

```

**Разбор построчно:**
- В `readConfig`: `%w` хранит оригинальную `os.PathError`.
- В `initApp`: ещё один `%w` — строим **цепочку**.
- В `main`: `errors.Is(err, os.ErrNotExist)` идёт по цепочке и находит совпадение.
- `errors.As(err, &pe)` достаёт конкретный тип и его поля (операцию и путь).
- Последняя строка печатает **всю трассу контекста**, которую мы добавляли.

___
# Частые ошибки (антипаттерны) с оборачиванием

- «<u>Форматнули текст</u>» через `%v` → потеряли тип исходной ошибки.
- <u>Дублируем сообщение</u> исходной ошибки в тексте контекста: `"read file: file not found: file not found"`. Старайся добавлять **новую** информацию.
- <u>Оборачиваем «свои»</u> доменные ошибки там, <u>где нужна "плоская" реакция</u> по `errors.Is`. Иногда полезнее вернуть sentinel **как есть** без новой обёртки.

# Сравнение и извлечение ошибок

# ~ <font color="#ff0000">errors.Is</font> ~

Проверяет, «есть ли в цепочке» заданная ошибка (или она равна текущей):
```go
if errors.Is(err, ErrInvalidAge) { /* ... */ }
if errors.Is(err, os.ErrNotExist) { /* ... */ }

```

# ~ <font color="#ff0000">errors.As</font> ~

Пытается привести любую ошибку в цепочке к заданному типу и записать в целевую переменную.
```go
var de *DomainError
if errors.As(err, &de) {
    switch de.Code {
    case "out_of_stock": /* показать «Уведомить о наличии» */
    }
}
```

# ~ <font color="#ff0000">errors.Unwrap</font> ~

Возвращает «следующую» ошибку из обёртки. Полезно для тонких разборов, но в большинстве случаев хватает `Is/As`.

# Рабочие кейсы по слоям приложения

#### Валидация входа (sentinel + точечная реакция):
```go
var ErrEmailInvalid = errors.New("некорректный email")

func ValidateEmail(s string) error {
    if !strings.Contains(s, "@") {
        return ErrEmailInvalid
    }
    return nil
}

func Register(email string) error {
    if err := ValidateEmail(email); err != nil {
        // тут не добавляем контекст — хотим, чтобы выше легко ловили ErrEmailInvalid
        return err
    }
    // ...создание пользователя
    return nil
}

func handler() {
    if err := Register("foo.example.com"); err != nil {
        if errors.Is(err, ErrEmailInvalid) {
            fmt.Println("попросить пользователя исправить email")
            return
        }
        fmt.Println("другая ошибка:", err)
    }
}

```
**Идея**: для пользовательских ошибок UI-уровня удобен **sentinel** без обёрток.
