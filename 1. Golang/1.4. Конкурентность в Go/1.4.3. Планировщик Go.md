# Введение

Мы уже знаем, что [[1.4.0. Goroutines|горутины]] — это **лёгкие потоки**, которые позволяют выполнять несколько задач одновременно.

Но возникает вопрос:
> А кто решает, какая горутина выполняется первой, и как [[1.1.0. Go Basics|Go]] управляет тысячами горутин одновременно?

#### Это делает **планировщик Go** (<font color="#ff0000">Go Scheduler</font>).

---
# Что делает планировщик

Планировщик — это **встроенная система Go**, которая распределяет горутины между потоками ОС и следит, чтобы:
- все горутины получили **время на выполнение**;
- ни одна не «зависла» навсегда;
- ресурсы процессора использовались **максимально эффективно**.

#### Простая аналогия:
Представь, что у тебя есть:
- **куча задач** (горутины);
- **несколько работников** (операционные потоки);
- **менеджер**, который решает, кому какую задачу выдать — это и есть **планировщик**.

Менеджер следит:
- чтобы ни один работник не простаивал;
- чтобы задачи распределялись равномерно;
- чтобы если кто-то «заснул» (ждёт ввод/вывод), другие продолжали работать.

---
# Горутины ≠ потоки

Чтобы понять мощь планировщика, важно различать:

|Термин|Что это|Кто создаёт|
|---|---|---|
|**Поток (Thread)**|Единица выполнения на уровне ОС|Операционная система|
|**Горутина (Goroutine)**|Лёгкий поток Go|Go runtime|

Создание потока — **дорого**: занимает ~1 МБ памяти.

Создание горутины — **дёшево**: всего около **2–4 КБ**, и их можно запускать **десятки тысяч**.

---
#### Пример: 1000 горутин — без проблем:
```go
package main
import (
    "fmt"
    "time"
)
func worker(id int) {
    fmt.Println("Горутина", id, "стартовала")
    time.Sleep(100 * time.Millisecond)
}
func main() {
    for i := 1; i <= 1000; i++ {
        go worker(i)
    }
    time.Sleep(time.Second)
    fmt.Println("Готово!")
}
```

Программа спокойно запускает тысячу горутин — и всё работает.
Если бы это были потоки ОС, программа бы просто **упала по памяти**.

---
# Как <font color="#ff0000">Go</font> это делает: модель <font color="#ff0000">G</font> <font color="#ff0000">M</font> <font color="#ff0000">P</font>

Внутри планировщика есть три основных компонента:

| Компонент         | Что это                  | Роль                                 |
| ----------------- | ------------------------ | ------------------------------------ |
| **G** (Goroutine) | Собственно горутина      | Код, который нужно выполнить         |
| **M** (Machine)   | Поток ОС                 | Тот, кто реально выполняет код       |
| **P** (Processor) | “Процессор” планировщика | Распределяет горутины между потоками |

**Упрощённо:**
```
G (горутины) -> попадают в очередь P (планировщик) -> исполняются M (потоком ОС)
```

---
## Что делает каждая часть

- **G (Goroutine)** — просто задача, которая должна быть выполнена.
- **M (Machine)** — реальный поток операционной системы.
- **P (Processor)** — логический «контролёр», который хранит очередь горутин и решает, какие выполнять.

---
## 🔁 Как всё работает вместе
1. Когда ты вызываешь `go func()`, создаётся **G** — новая горутина.
2. Планировщик добавляет её в очередь **P**.
3. Один из активных **M** (потоков ОС) берет задачу из этой очереди.
4. После завершения — берёт следующую.

Если горутина “зависает” (например, ждёт канал или `time.Sleep`), её **вытесняют**, и процессор переключается на другую горутину.

#### Пример (упрощённо):
```
P1: G1 → G2 → G3
P2: G4 → G5
M1 выполняет P1
M2 выполняет P2
```

- Если `G2` ждёт что-то, M1 переключается на `G3`.
- Если P1 закончились задачи, M1 может “одолжить” горутины у P2.

Это даёт **равномерное распределение нагрузки** между ядрами.

---
# Параметр ~ <font color="#ff0000">GOMAXPROCS</font> ~

По умолчанию Go использует **столько “процессоров” (P)**, сколько есть **ядер CPU**.
Можно изменить это вручную:
```go
import "runtime"

func main() {
    runtime.GOMAXPROCS(1) // ограничить одним ядром
}
```
Обычно менять не нужно — Go сам подбирает оптимальное количество.

# Как планировщик распределяет горутины

Планировщик Go использует модель <font color="#ff0000">M</font>:<font color="#ff0000">N</font>, где **M** — реальные потоки ОС, а **N** — количество горутин.

То есть:
**много горутин** → распределяются на **меньшее количество потоков**.

# Когда происходит переключение (<font color="#ff0000">scheduling</font>)

Планировщик решает, когда приостановить одну горутину и запустить другую.

Это может произойти, если:
- горутина ждёт чтения из [[1.4.1. Каналы и конструкция Select|канала]] (`<-ch`);
- выполняется `time.Sleep`;
- вызывается системная операция ввода/вывода;
- истекает “тайм-квант” (время исполнения).

Go старается **минимизировать переключения**, поэтому планировщик работает очень эффективно.

#### Пример: “смешивание” вывода:
```go
package main
import "fmt"
func main() {
    for i := 0; i < 3; i++ {
        go fmt.Println("A")
        go fmt.Println("B")
    }
    fmt.Scanln()
}
```

Вывод может быть:
```
A
B
A
B
B
A
```
или в другом порядке.

Почему? Потому <u>что планировщик решает сам, в какой последовательности исполнять горутины.</u>

---
# Планировщик и блокировки

Если одна горутина заблокировала канал или ожидает ресурс, планировщик просто **снимает её с выполнения** и передаёт управление другой.

Это значит, что:
- одна “застрявшая” горутина не тормозит всю программу;
- остальные продолжают работать независимо.

# Важная особенность: кооперативная многозадачность

Go не прерывает горутины “насильно”, как это делает ОС с потоками.

Горутина **сама уступает** место другим при определённых точках:
- обращении к каналам;
- вызове системных функций;
- при ожидании (`Sleep`, `I/O`, `select`).

Это делает выполнение предсказуемым и безопасным — без резких прерываний.

---
# Почему Go-планировщик такой эффективный

1. Он **не зависит** от ОС — Go сам управляет многозадачностью.
2. Переключение горутин дешевле, чем переключение потоков.
3. Он оптимизирован под **массовую параллельность** — тысячи задач без проблем.
4. Реализует “work stealing”:
    если один поток простаивает, он забирает задачи из очередей других.

# <font color="#ff0000">Главное</font>, что нужно запомнить

|Понятие|Что это|Для чего нужно|
|---|---|---|
|**Горутина (G)**|Лёгкий поток Go|Выполняет код|
|**Поток (M)**|Поток ОС|Реально исполняет горутины|
|**P (Processor)**|Планировщик Go|Хранит очередь горутин|
|**Scheduler**|Менеджер горутин|Решает, какая выполняется сейчас|
|**GOMAXPROCS**|Кол-во доступных P|Задает, сколько ядер используется|
