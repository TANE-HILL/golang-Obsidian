# Зачем нужен пакет ~ <font color="#ff0000">sync</font> ~

Когда программа работает с несколькими [[1.4.0. Goroutines|горутинами]], они часто **делят общие данные** — например, общий счётчик, [[1.1.6. Массивы и слайсы, работа под капотом|слайс]] или [[1.1.7. Map в Go - устройство и особенности|карту]].

Без синхронизации всё может пойти не так:
- данные обновляются **одновременно** из разных горутин;
- часть изменений теряется;
- программа ведёт себя **непредсказуемо**.

Такое поведение называется **гонкой данных (data race)**.

Чтобы избежать этого, [[1.1.0. Go Basics|Go]] предлагает **пакет `sync`**, который содержит набор инструментов для безопасной работы с горутинами:

| Инструмент                             | Что делает                                            |
| -------------------------------------- | ----------------------------------------------------- |
| <font color="#ff0000">WaitGroup</font> | Ждёт завершения всех горутин                          |
| <font color="#ff0000">Mutex</font>     | Защищает общий ресурс от одновременного доступа       |
| <font color="#ff0000">RWMutex</font>   | Разделяет доступ — одни читают, другие пишут          |
| <font color="#ff0000">Atomic</font>    | Выполняет простые операции без блокировок             |
| <font color="#ff0000">Pool</font>      | Позволяет переиспользовать объекты и экономить память |

Разберём каждый по порядку.

---
# <font color="#ff0000">WaitGroup</font> — ожидание завершения горутин

#### Проблема без `WaitGroup`
Когда `main()` завершается, **все горутины мгновенно останавливаются**, даже если они не успели завершить работу.

Пример:
```go
package main
import "fmt"
func main() {
    for i := 1; i <= 3; i++ {
        go fmt.Println("Горутина", i)
    }
    fmt.Println("The End")
}
```

Иногда программа вообще не успевает ничего вывести, потому что `main()` завершилась раньше.

#### Решение: <font color="#ff0000">sync.WaitGroup</font>

`WaitGroup` — это счётчик активных горутин.

Ты добавляешь задачи (`Add()`), запускаешь горутины, и в конце вызываешь `Wait()` — программа ждёт, пока все не завершатся.
#### Пример:
```go
package main
import (
    "fmt"
    "sync"
)
func main() {
    var wg sync.WaitGroup // создаём группу ожидания
    wg.Add(1) // добавляем одну задачу
    go func() {
        defer wg.Done() // уменьшаем счётчик, когда завершим работу
        fmt.Println("Горутина работает")
    }()
    wg.Wait() // ждём, пока все горутины закончат
    fmt.Println("The End")
}
```

Разбираем построчно:
1. `var wg sync.WaitGroup` — создаём объект ожидания.
2. `wg.Add(1)` — добавляем 1 задачу в очередь ожидания.
3. В горутине: `defer wg.Done()` — когда она закончится, уменьшится счётчик.
4. `wg.Wait()` — блокирует `main`, пока счётчик не станет 0.

Результат:
```
Горутина работает
The End
```

#### Зачем нужен `WaitGroup` на практике:
- ждать завершения фоновых задач (запросов, обработчиков, загрузок);
- координировать несколько независимых процессов;
- гарантировать, что `main` не завершится слишком рано.

`WaitGroup` используется почти во всех программах, где есть несколько горутин.

# Гонки данных ~ <font color="#ff0000">data race</font> ~

Гонка данных — это ситуация, когда **две или больше [[1.4.0. Goroutines|горутин]] одновременно обращаются к одной [[1.1.1. Переменные|переменной]]**, и хотя бы одна из них её изменяет.

Результат — хаотичный и непредсказуемый.

#### Пример гонки:
```go
package main
import "fmt"

var counter = 0

func main() {
    for i := 0; i < 2; i++ {
        go func() {
            for j := 0; j < 1000; j++ {
                counter++ // небезопасно!
            }
        }()
    }
    fmt.Scanln()
    fmt.Println("Результат:", counter)
}
```

Иногда результат будет `2000`, иногда — `1573`, а иногда меньше.
#### Потому что `i++` не атомарна!

На самом деле `counter++` — это не одно действие, а три:
1. Прочитать значение `counter`
2. Увеличить на 1
3. Записать обратно

Если две горутины выполняют это одновременно, <u>шаги перемешиваются, и часть инкрементов теряется</u>.

---
# Как найти ~ <font color="#ff0000">data race</font> ~

<u>Go может показать её автоматически</u>:
```
go run -race main.go
```

Выведет предупреждение:
```
WARNING: DATA RACE
Read at 0x... by goroutine 7:
  main.main.func1()
```

Это означает, что два потока читают и записывают одну переменную одновременно.

Чтобы исправить — нужно **синхронизировать доступ**: через `sync.Mutex` или `atomic`.

---
# Защита общих данных ~ <font color="#ff0000">sync.Mutex</font> ~

<font color="#ff0000">Mutex</font> (mutual exclusion — «взаимное исключение») гарантирует, что **только одна горутина** имеет доступ к данным в конкретный момент времени.

#### Пример без мьютекса (ошибка)
```go
package main
import "fmt"

var counter = 0

func main() {
    for i := 0; i < 5; i++ {
        go func() {
            for j := 0; j < 1000; j++ {
                counter++
            }
        }()
    }
    fmt.Scanln()
    fmt.Println("Результат:", counter)
}
```

Иногда выводится 5000, иногда 4321. Это гонка данных.

---
#### Пример с `sync.Mutex`:
```go
package main
import (
    "fmt"
    "sync"
)

func main() {
    var mu sync.Mutex
    var counter int

    for i := 0; i < 5; i++ {
        go func() {
            for j := 0; j < 1000; j++ {
                mu.Lock()   // закрываем доступ
                counter++
                mu.Unlock() // открываем доступ
            }
        }()
    }

    fmt.Scanln()
    fmt.Println("Результат:", counter)
}
```

Разбор:
- `Lock()` — "закрывает дверь": другие горутины ждут.
- `Unlock()` — "открывает дверь" после завершения.
- `counter` теперь изменяется последовательно.

Результат:
```
Результат: 5000
```

<u>Мьютекс нужен, когда несколько горутин читают и пишут общие данные</u>.

---
# Пример совместного использования с <font color="#ff0000">WaitGroup</font>

```go
var (
    counter int
    mu sync.Mutex
    wg sync.WaitGroup
)

for i := 0; i < 3; i++ {
    wg.Add(1)
    go func() {
        defer wg.Done()
        for j := 0; j < 1000; j++ {
            mu.Lock()
            counter++
            mu.Unlock()
        }
    }()
}

wg.Wait()
fmt.Println("Результат:", counter)
```

Теперь программа и ждёт горутины, и защищает данные — безопасно и корректно.

# Разделение доступа ~ <font color="#ff0000">sync.RWMutex</font> ~

Если данные часто читаются, но редко изменяются — использовать обычный `Mutex` неэффективно: он блокирует даже чтение.

#### Решение:

`sync.RWMutex` позволяет разделить потоки:
- **читатели** (`RLock` / `RUnlock`) могут работать параллельно;
- **писатель** (`Lock` / `Unlock`) блокирует всех.

#### Пример:
```go
package main
import (
    "fmt"
    "sync"
    "time"
)

func main() {
    var mu sync.RWMutex
    var data int

    // писатель
    go func() {
        for i := 1; i <= 3; i++ {
            mu.Lock()
            data = i
            fmt.Println("Писатель изменил:", data)
            mu.Unlock()
            time.Sleep(200 * time.Millisecond)
        }
    }()

    // читатели
    for r := 1; r <= 2; r++ {
        go func(id int) {
            for {
                mu.RLock()
                fmt.Printf("Читатель %d прочитал: %d\n", id, data)
                mu.RUnlock()
                time.Sleep(100 * time.Millisecond)
            }
        }(r)
    }

    time.Sleep(time.Second)
}

```

**Что происходит:**
- Несколько читателей читают одновременно.
- Писатель ждёт, пока они закончат.
- После записи снова разрешается чтение.

#### Где использовать:
- при работе с кэшем (данные читаются чаще, чем пишутся);
- в простых базах данных или конфигурационных хранилищах;
- при мониторинге или логировании.

# Атомарные операции ~ <font color="#ff0000">sync</font>/<font color="#ff0000">atomic</font> ~

Атомарная операция выполняется **целиком**, без возможности прерывания.

Она гарантирует, что значение будет изменено **в одном шаге**.

#### Пример:
```go
package main
import (
    "fmt"
    "sync"
    "sync/atomic"
)

func main() {
    var counter int64
    var wg sync.WaitGroup

    for i := 0; i < 3; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            for j := 0; j < 1000; j++ {
                atomic.AddInt64(&counter, 1)
            }
        }()
    }

    wg.Wait()
    fmt.Println("Итог:", counter)
}
```

**Пояснение:**
- `AddInt64` выполняет операцию сложения неделимо.
- Доступ к `counter` синхронизирован без `Mutex`.
- Быстро и безопасно.

---

## Другие функции:

| Функция                                                        | Описание                              |
| -------------------------------------------------------------- | ------------------------------------- |
| <font color="#ff0000">LoadInt64(&x)</font>                     | Безопасно читает значение             |
| <font color="#ff0000">StoreInt64(&x, val)</font>               | Безопасно записывает значение         |
| <font color="#ff0000">AddInt64(&x, n)</font>                   | Увеличивает значение                  |
| <font color="#ff0000">CompareAndSwapInt64(&x, old, new)</font> | Меняет значение, если оно равно `old` |

---
#### Когда использовать <font color="#ff0000">atomic</font>:
- для простых счётчиков, индикаторов и флагов;
- когда нужен **максимум производительности**;
- если нет сложных структур, требующих блокировки.

Атомарные операции — это «*микро-мьютексы*» на уровне процессора.

# Переиспользование объектов ~ <font color="#ff0000">sync.Pool</font> ~

Если программа часто создаёт временные объекты (например, буферы или структуры), сборщик мусора тратит много времени на их очистку.

#### Решение:
<font color="#ff0000">sync.Pool</font> хранит неиспользуемые объекты и **переиспользует их**, уменьшая нагрузку на память и ускоряя выполнение.

#### Пример:
```go
package main
import (
    "fmt"
    "sync"
)

func main() {
    pool := sync.Pool{
        New: func() any {
            fmt.Println("Создаю новый объект")
            return make([]byte, 4)
        },
    }

    buf1 := pool.Get().([]byte)
    fmt.Println("Получен объект:", buf1)

    pool.Put(buf1)
    fmt.Println("Возвращён обратно")

    buf2 := pool.Get().([]byte)
    fmt.Println("Повторно используем:", buf2)
}
```

**Как это работает:**
- При первом `Get()` создаётся объект (`New()`).
- После `Put()` объект сохраняется.
- При следующем `Get()` возвращается тот же экземпляр.
- После `GC` пул очищается автоматически.

#### Где применять
- при работе с временными буферами (`[]byte`, `bytes.Buffer`);
- для повторного использования структур (например, `User`, `Request`);
- в веб-серверах и обработчиках, где важно снизить количество выделений памяти.

# Управление временем и отменой ~ <font color="#ff0000">context</font> ~

Когда программа работает с несколькими горутинами, важно уметь **останавливать** их по требованию — например, если операция заняла слишком много времени или пользователь закрыл приложение.

Для этого в Go есть мощный инструмент — **`context`**.

#### 🔹 Что такое `context`

`context.Context` — это объект, который:
- хранит **сигнал отмены** (cancel);
- может иметь **таймаут или дедлайн**;
- передаётся в горутины, чтобы те знали, **когда пора завершиться**.

#### Пример: ручная отмена с `context.WithCancel`:
```go
package main
import (
	"context"
	"fmt"
	"time"
)
func worker(ctx context.Context, id int) {
	for {
		select {
		case <-ctx.Done():
			fmt.Println("Горутина", id, "завершена")
			return
		default:
			fmt.Println("Горутина", id, "работает")
			time.Sleep(200 * time.Millisecond)
		}
	}
}
func main() {
	ctx, cancel := context.WithCancel(context.Background())
	go worker(ctx, 1)
	go worker(ctx, 2)
	time.Sleep(time.Second)
	cancel() // 🟥 останавливаем все горутины
	time.Sleep(500 * time.Millisecond)
	fmt.Println("Главная программа завершена")
}
```
Вывод:
```Run
Горутина 1 работает
Горутина 2 работает
Горутина 2 работает
Горутина 1 работает
Горутина 2 работает
Горутина 1 работает
Горутина 1 работает
Горутина 2 работает
Горутина 2 работает
Горутина 1 работает
Горутина 1 завершена
Горутина 2 завершена
Главная программа завершена
```

**Пояснение:**
- `context.WithCancel` возвращает <u>контекст</u> и <u>функцию отмены</u>.
- Все горутины, использующие этот контекст, завершаются при вызове `cancel()`.
- Отмена распространяется автоматически.
