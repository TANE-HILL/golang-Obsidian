# Что такое ООП

ООП (объектно-ориентированное программирование) — это способ **организовать код вокруг объектов**, которые **хранят данные** и **умеют что-то делать**.

Главная идея — программа состоит не просто из [[1.1.5. Функции и передача данных|функций]], а из **взаимодействующих сущностей**:
пользователь, заказ, товар, сервер, сообщение — каждая из них имеет **состояние** (данные) и **поведение**(действия).

---
# 4 базовых принципа ООП

#### 1. Инкапсуляция — объединение данных и поведения

Инкапсуляция означает, что объект **сам управляет своими данными** и предоставляет только безопасные способы работы с ними. В [[1.1.0. Go Basics|Go]] это делается через **[[1.2.0. Структуры и методы|структуры и методы]]**, а доступ к полям можно **скрывать**, если имя начинается с маленькой буквы.

```go
type User struct {
    name string // приватное поле
}

func (u *User) SetName(n string) {
    u.name = n
}

func (u User) GetName() string {
    return u.name
}
```

**Пояснение:**
- Поле `name` не видно снаружи (с маленькой буквы).
- Работа с ним возможна только через методы `SetName` и `GetName`.
- Так объект сам управляет своим состоянием.

**Пример:**
```go
func main() {
    var u User
    u.SetName("Аня")
    fmt.Println(u.GetName())
}
```
**Вывод:**
```Run
Аня
```

#### 2. Композиция — сборка поведения из частей

[[1.1.0. Go Basics|Go]] не использует наследование, зато поддерживает **композицию** — когда один тип **встраивает** другой и получает его возможности.
```go
type Address struct {
    City string
}

type User struct {
    Name string
    Address // встроенное поле
}
```
Теперь `User` может напрямую обращаться к полям `Address`:
```go
u := User{Name: "Сергей", Address: Address{City: "Москва"}}
fmt.Println(u.City)
```
**Вывод:**
```Run
Москва
```

**Пояснение:**
- Встраивание позволяет собирать сложные типы из простых.
- Это удобнее и гибче, чем наследование: можно выбирать, **что именно** включать в объект.

#### 3. Полиморфизм — разные типы, одно поведение

Полиморфизм — это когда **разные [[1.1.2. Типы данных|типы]] умеют делать одно и то же**.

В Go это реализуется через **[[1.2.1. Интерфейсы в Go|интерфейсы]]**. Интерфейс описывает, **что умеет объект**, а не то, **как** он это делает:
```go
type Notifier interface {
    Notify()
}
```
Теперь любой тип, у которого есть метод `Notify()`, автоматически соответствует этому интерфейсу.

```go
type Email struct{}
func (Email) Notify() { fmt.Println("Отправка email...") }

type SMS struct{}
func (SMS) Notify() { fmt.Println("Отправка SMS...") }

func Send(n Notifier) {
    n.Notify()
}
```

**Пример использования:**
```go
func main() {
    Send(Email{})
    Send(SMS{})
}
```
**Вывод:**
```Run
Отправка email...
Отправка SMS...
```

**Пояснение:**
- Типы `Email` и `SMS` разные, но оба реализуют интерфейс `Notifier`.
- Функция `Send` не знает, что именно ей передали — она просто вызывает `Notify()`.
- Так Go реализует полиморфизм **без наследования и лишних связей**.

#### 4. Абстракция — работа через общие интерфейсы

Абстракция — это когда код работает **не с конкретными [[1.1.2. Типы данных|типами]]**, а с их **поведением**. То есть [[1.1.5. Функции и передача данных|функция]] знает, _что нужно сделать_, но не знает, _как именно_ это выполняется.

---
#### Пример - разные способы оплаты:
```go
package main

import "fmt"

// Интерфейс описывает общее поведение
type Payment interface {
    Pay(amount int)
}

// Разные реализации
type Card struct{}
func (Card) Pay(amount int) {
    fmt.Println("Оплата картой на сумму", amount)
}

type Cash struct{}
func (Cash) Pay(amount int) {
    fmt.Println("Оплата наличными на сумму", amount)
}

// Функция работает не с конкретным типом, а с поведением Payment
func Checkout(p Payment) {
    p.Pay(500)
}

func main() {
    Checkout(Card{}) // используем карту
    Checkout(Cash{}) // используем наличные
}
```
**Вывод:**
```Run
Оплата картой на сумму 500
Оплата наличными на сумму 500
```

#### Объяснение:

- Интерфейс `Payment` говорит:
    > “Любой, кто умеет Pay(amount int), может быть способом оплаты.”
- `Card` и `Cash` реализуют этот метод по-разному.
- Функция `Checkout` не знает, чем оплачивают — **она просто вызывает `Pay()`**.
---
**Главная мысль:**
> Абстракция — это умение писать код, который работает не с деталями, а с поведением. Благодаря интерфейсам можно менять реализацию, не трогая остальной код.

# Интерфейсы и композиция вместе

Интерфейсы часто комбинируют с встраиванием, чтобы создавать **составное поведение**.

```go
type Reader interface {
    Read() string
}

type Writer interface {
    Write(data string)
}

// Комбинированный интерфейс
type ReaderWriter interface {
    Reader
    Writer
}
```
Теперь любой тип, у которого есть оба метода (`Read` и `Write`), соответствует `ReaderWriter`.

**Пример:**
```go
type File struct{}

func (File) Read() string        { return "данные из файла" }
func (File) Write(data string)   { fmt.Println("Запись:", data) }

func main() {
    var rw ReaderWriter = File{}
    fmt.Println(rw.Read())
    rw.Write("новые данные")
}
```
**Вывод:**
```Run
данные из файла
Запись: новые данные
```

**Пояснение:**
- Интерфейсы можно объединять — это как «набор возможностей».
- Код остаётся простым, без иерархий и сложных зависимостей.

# Принципы ООП в Go:

| **<u>Принцип</u>** | **<u>Как реализован в Go</u>**                            |
| ------------------ | --------------------------------------------------------- |
| **Инкапсуляция**   | Пакеты, неэкспортируемые поля (с маленькой буквы), методы |
| **Композиция**     | Встраивание структур                                      |
| **Полиморфизм**    | Интерфейсы и структурная типизация                        |
| **Абстракция**     | Работа с поведением вместо конкретных типов               |
